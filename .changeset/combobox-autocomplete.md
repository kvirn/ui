Combobox and Autocomplete (Plan 0022, ADR-0037 items 4 and 5, ADR-0050): an editable ARIA 1.2 combobox that filters a list as the user types.

- `@kvirn-ui/react`: `Combobox.Root`, `.Control`, `.Input`, `.Toggle`, `.Clear`, `.ValueList`, `.Value` and the Listbox's popup parts re-exported as `Combobox.Popup`, `.List`, `.Option`, `.Group`, `.GroupLabel` and `.Empty` (also `ComboboxRoot`, `ComboboxInput` and so on), and the hook `useCombobox`. The value is the chosen option's key (`itemToKey`): a string or `null`, or with `multiple` an array of keys, controlled with `value` and `onValueChange(value, { reason })`, or uncontrolled with `defaultValue`. The text is `inputValue`, `defaultInputValue` and `onInputValueChange`. DOM focus stays on a native `<input role="combobox" aria-autocomplete="list">` named by the Field's label, and the active option is `aria-activedescendant`. No option is active until an arrow key, so Enter never chooses something the user didn't move to, and with none active Enter is the browser's own (a form submits). Typed text is never cleared silently: text that matches no option stays and the value is `null`. The default filter matches anywhere in the label in the provider's locale (å, ä and ö are not a and o in Swedish), `filter` replaces it, and `filter={false}` with `isLoading` serves results that your server has filtered. With `multiple`, the popup stays open, and the chosen values are a list of remove buttons before the input; removing one moves focus to the next, else the previous, else the input. With `name`, hidden inputs put the keys in a plain `<form>`. The result count, "no results" and "loading" are announced politely once typing stops (`announcementDebounceMilliseconds`, default 500), through the Announcer: wrap the app in `KvirnProvider`.
- `@kvirn-ui/react`: `Autocomplete.Root`, `.Control`, `.Input`, `.Toggle`, `.Clear` and the same popup parts (also `AutocompleteRoot` and so on), and the hook `useAutocomplete`. The value is the text, which may match nothing: `value`, `defaultValue` and `onValueChange(text, { reason })`, and `name` goes on the input. Picking a suggestion fills the input and closes the popup, and suggestions never block other text. It is the same input, popup and keys as the Combobox.
- `@kvirn-ui/react`: `Combobox.Toggle` and `Combobox.Clear` are not tab stops (`tabindex="-1"`): ArrowDown, Alt+ArrowDown and selecting and deleting the text do the same from the keyboard. The popup opens for typing, ArrowDown, ArrowUp, Alt+ArrowDown and the Toggle, and not for a click on the input. With several choices `Combobox.Clear` empties the typed text only; each chosen value has its own remove button. Put the input in a `Combobox.Control` with a Toggle and a Clear, so it doesn't look like a plain text field.
- `@kvirn-ui/react`: types `UseComboboxOptions`, `UseComboboxSingleOptions`, `UseComboboxMultipleOptions`, `UseComboboxCommonOptions`, `UseComboboxResult`, `UseAutocompleteOptions`, `UseAutocompleteResult`, `ComboboxVariant`, `ComboboxSelectedValue`, `ComboboxOpenChangeReason`, `ComboboxOpenChangeDetails`, `ComboboxValueChangeReason`, `ComboboxValueChangeDetails`, `ComboboxInputChangeDetails`, the `Combobox*PartProps` and `*Props` types of every part.
- `@kvirn-ui/react`: `usePopup` places the popup again when its anchor moves (checked once per frame while open), so a popup never ends up covering the field after chosen values appear or wrap above it.
- `@kvirn-ui/theme`: the default styles for `kv-combobox-input` and `kv-autocomplete-input` (they look like `kv-input`), `kv-combobox-control` and `kv-autocomplete-control` (the box around the input and its buttons), `kv-combobox-toggle`, `kv-combobox-clear` (and the `kv-autocomplete-*` ones), `kv-combobox-value-list`, `kv-combobox-value`, `kv-combobox-value-label` and `kv-combobox-value-remove`. The popup and options reuse the `kv-listbox-*` styles, and an open popup with no option and no group draws nothing. The chevron and the crosses are drawn with borders, so they stay visible in forced colours. No new tokens.
