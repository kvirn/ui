`TableOfContents`: the headings of a long page as a named `<nav>` of plain `#id` links, with the heading the reader is in marked `aria-current="location"` (Plan 0049). You give it the page's `items` (`{ id, label, level }`, in document order) and it draws the nested list. The links are native hash links, so the list works before any script has run and in a server-rendered page, the browser scrolls with the page's own `scroll-margin-top`, and nothing moves focus or announces a change. It is never sticky and never smooth-scrolls: where it sits is the page's layout.

- React: the namespace `TableOfContents` (`Root`, `List`, `Item`, `Link`) with the flat exports `TableOfContentsRoot`, `TableOfContentsList`, `TableOfContentsItem` and `TableOfContentsLink`, the hook `useTableOfContents({ items, offset, labelledBy, messages })` (`rootProps`, `listProps`, `itemProps`, `tree`, `activeId`, `getLinkProps(item)`), and the types `TableOfContentsEntry`, `TableOfContentsNode`, `TableOfContentsState`, `TableOfContentsChildrenState`, `TableOfContentsElementProps`, `TableOfContentsRootProps`, `TableOfContentsListProps`, `TableOfContentsItemProps`, `TableOfContentsLinkProps`, `TableOfContentsRootPartProps`, `TableOfContentsListPartProps`, `TableOfContentsItemPartProps`, `TableOfContentsLinkPartProps`, `UseTableOfContentsOptions` and `UseTableOfContentsResult`. A function child, `({ tree, activeId }) => …`, draws your own list. Empty `items` render nothing, so there is no empty landmark. `offset` is the line a heading has to reach in px, and it must equal the headings' `scroll-margin-top`. The current heading is found in the browser with an `IntersectionObserver` and one passive `scroll` listener; on the server, during hydration and without an `IntersectionObserver` nothing is current. Two development warnings: `table-of-contents-missing-heading:<id>` and `table-of-contents-<part>-outside-root`.
- Core: the pure maths `getTableOfContentsTree(items)` (nests by level, a skipped level nests one step) and `getActiveHeading({ headings, offset, isAtEnd })` (the last heading above the line, with 1px of tolerance), and the types `TableOfContentsEntry`, `TableOfContentsNode`, `HeadingPosition` and `ActiveHeadingInput`.
- i18n: a new namespace `tableOfContents` with the key `label` ("On this page", "På den här sidan", "Tällä sivulla", "På denne siden", "På denne sida"; `se` is an English placeholder that needs a native review). **A full custom catalog must add the namespace**, because a `KvirnMessages` object without it no longer type-checks. A provider's partial `messages` and the built-in `en` fallback are unaffected.
- Theme: `kv-table-of-contents`, `kv-table-of-contents-list` and `kv-table-of-contents-item`, styled with the navigation item rules and no new token: the heading being read is a solid `primary` fill at weight 600, and the headings above it are the quiet trail (found with `:has()`). Levels indent 16px, forced colours get a straight `LinkText` bar, and `kv-table-of-contents` is a prose boundary.
