## Theme and docs

**Docs site goal ([Plan 0053](plans/0053-docs-as-municipality-site.md)).** `apps/docs` is a docs site first, and it is also a reference municipality website: the page types, layouts, blocks and patterns a Nordic municipality needs, built from KvirnUI as an adopter would. The order is fixed: a missing component, block or pattern is built in `@kvirn-ui/*` and reviewed in Storybook first, following this roadmap, and only then used in `apps/docs`, with its end-user documentation page.

**Components and patterns on no list**

| Gap                                                  | Why it matters for a public-sector site                                                                                                                                                             |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Audio and video (captions, transcript, no autoplay)  | WCAG 1.2.x; municipalities publish meeting recordings. Third-party embeds are banned (rule 7), so it is a native `<video>` pattern or nothing                                                       |
| Callout or inset text ("Viktigt", quote, pull quote) | A common content type that is not an Alert: it is not a status and is not announced                                                                                                                 |
| Ordered steps ("Så här går det till")                | Process explanations on every e-service start page (P4). Native `<ol>` styled as numbered steps is not specified                                                                                    |
| Charts and statistics                                | Open data and budget pages. Needs a table alternative and no colour-only series (1.4.1). Out of scope until asked, so record the decision                                                           |
| Print stylesheet                                     | Decisions, forms and receipts are printed. No print rule found in `DESIGN.md` or `theme.css` guidance                                                                                               |
| FocusScope, Portal                                   | Dialog and AlertDialog are built (Plan 0067) on the native top layer, so the timeout warning (P9) is unblocked. FocusScope (return focus to the action that opened a modal) and Portal stay planned |

**Checked and not gaps:** external-link, download and `target` handling are in `Link` (`link.a11y.md`); dates and numbers are in `useFormat` (Plan 0046); breadcrumb, pagination, summary list, error summary, table of contents and the layout components exist and have stories.

**Suggested order:** Dialog, Switch, Menu and Toast are done (Plans 0067, 0069, 0070, 0071). Next: Slider (planned, not started), then the empty, loading and busy pattern, then Tag and filter, then Image and Figure with a callout and ordered-steps rule in `Prose`. Audio, video, charts and print are decisions to take before they become plans. FocusScope and Portal stay planned (extract `dialog/focus-return.ts` when a second component needs it).
