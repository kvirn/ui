# ADR-0053: Kbd is the native `<kbd>` with a `kv-kbd` class, one key per element

- **Status:** Proposed
- **Date:** 2026-10-03
- **Deciders:** Magnus Vike (asked for a Kbd component), proposed with Plan 0024
- **Tags:** api, a11y

## Context

The theme styled `kbd` only inside `kv-prose` and `kv-card`, so a key outside them had no look, and examples wrote raw `<kbd>` tags. Keyboard help is common in public-sector guidance ("Du kan flytta mellan fälten med Tab").

## Decision drivers

- Native semantics first (AGENTS.md hard rule 2): `<kbd>` is the element for keyboard input.
- The component must not add strings: key names are printed on keyboards and are not translated.
- Same look in prose and outside it, with no new tokens.

## Decision

1. **`Kbd` renders `<kbd class="kv-kbd">`**, with `useKbd()` (`element`, `rootProps`). No role, ARIA, text or state. `render` changes the element, and the class joins the consumer's.
2. **One key per `Kbd`, and nesting groups.** `<Kbd><Kbd>Ctrl</Kbd>+<Kbd>C</Kbd></Kbd>` draws each key and leaves the outer one plain, as prose's `kbd` rule already does.
3. **`kv-kbd` and prose's `kbd` share one zero-specificity rule in the theme (section 9b):** a flat key in the inline-code family, with the body font at the prose code size, `surface`, a 1px `border-control` edge, `radius-sm`, `nowrap` and no hyphenation. No depth, because depth is for buttons only (ADR-0026). A grouping `kbd` inherits the font, stays on one line and spaces its keys by `space-1`. In forced colours the edge is `CanvasText` (design: `docs/design/kbd.md`).
4. **Key names are not translated and Kbd sets no `lang`.** The consumer sets `lang="en"` on a key in other-language text (3.1.2). A default would be wrong for the keyboards that print `Retur`.

## Consequences

- Positive: a key has one component and one look, in and out of prose.
- Negative: a bare `kbd` inside prose is styled even within fields and nav, but not inside `kv-not-prose`. A bare `kbd` in a card without prose stays unstyled: use `Kbd`.
- The Storybook Keyboard section keeps its own `kbd` styling (a docs-only rule, in the Docs page's text colour).

## Validation

Light component tests (element, class join, nesting, `render`, not a Tab stop, axe), Storybook stories, `theme:check` and the keyboard-docs check.
