# Design spec: Prose styles and the Storybook Foundation section

- **Status:** Draft
- **Designer:** ux-designer agent · **Date:** 2026-10-01
- **Plan:** to be written (proposed Plan 0006). Builds on [Plan 0005](../plans/0005-default-theme-storybook-docs.md)
- **Related ADRs:** [ADR-0013](../adr/0013-default-theme-delivery.md), [ADR-0014](../adr/0014-default-theme-visual-direction-linear.md), [ADR-0017](../adr/0017-default-theme-prototype-implementation.md), [ADR-0018](../adr/0018-prose-styles-and-foundation-tokens.md) (Accepted)
- **Type:** component default styling (prose) + theme/token change + docs page (Storybook)
- **Companion specs:** [default-theme-button-link.md](default-theme-button-link.md), [storybook-presentation.md](storybook-presentation.md)

## 1. Brief

- **Users:**
  - **Prose:** residents reading long guidance on an adopter's service ("How do I apply for …"), and staff reading instructions in internal tools. Also the docs site's readers.
  - **Foundation section:** maintainers, contributors (including agents) and adopters' designers and developers, who build on the tokens, rebrand them and check contrast.
- **Hardest-case users:**
  - Prose: a resident with low vision at 200% text size, on a phone, in Finnish, who also uses a text-spacing bookmarklet. Long compounds, deep lists and a table must still reflow at 320px.
  - Foundation: a designer who is a screen-reader user, checking whether `text-muted` may be used on `warning-subtle` in dark high contrast. The answer must be text in a table cell, not a colour.
- **Job to be done:**
  - Prose: when I publish a long article from a CMS or Markdown, I want to wrap it once and get readable, accessible typography in every theme, without styling each element.
  - Foundation: when I build or rebrand on KvirnUI, I want to see every token, which palette step it uses, and which text and background pairs I'm allowed to combine, with measured ratios, so I don't need a separate contrast tool.
- **Context:** Prose is read once, under stress, on any device. The Foundation pages are desktop workbench pages, used daily or weekly.
- **Constraints:** headless packages ship no CSS (hard rule 5). Prose lives in `theme.css` inside `@layer kv` (ADR-0013). There are no third-party requests, so the fixtures use local images only (hard rule 7). Every string rendered inside a story is fixture text in all six locales (storybook-presentation.md §4).
- **Success criteria:**
  - A Markdown article in `kv-prose` gets 0 axe violations in all four themes.
  - It has no horizontal page scroll at 320px, apart from a table inside its own scroll region.
  - Nothing is clipped or overlaps with the 1.4.12 overrides applied.
  - The matrix answers "may I use X on Y in theme Z?" in one table lookup, with the answer in text.
- **Evidence:** none from users. The Tailwind model is prior art, not evidence.
- **Assumptions and research questions:**
  - Assumption: adopters' CMS output is plain HTML (`h2`, `p`, `ul`, `table`) with no classes. → Research question: what do Nordic municipal CMSs (Sitevision, EPiServer/Optimizely, Drupal) emit for tables and figures?
  - Assumption: the 16px default is right for prose, and resident services opt into `large`. → Open question 1.

## 3. Flow

**Prose (adopter):** wrap the content in `<article class="kv-prose">` (add `kv-prose--large` for long resident text). Put embedded components inside `<div class="kv-not-prose">`, and wide tables in a scroll region. Check the result in the four themes.

**Foundation (maintainer or designer):**

1. Open _Foundation / Overview_ to see what each page answers.
2. Open _Colors / Text on surface_. Read the summary: "48 pairs in use in this theme. 48 pass, 0 fail".
3. Look up the row for `text-muted` and the column for `warning-subtle`. The cell reads "4.92:1 · 4.5:1 or more · Not in use".
4. Switch the Theme toolbar, or open a fixed-theme story, and read again.
5. Rebrand in _Theming_, then see the scoped live check.

Unhappy paths:

- **Forced colours active:** the matrix shows a notice that the system colours replace the theme, so the ratios describe the user's palette. The swatches keep their text.
- **A consumer override breaks a pair in use:** the summary counts it as failing and lists it by name, with the ratio and the minimum.
- **A token can't be measured** (translucent, `color-mix` with transparency, or unparseable): the cell says "Can't measure" in text. It never shows a guessed ratio.
- **Prose contains a component:** without `kv-not-prose` the component still keeps its own look, because prose never styles component parts (§6). Its spacing is the only thing that could look off.

## 5. Structure

**Prose article** (all breakpoints; it's a single column):

```
[main]
  article.kv-prose.kv-prose--large        measure 70ch, centred by the story, not by prose
    h1 · p.kv-lead
    h2 · p · ul (> li > ul)
    h2 · p · figure (img, figcaption)
    h2 · ol (> li > p, > li > ol) · p (kbd)
      h3 · dl
      h3 · p
        h4 · p (address)
    h2 · p (code) · p · pre · div[role=region].kv-scroll-region > table (caption, thead, tbody)
    figure (blockquote, figcaption)
    hr
    h2 · p (strong, em, a) · p (a lang=se)
    div.kv-not-prose > div.kv-button-group > Button.kv-button--primary "Apply online"
    p > small (updated date)
```

**Foundation pages:** `h1` is the page subject, `h2` is each group, and `h3` is rarely needed. Reading order equals DOM order. Explanatory text sits in a `kv-prose` wrapper, and the specimens and tables sit in `kv-not-prose` blocks inside it. This dogfoods prose. Tables and matrices wider than the viewport scroll in a labelled region at 320px.

## 6. Visual specification

### 6.1 Prose: API

| Class                      | On                                   | Effect                                                                                                                                 |
| -------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `kv-prose`                 | a wrapper (`article`, `div`, `main`) | Default size: the `body` role (16px / 1.5)                                                                                             |
| `kv-prose kv-prose--large` | a wrapper                            | The `body-large` role (18px / 1.6), for long resident-facing text (DESIGN.md Typography)                                               |
| `kv-lead`                  | a `p`                                | Lead paragraph, one step up from the prose body                                                                                        |
| `kv-not-prose`             | any element inside prose             | Prose stops styling it and everything inside it. The element itself keeps prose block spacing                                          |
| `kv-scroll-region`         | a `div` around a wide table          | Scrolls horizontally, and has a focus ring. The consumer adds `role="region"`, `aria-labelledby` (the caption's id) and `tabindex="0"` |

**Why `kv-prose` classes, not `data-*` attributes:** ADR-0013 keeps `data-*` for state. Consumer choices are `kv-*` classes (`kv-compact`, `kv-nav`, `kv-button-group`), and prose is the same kind of choice. The `kv-` prefix keeps it apart from Tailwind's `.prose`. The modifier names are spelled out (`--large`, not `--lg`), following the API naming convention (no abbreviations).

**Why no `sm` size:** it would make instructions 14px, which DESIGN.md forbids. Compact contexts use the default.

**Selector rules (for the engineer):**

- Every element rule has zero specificity: `:where(.kv-prose) :where(p)`.
  - Because of that, any component rule in `@layer kv` (for example `.kv-link`, which is 0,1,0) and any consumer CSS wins.
- Every element rule excludes these, also through `:where()`:
  - component parts (components style themselves): an explicit list of their classes, `kv-button`, `kv-link`, `kv-link-new-tab-notice` and the card parts,
  - `.kv-not-prose` and its descendants,
  - descendants of `.kv-nav` and `.kv-button-group`. These are always "not prose", and the list is kept in one place in `theme.css`.
- Known limitation, as in Tailwind: prose nested inside `kv-not-prose` isn't re-enabled.
- `.kv-prose--large` only redefines `--kv-prose-*` tokens. It has no element rules of its own.

### 6.5 Modes

- **Dark and high contrast:** everything is a semantic token, so nothing is theme-specific. In the contrast themes, `border-subtle` becomes `neutral-500` or `neutral-400`, which makes the `hr`, table dividers and code borders stronger automatically.
- **Prose on panels:** the prose pairs on status panels were measured on 2026-10-01 with `read-theme.ts` and `contrast.ts`, in all four themes:
  - `link` on `danger-`, `success-` and `warning-subtle`: at least 5.25:1 (light) and 5.55:1 (dark). The contrast themes are at least 8.50:1.
  - `text-muted` on those backgrounds: at least 5.52:1 (light) and 4.90:1 (dark). The contrast themes are at least 9.65:1.
  - `link-hover` on `primary-subtle`: 6.28:1 (light) and 7.35:1 (dark).
  - `border-control` on `-subtle` (the blockquote bar): at least 4.42:1 (light) and 3.20:1 (dark).
  - `focus-ring` on `-subtle`: at least 4.18:1.
  - All of them pass, but none is in `contrast-requirements.ts` yet. Add them, so `theme:check` guards prose in panels (see §6.7).
- **Forced colours:**
  - `surface` backgrounds disappear (Canvas). The 1px `border-subtle` edges (CanvasText) keep inline code, `pre`, `kbd` and table headers visible, and the monospace font and weight 600 are non-colour cues too.
  - Links are `LinkText` with an underline. The blockquote bar uses `border-control` (ButtonBorder).
  - `mark` loses its background, so the forced-colours block gives it a 1px `CanvasText` outline. Never use `forced-color-adjust: none` (ADR-0013).
- **RTL:** only logical properties are used. List markers, the blockquote bar and `caption` alignment follow `dir` automatically. `pre` and `code` keep their own direction (`dir="ltr"` is the author's job for code in an RTL page).
- **Motion:** none.
- **320px, 400% zoom and text spacing (1.4.12):**
  - No fixed heights and no `overflow: hidden` on text. Line heights are unitless.
  - Spacing is in rem, apart from the relative code size and list indent, which are in em. Nothing depends on a line count.
  - `pre` wraps. Tables scroll in their region. Images shrink. Long words wrap.
  - With the 1.4.12 overrides (line height 1.5, paragraph spacing 2em, letter spacing 0.12em, word spacing 0.16em), nothing must clip or overlap. The Prose `Text spacing` story checks this.

## 7. Accessibility annotations

- **Prose is CSS only.** It changes no roles, except that it never changes `display` on tables or lists and it keeps list markers, so semantics survive, including in Safari with VoiceOver.
- **Author responsibilities** (the Overview and the theme README say so): don't skip heading levels, write alt text for images, give tables a `caption` and `th` with `scope`, add captions to videos (1.2.2) and don't autoplay them, write descriptive link text (2.4.4), and set `lang` on passages in another language (3.1.2).
- **Scroll region:** `role="region"`, an `aria-labelledby` pointing at the caption, and `tabindex="0"`. It has a visible focus ring, so keyboard users can scroll it (2.1.1, 1.4.10).
- **Colour is never the only signal (1.4.1):**
  - Swatches and chips are `aria-hidden` graphics. Every value, step, ratio, tier and "In use" appears as text.
  - Failures have words and an icon.
  - The current theme is named in text.
- **Tables:** every Foundation table has a `caption`, `th scope="col"` and a `th scope="row"` for the token. In the matrix, a screen-reader user who moves by cell hears the row and column headers. The cell text order is ratio, tier, use: "4.92:1, 4.5:1 or more, Not in use".
- **No hover-only information:** no tooltips. Everything is in the cell or the row.
- **Contrast (1.4.3):** the page text is `text` or `text-muted` on `canvas`. Failing samples are never rendered as text (§6.6).
- **Focus (2.4.7, 2.4.11, 2.4.13):** the focus ring specimens are static renderings with `data-focus-visible`. The live elements next to them still take real focus.
- **Motion (2.2.2, 2.3.3):** the demo starts only when the user acts, and it is instant under reduced motion. The button's state is `aria-expanded`.
- **Language (3.1.1, 3.1.2):** the prose story gets `lang` from the toolbar. The Sámi link has `lang="se"`. The English fallbacks have `lang="en"`.
- **WCAG SCs of note:** 1.3.1, 1.4.1, 1.4.3, 1.4.6 (contrast themes), 1.4.10, 1.4.11, 1.4.12, 2.1.1, 2.4.4, 2.4.13, 3.1.2.
- **Tests to derive:**
  - axe on every story in all four fixed themes.
  - e2e:
    - `reflow-320` on _Article_ and _Large_ (no page scroll)
    - _Text spacing_ (no element whose `scrollHeight` exceeds its `clientHeight`, and no overlap)
    - forced colours on _Article_ (code, `pre` and `thead` have a visible border)
    - RTL (the marker and blockquote bar are on the right)
    - Tab reaches the scroll region, and it shows a ring
  - unit:
    - a prose rule never matches a component part or inside `.kv-not-prose`
    - `theme:check` covers the new pairs

## 9. Open questions

1. **Default size.** Should bare `kv-prose` be 16px (proposed: DESIGN.md's `body`, Tailwind's default, the docs site) or 18px, the size DESIGN.md prescribes for long resident text? With 18px as the default, the opt-out would be `kv-prose--compact`, which reads close to `kv-compact`.
2. **h4 in large prose** looks the same as h3. Is that acceptable, as in GOV.UK and with guidance to stop at h3, or should `lead` (20px, weight 600) become h3 in large?
3. **`hyphens: auto`** for fi, sv and nb would help long compounds, but it hurts some readers with dyslexia, and browser dictionaries vary. The proposal is `manual` plus `overflow-wrap`. Do you want it?
4. **Visited links:** DESIGN.md has no visited style. Residents following multi-page guidance benefit from one. Is that a separate token decision?
5. **Theming story, dark rebrand** (resolved by ADR-0019: the brand scale passes in all four themes)**:** a naive teal dark mapping fails (measured: `primary` teal-600 on `primary-subtle` teal-950 is 2.75:1, needs 3:1). Should the story show only the light theme, or show the failure caught by the live check, as a teaching example?
6. **Video in the fixture:** a real `<video>` needs a local clip with a captions file, which adds binary files to the repo. Should it be left out, with `video` sharing the `img` rule and covered by a unit test only?
7. **Docs site:** should the docs article styles move to `kv-prose` in the same plan, or later?
8. **Numeric table columns:** should there be an end-alignment class (`kv-align-end`) for numeric columns in prose tables, or should it be left to the consumer's CSS?
