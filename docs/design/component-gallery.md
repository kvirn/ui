# Design spec: one gallery of cards for Components, Patterns and Content types

- **Status:** Draft
- **Designer:** ux-designer agent · **Date:** 2026-10-10
- **Plan:** [0095](../plans/0095-storybook-patterns-and-content-types.md) T10 (spec); the build plan is to be written
- **Type:** docs page (three index pages, one shared gallery; no library change, no new token)
- **Changes:** [docs-landing-and-header.md](docs-landing-and-header.md) §3.1 rows Components, Patterns and Content types, §8 T3 (superseded: the prose pieces move, §4 here) and §10 Q8 (answered in §6 here). Its shell rules, keys and guards stand.

## 1. Brief

- **Users:** integrators (municipality front-end developers, daily) and evaluators (accessibility consultants, procurement, once). **Hardest case:** a keyboard and NVDA user at 400% zoom (320 CSS px) who reads English as a second language, and a sighted developer with dyslexia who finds parts by picture faster than by name.
- **Job:** _When I need a part for a screen, I want to see what each one is for, so I can open the right page without knowing its name._ Evaluators: _I want to see how much there is and how it's organised._
- **Context:** desktop for integrators, any device for evaluators; scanning, no time pressure; return visits jump to a group.
- **Constraints:** no third-party requests (rule 7); no dead links; existing components, classes and tokens only; site copy is English in the docs app catalog (docs-site.md §4); a card is never clickable (DESIGN.md Cards, Nav tiles); a content type is only the slot between header and footer (0095 D12).
- **Success:** in the test (§9, `pending`), ≥ 80% open the right page for a described job within 30 s; 0 participants reach a link that goes nowhere; screen reader users hear each group's count without counting.
- **Evidence:** none from users. Assumptions: (1) a schematic picture speeds recognition for sighted users → RQ: time to the right card with and without previews. (2) 64 cards in 7 groups need no filter → RQ: does anyone use Ctrl+F or ask for search?

## 3. Decisions (the brief's six points)

### 3.1 Card anatomy and the preview

**Anatomy, every gallery:** `li` card → `h3` (or `h2`, §3.2) holding one Link: the **preview** (decorative, inside the link) and the **name** (the link's only text) → `p` the **one-line job**. The **group** is the list's heading, never repeated on 64 cards (it would be read 64 times). No status, no "Read more", no second link.

| Option for the preview                              | For                                                                                                                                                                                                                                                                                       | Against                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. Live render of the default docs example, `inert` | Never drifts; real look in all four themes; forced colours honest                                                                                                                                                                                                                         | Client JS and hydration for 64 example trees on one index page (most parts are `'use client'`); date examples (Calendar, DatePicker, DateRangePicker) risk SSR/hydration mismatches; Announcer, Focus, Route focus, VisuallyHidden and SkipLink draw nothing, and Dialog, AlertDialog, Popover, Menu, Tooltip and Toast draw only a closed trigger, so a sixth of the cards look alike or empty; wide parts (Table, Calendar, Toolbar) must be scaled into pictures of sub-1rem text; any example landmark, heading, `id` or on-mount effect becomes page noise unless `inert` is honoured; a link can't contain a live example (nested interactive content), so the picture can't be part of the target |
| B. Screenshots (PNG/WebP)                           | Zero JS                                                                                                                                                                                                                                                                                   | Four themes plus forced colours need five images each or the picture is wrong; a capture pipeline to maintain; stale after every visual change; weight                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **C. Inline SVG schematic per item (recommended)**  | Zero JS, server-rendered, prints; follows the theme and forced colours through classes; draws the defining state (the dialog open, the tooltip shown, the selected tab), which A can't; one system for all three galleries, including the content-type wireframe; can sit inside the link | ~64 + 12 + 4 drawings to author and keep honest (mitigated: a small set of primitives, §3.3; a missing drawing is allowed, the card is complete without it)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D. No preview                                       | Cheapest                                                                                                                                                                                                                                                                                  | Not the "cool cards" asked for; loses recognition for the dyslexic and visual users the picture helps                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

**Drawing rules (C):** `svg viewBox="0 0 160 100"`, `aria-hidden="true"`, `focusable="false"`, no `title`, **no text** (text is grey bars: no i18n, no image of text, 1.4.5), at most ~15 shapes, strokes `vector-effect: non-scaling-stroke`, no animation. Colour is by role class only (§3.3): the one part that is the point (the primary button, the selected day, the current item) uses the `key` class; everything else is ink, fill and text bars.

| Gallery       | Preview draws                                                                                                                                                                                                                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components    | The component in its defining state, alone (Dialog: a page with a raised box over it; Tabs: a row with one selected bar; Announcer: a speech bubble from a page edge; SkipLink: a focused bar at the page's top)                                                                                                            |
| Patterns      | The pattern in a page strip (Site header: brand, nav row, search; Hero: title bars and a picture block; Site footer: columns of link bars)                                                                                                                                                                                  |
| Content types | A page: the **shell** (header bar at the top, footer bar at the bottom) in the greyed `shell` class, and the **slot** between them outlined with a dashed `slot` edge holding the type's own blocks (breadcrumb, `h1` bar, tiles, sidebar). The picture shows D12: everything outlined is the content type, the grey is not |

**Link shape (one Tab stop, no nested interactive):** recommended **the picture and the name in one heading link** (`h3 > a > svg + name`). The card stays unclickable (summary and padding are not a target), the target is the picture plus the name, the accessible name is the name only (the SVG is hidden), text selection of the summary works, and the Link's outline ring draws round the whole block. Weighed: heading-only link (picture not a target: pointer users click the picture and nothing happens); stretched `::after` link (needs a DESIGN.md change, blocks selection); whole card in `<a>` (the summary joins the name, verbose; rejected).

### 3.2 Structure

- **Groups:** one `h2` per group (its existing `id`, so `/components#forms` and the landing links keep working), then one `Columns as="ul"` of cards. A group with no items renders nothing (no heading over an empty list).
- **Card heading:** one level under the group heading (`h3`). A gallery without groups (Content types, ≤ 8 items) uses `h2` per card, so no level is skipped.
- **Order:** groups in the IA order (purpose: `componentGroups`; patterns per [storybook-patterns.md](storybook-patterns.md) §3); cards alphabetical inside a group, the same order as the sidebar (3.2.3).
- **Count:** none visible per group; `ul role="list"` announces "list, 15 items". The page lead says the total, derived from the data (§4).
- **Jump links:** the page's "On this page" contents (existing `PageContents`) lists the group `h2`s. Components 7, Patterns ≤ 6: within the 8-entry cap.
- **Filter or search:** **no.** 64 items in 7 labelled groups, plain text names that the browser's find reaches (the SVG has no text, so find never hits a picture). Revisit above ~120 items or 8 groups.

## 6. Visual specification

| Part      | Tokens / style                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| Card      | `surface-raised`, `border-subtle` edge, `lg` radius, `md` padding; no shadow, hover or pointer style on the card |
| Name link | `link` colour, `heading-4` role, underline on hover (contrast themes and forced colours: always); outline ring   |
| Picture   | `docs-gallery-preview` on `surface`; shapes by role class (§3.3)                                                 |
| Job       | `body`, `text`                                                                                                   |

**States:** link default, hover (underline on the name), focus-visible (2px `focus-ring` outline with offset round picture and name), active (`link-hover`). No selected, disabled, loading or empty state: an item without a page is not listed, a group without items is not rendered, a section without items stays out of the header (§8 Q6).

**Modes:** four themes through semantic tokens only. **Forced colours:** card edge `CanvasText` (existing), name `LinkText`, picture edge `CanvasText`; shape classes map `ink`/`text`/`slot` → `CanvasText`, `fill` → `Canvas`, `key` → `Highlight`, `shell` → `GrayText`, set in a `forced-colors: active` block because SVG paint from custom properties is not reliably forced. **Motion:** none. **RTL:** logical properties; the site is LTR, drawings would mirror with `:dir(rtl)` if it ever isn't. **320px / 400% / 1.4.12:** single column, no fixed heights; camel-case names fit 288px; `overflow-wrap: anywhere` as the fallback, no hyphenation of identifiers. **Print:** pictures print as drawn (SVG); no print rule.

**Contrast pairs used (all existing, measured by `theme:check`):** `link`, `text`, `heading` on `surface-raised` and `canvas`; `focus-ring` on `surface-raised`; `border-control`, `primary` on `surface` (pictures are decorative, so 1.4.11 doesn't apply; they still use measured pairs). **New tokens: none.**

## 7. Accessibility annotations

- **Landmarks:** the shell's `banner`, sidebar `nav`, `main`, `contentinfo`; the contents `nav` named by its heading. No `section` per group, no landmark per card.
- **Headings:** h1 → h2 per group → h3 per card (Content types: h1 → h2 per card). No skipped level; group ids stable.
- **Lists:** `ul role="list"` (Columns), `li` per card (1.3.1).
- **Link names (2.4.4, 2.5.3):** the visible name only, unique on each page (component, pattern and type names don't repeat). The picture is `aria-hidden`; the job line is outside the link, reached in reading order after it.
- **Tab stops:** skip link → shell → sidebar → contents links → one per card, in group then alphabetical order. Nothing else is focusable; no focus moves; nothing announced.
- **Target size (2.5.8):** picture plus name, at least 5rem × 3rem; one target per card.
- **Hidden from AT:** each `svg` (`aria-hidden`, `focusable="false"`, no text). No `inert` needed: nothing live is rendered.
- **SCs of note:** 1.1.1, 1.3.1, 1.3.2, 1.4.1, 1.4.3, 1.4.10, 1.4.11, 1.4.12, 2.4.4, 2.4.6, 2.4.7, 2.4.11, 2.5.3, 2.5.8, 3.2.3.
