# Design spec: docs site header with six sections, and the Home landing page

- **Status:** Draft
- **Designer:** ux-designer agent · **Date:** 2026-10-08
- **Plan:** 0089 (to be written; see Q1 on the number)
- **Type:** docs page + information architecture (no library change, no new token)
- **Changes:** [docs-site.md](docs-site.md) §3 (IA) and §5 (header) are superseded where this file differs. Its keys, shell rules (nothing sticky, route focus, JS-off fallbacks) and footer stand.

## 1. Brief

- **Users:** (1) evaluators: municipality frontend leads, accessibility consultants, procurement; (2) integrators who come back daily. **Hardest case:** a Finnish accessibility consultant on NVDA at 400% zoom (320 CSS px), reading English as a second language, who arrives at `/`, judges the library in two minutes, and deliberately makes a form error to see what happens (same persona as [municipality-reference-site.md](municipality-reference-site.md) §1).
- **Job:** _When I'm deciding whether to adopt KvirnUI, I want proof, not adjectives, so I can tell my team it holds up._ Integrators: _When I come back, I want to reach the right section in one step._
- **Context:** desktop and phone; first visit is a judgement call; return visits are reference look-ups.
- **Constraints:** no third-party requests, fonts, images or analytics (rule 7); "designed and tested to meet WCAG 2.2 AA" only (rule 8); no dead links, no empty sections; existing components and tokens only; site copy is en (app-local catalog, as docs-site.md §4).
- **Success:** in the test (§9, `pending`), ≥ 80% find "Get started" and a component's keyboard contract from `/` within 1 minute; ≥ 80% say correctly that KvirnUI is pre-alpha and that AT testing is pending (the honesty check); 0 participants reach a dead end.
- **Evidence:** none from users. Assumptions:
  - Interactive proof persuades evaluators more than feature lists → RQ: which demo do evaluators mention afterwards?
  - Six visible section links are faster than a hidden menu for returning integrators → RQ: time to reach a component page from another section.
  - A transcript of what a screen reader says is understood by sighted visitors → RQ: can they explain what the transcript shows?

### 3.2 Flows

1. **Evaluator:** `/` → hero → a demo → "How we know it works" → a component's Keyboard section, or Get started.
2. **Integrator:** any page → header section link (1 step) → sidebar page.
3. **Unhappy paths:**

| Case                | Behaviour                                                                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| JavaScript off      | Header nav and sidebar shown expanded; Menu and Display settings hidden (as today). Demos render their initial state; their controls show `home.noScript` "Turn on JavaScript to try this example." in place of the interactive part |
| A demo throws       | Error boundary per demo shows `docs.example.error`; the rest of the page works; nothing announced                                                                                                                                    |
| Forced colours      | Settings demo shows `docs.display.forcedColors` (existing key) above its radios                                                                                                                                                      |
| Storage blocked     | Theme choice lasts the visit (existing store); no error                                                                                                                                                                              |
| Reduced motion      | Transcript shown complete, no reveal                                                                                                                                                                                                 |
| Deep link `/#start` | Header not sticky, heading gets `scroll-margin-block-start: space-4`                                                                                                                                                                 |
| Client navigation   | Menu closes, focus to the new page's `h1` (`useRouteFocus`, as today)                                                                                                                                                                |
| 404                 | Unchanged, but `docs.notFound.homeLink` becomes "Go to the home page"                                                                                                                                                                |

## 5. Structure

### 5.1 Header (DOM order = visual order at every width; no CSS `order`)

> **Superseded** by [docs-header-bands.md](docs-header-bands.md) (three primary bands, 2026-10-10), with the Header and Site nav rows of §6 and the header lines of §7 and §11. The DOM-order rule, the Menu behaviour per width and the contract below still hold where that spec does not change them.

```
[skip link]                                     first Tab stop, existing
[header: banner]  Section canvas, kv-compact from 64rem
  brand: Link "KvirnUI" + Badge "Pre-alpha"
  Menu button      (rendered only below 64rem; below 40rem always, 40–64rem only if the section has a sidebar)
  nav "Site" (Navigation.Root, kv-navigation--horizontal): Home · Docs · Components · Patterns · Content types · Theming
  Display settings button → its panel (existing, full width below)
[sidebar nav "<section name>"]  only for sections with ≥ 2 pages
[main#main]
[footer: contentinfo]
```

| Width           | Header layout                                                                                                            | Menu controls                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| < 40rem (320px) | Row 1: brand, badge, Menu. Row 2 (when open): Site nav, wrapping (≈ 3 rows of 44px targets). Row 3: Display settings     | `aria-controls="docs-site-nav docs-sidebar"` (sidebar id only if present); open shows both |
| 40–64rem        | Row 1: brand, badge, Menu (if sidebar). Row 2: Site nav always shown, wraps. Display settings at the end of the last row | Sidebar only (the nav is already shown)                                                    |
| ≥ 64rem         | One row: brand, badge, Site nav, Display settings at the inline end. Compact density. No Menu                            | –                                                                                          |
