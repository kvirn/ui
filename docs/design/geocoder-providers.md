## 1. The open adapter

`GeocoderProvider` is the whole contract. AddressSearch never knows which service it talks to. Target shape (address-search.md D3, being added in P4b):

| Member                                                         | Meaning                                                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `search(query, { signal, locale }) → Promise<AddressResult[]>` | One lookup. `locale` is the provider's BCP 47 locale                                           |
| `name?`                                                        | Who receives the typed text. Fills `addressSearch.privacy` ("…sent to {service}…")             |
| `attribution?`                                                 | The licence or credit text that the service's terms require. Shown in the Notice               |
| `suggest?`                                                     | `true` only if the terms allow a request per pause in typing. Otherwise search on request (D2) |
| `AddressResult { id, label, position, bounds?, address? }`     | `address` = `{ line1, postalCode, city, country }` for the AddressInput hand-off (3.3.7)       |

**Recipe**: a consumer's own endpoint (a proxy or an in-house register), about 15 lines:

```ts
const cityAddresses: GeocoderProvider = {
  name: 'Example City address service',
  attribution: '© Kartverket, CC BY 4.0',
  suggest: true,
  async search(query, { signal, locale }) {
    const url = new URL('/api/addresses', location.origin)
    url.search = new URLSearchParams({ q: query, ...(locale ? { lang: locale } : {}) }).toString()
    const response = await fetch(url, { signal, credentials: 'omit' })
    if (!response.ok) throw new Error(`Address search failed (${response.status})`)
    const { items } = (await response.json()) as { items: Item[] } // Item: your endpoint's row type
    return items.map((item) => ({
      id: item.id,
      label: `${item.street}, ${item.postcode} ${item.city}`,
      position: { longitude: item.lon, latitude: item.lat },
      address: {
        line1: item.street,
        postalCode: item.postcode,
        city: item.city,
        country: item.country,
      },
    }))
  },
}
```

**Rules for every adapter** (the stricter note for the docs page):

| Topic     | Rule                                                                                                                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Abort     | Pass `signal` to every request. Let an `AbortError` reject; never turn it into `[]`. AddressSearch ignores aborted calls and shows only the latest answer                                                                         |
| Errors    | Throw on a non-2xx response, an unparseable body or a service error. Return `[]` only when the service found nothing. No retries inside the adapter: AddressSearch shows `error` and the user retries (this protects rate limits) |
| Timeout   | None in the adapter. AddressSearch owns the 10 s limit and `offline`                                                                                                                                                              |
| Locale    | Map `locale` to the service's parameter. Send `nn` as `nb` or `no` where a service lacks it. Omit a code the service rejects (Google returns `INVALID_ARGUMENT` for an invalid code [8])                                          |
| `suggest` | Follow the service's terms, not its features. Nominatim is always `false` [1]                                                                                                                                                     |
| `name`    | The organisation that receives the text. Behind a proxy, name the final service too ("Example City and Digitransit")                                                                                                              |
| Label     | One line: street and number, postcode, town, in the user's script. Not ALL CAPS (some registers store place names in capitals). Keep ids stable (the service's place id) and remove duplicate labels                              |
| Position  | WGS 84 longitude/latitude. Convert national grids (EPSG:3067, 3006, 25833) in the adapter or ask the service for 4326/4258                                                                                                        |
| Limit     | Request at most 10. AddressSearch shows 6                                                                                                                                                                                         |
| Bias      | Static options on the adapter (country codes, the municipality's bounds) fix the "Storgatan 1 without a town" case. They are not part of the contract                                                                             |
| Privacy   | Send only the query. No cookies (`credentials: 'omit'`), no user ids, no analytics parameters. A billing session token that the provider requires (Google) is random and per search                                               |
| Keys      | A key in the browser is public: restrict it by origin or referrer. A secret (Basic auth, contract credentials) goes only behind the consumer's own proxy                                                                          |
| Caching   | The adapter's decision, per the terms: Nominatim requires a cache [1]; Google allows only place ids and lat/lng for 30 days [6]; Mapbox temporary results may not be cached [10]                                                  |

**Proxy pattern** (recommended in the docs for public-sector production): the browser calls the consumer's own origin, and the server calls the geocoder. It hides the visitor's IP from the third party, holds secrets, caches where the terms allow and rate-limits. The adapter is the recipe above.

**Helper: not now.** `createFetchGeocoder({ url, parse })` would wrap about 4 shared lines (`fetch`, `signal`, `response.ok`). The parts that differ between services (GET or POST, headers, parameters, response shape, caching rules) are the whole adapter. Abort, ordering, timeout and status already live in AddressSearch. A generic `withCache()` would also be wrong for Google and Mapbox, whose terms restrict caching. Revisit after three sub-entries if they share more than that.

## 4. Google geocoding and the Google map adapter

- **Outside the EEA:** Places and Geocoding content "must not" be used "in conjunction with a non-Google map" [7]. So it goes only with `@kvirn-ui/map/google`, or with no map (a form).
- **EEA billing address** (every Nordic municipality): the EEA terms forbid content "With any Map" other than latitude, longitude and place_id. "With any Map" includes "next to, or in a manner that is visually associated with any map, including a Google Map" [7]. So a pin from Google's lat/lng may go on MapLibre or Leaflet. Whether a suggestion list next to any map counts as "visually associated" is a legal question for the consumer: KvirnUI can't decide it. A form lookup with no map is Permitted Use (1) [9].
- **What the terms force on an adapter:** no cache beyond place id and 30-day lat/lng; attribution in the Notice (logo or "Google Maps", G3); an origin-restricted key; session tokens for billing. Predictions need G1 (`resolve`) to get coordinates [8].

## 6. Open questions for the maintainer

1. **O1 G1 `resolve` for suggestions without coordinates.** Recommend yes, before `/google-places`. Cost: one more state in AddressSearch (reuse `searching`, no new key). Alternative: the Google adapter calls Place Details for every prediction (6× the cost; still in the terms).
2. **O2 G2 `intent: 'suggest' | 'submit'`.** Recommend yes, in P4b while the type is open (it is optional, so no breaking change later either).
3. **O3 Rule 7 for single-service sub-entries.** Recommend: `/kartverket` and `/google-places` may default their official URL (the precedent is the Google map adapter's `apiKey` path, plan 0117). Importing them is the consumer's choice, and nothing is sent before a mount and typing. Generic adapters (`/nominatim`, `/photon`, `/pelias`) keep `url` required. Alternative: `url` required everywhere.
4. **O4 `address.country`.** Recommend ISO 3166-1 alpha-2, upper case (every service returns a code); AddressInput maps it to a localised name.
5. **O5 Capitals from Kartverket** (`poststed` "MYRE"). Recommend the adapter title-cases with `toLocaleLowerCase('nb')` per word and hyphen part, with a native reviewer checking the particles (for example "i"). Alternative: show them as given.
6. **O6 Coverage check.** Recommend a docs task: 50 known addresses per country (SE, FI, NO, DK, IS), the hit rate and house-number detail per service. It calls third parties, so the maintainer runs it or approves it.
7. **O7 Legal review** of §4 (Google EEA "With any Map") and the Nominatim personal-data clause, before the docs recommend either for resident forms. This is for the maintainer or counsel, not an agent.

**Validation:** no new UI, strings or colour pairs. AddressSearch's usability plan (address-search.md §8) gains one task: as-you-type against a real `suggest` provider on a slow phone. Result: `pending`.
