# Design spec: the docs site built from the shipped components

- **Status:** Accepted (maintainer answers to §9, 2026-10-06)
- **Designer:** ux-designer agent · **Date:** 2026-10-06
- **Plan:** [0052](../plans/0052-docs-on-built-packages.md) §Phase C
- **Type:** docs site (shell and template), amends [docs-site.md](docs-site.md) §5–§7
- **Rule:** `apps/docs` uses `@kvirn-ui/react` and `theme.css` as they ship. Where they fall short, the flaw shows on the site, it is listed here as a gap, and the docs keep a thin wrapper until the gap ships. `docs.css` is layout glue only.

## 1. Brief

- **Users and hardest case:** as in [docs-site.md §1](docs-site.md#1-brief): a Finnish accessibility specialist with NVDA and 200% zoom, judging the library by its own site. New here: **adopters**, who copy what the site does. A hand-rolled part on the site teaches them to hand-roll it too.
- **Job:** "When I see the docs site, I want it to be built the way I'd build my service, so what I see is what I get."
- **Success:** every row in §3 is a library component or a named gap with an interim wrapper; `docs.css` holds only §6's list; no focus-ring, outline-removal or forced-colours rule in it; 0 axe violations in four themes.
- **Assumption:** adopters read the docs' source as a reference implementation. → Research question: do integrators open the docs repository to copy the shell? (`pending`)

**Flaw found (not a gap, a theme fix):** **F1.** `.kv-card` and `.kv-section` set `display: block` in `@layer kv`, which beats the browser's `[hidden]`, so a hidden Card or Section shows. Restate `:is(.kv-card, .kv-section)[hidden] { display: none }`, as 0047 did for the navigation list (the `theme-css` rule). Until then, R2 puts `hidden` on a plain wrapper.

## 4. Tabs or anchors on the component page

**Decision (recommended): no Tabs for page sections.** Example, Usage, Styling and the rest stay headings in one long page, with the contents list (R11).

| Criterion                                     | Tabs (Example · Usage · Styling)                                        | Headings + TableOfContents                                      |
| --------------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------- |
| Deep link `#keyboard`, shared by a colleague  | Fails unless a hash selects the tab (custom code, `Tabs` doesn't do it) | Native                                                          |
| Find in page, print, browser translation      | Miss hidden panels                                                      | Everything is in the page                                       |
| Screen-reader heading and landmark navigation | Sees one panel; the rest is behind the tab list                         | Whole outline (H key, rotor)                                    |
| TableOfContents                               | Can't link into a hidden panel                                          | Works as built                                                  |
| Prior art                                     | Radix, MUI                                                              | GOV.UK ("tabs hide code from people who scan"), docs-site.md §2 |

Tabs are dogfooded where the content really is one-at-a-time: the Tabs page's own example. Revisit only if user research shows evaluators get lost on long pages (`pending`).

## 5. Gaps, ranked by value for the docs and for adopters

Each is its own plan (with a ux-designer spec when visual). The interim wrapper is a few lines in `apps/docs/components/` and goes when the gap ships.

1. **G1 SkipLink and VisuallyHidden** (roadmap M1, planned). Every adopter site needs a bypass (2.4.1); the docs need two interim CSS blocks without it. `VisuallyHidden` is flat (`<span>`, `as`, class `kv-visually-hidden`), and the theme supplies the clip rule; it never hides focusable content unless it is the skip link. `SkipLink` is a flat `<a href="#id">` (never the router's link), first in the body, with key `skipLink.label` ("Skip to main content", "Hoppa till huvudinnehållet") in six locales. States: hidden, focused (visible, **in flow**, never covering the header: 2.4.11), forced colours (system link colour and ring). On activation it moves focus to the target; a non-focusable target gets `tabindex="-1"` until blur (GOV.UK). Whether the target shows the ring is Open question 1. Interim: `Link.Root as="a"` with `.docs-skip-link`.
2. **G2 Page base in `theme.css`.** "One import styles everything" stops at the page: nothing paints `body`, so an adopter in the dark theme gets the browser's own canvas behind KvirnUI text, an unmeasured pair. A zero-specificity base (`:where(body)`: `canvas`, `text`, the body font and role, `overflow-wrap`) in `@layer kv`, which any adopter CSS beats. A theme and DESIGN.md change: maintainer approval, `theme:check`. Interim: the `body` block in `docs.css`.
3. **G3 Disclosure** (roadmap M1, planned; Accordion and NavigationMenu build on it). APG Disclosure: `Disclosure.Root` (no element; `open`, `defaultOpen`, `onOpenChange`), `.Trigger` (`<button aria-expanded aria-controls>`, a `chevron-down` that becomes `chevron-up` at the inline end), `.Panel` (`hidden` when closed; `hidden="until-found"` to keep find-in-page is a plan question). Never moves focus; no Escape (APG doesn't require it), documented. States: closed, open (`data-open`; the open look needs a DESIGN.md rule, never colour alone), disabled. The plan must settle the docs' case: a panel shown from a breakpoint and expanded without JavaScript (the responsive menu), or leave that to NavigationMenu. Interim: `DocsDisclosure` (Button + `aria-expanded`/`aria-controls` + Icon, about 15 lines).
4. **G4 Route focus.** Every Next.js or TanStack Router adopter needs it (2.4.3). `useRouteFocus(pathname)` or a `RouteFocus` part: after a client-side navigation (not the first load, not a hash change, not Back with scroll restoration) it focuses the page's `h1` (`tabindex="-1"` while focused), and the theme gives it the token ring under `:focus-visible` only. Announcement: Next.js has a route announcer, TanStack Router doesn't, so the plan decides whether the Announcer reads the title, with AT `pending`. Interim: the shell's existing effect and the h1's `tabIndex={-1}`, no outline rule.
5. **G5 Listbox option language.** Language switchers are common in Nordic services (sv, fi, se). An `itemToLang` option on `Listbox.Root` puts `lang` on each native `<option>` and popup option (3.1.2), and on the trigger's value. Small. Unblocks R3. Interim: raw select with `kv-listbox-native`.
6. **G6 Badge** (DESIGN.md "Badges and tags": the theme has none). Status and metadata in staff tools (case lists) and the docs' status. A static `<span class="kv-badge">`, never interactive; choices by role (neutral, primary, and the four statuses), always with words, never colour alone; `radius-full`, `body-small`; forced colours: a `CanvasText` edge. docs-site.md §6 measured `link` on `primary-subtle` (4.68 / 5.44 / 8.72 / 8.33). Interim: plain text (R12).
7. **G7 CopyButton and CodeBlock.** Adopters copy case and payment reference numbers (OCR); the docs copy code. `CopyButton`: a Button that writes text to the clipboard and announces `copyButton.copied` through the Announcer (it exists now); its name stays "Copy"; on failure (no permission, insecure context) it announces `copyButton.failed` and selects the text. `CodeBlock`: Root, Label, Code (`pre` that wraps, no 2D scroll), Copy. No highlighting (a dependency). Interim: the existing `CodeBlock` wrapper.
8. **G8 Navigation group label.** Staff sidebars group links under non-link labels. `Navigation.Label` in a `Navigation.Item`, naming its nested `Navigation.List` (`aria-labelledby`); not a heading, not a link, so it can't be mistaken for one: `label-compact` in `text-muted` (measured on `surface` in docs-site.md §6). 0047 ruled out `Navigation.Group`; this is narrower. Interim: `.docs-nav-group-label` (kept, marked interim).
9. **G9 Site header and footer blocks** (roadmap M4). A brand link (text colour, weight 600, underline on hover: identity is the cue), an optional logo, a Badge, a horizontal `Navigation` for top-level sections, the Menu disclosure, and a footer with statement, contact and feedback. Low for the docs: they have no top-level sections yet, and a second header `nav` would duplicate the sidebar. Interim: R13, R14.

## 6. `docs.css` after Phase C

**Keeps (layout glue):** the three `--docs-*` constants and `scroll-padding-block-start`; `body { margin: 0 }`; the max-inline-size and centring wrappers for header, layout and footer; the 64rem grid (sidebar column, `minmax(0, 1fr)`); main's padding by breakpoint and the column and measure caps; header and Card-header flex rows (`flex-wrap`, `gap`, `justify-content`); the display groups' flex row; the sidebar wrapper shown or hidden below 64rem and the no-JS rules, on docs elements only; the Menu wrapper hidden from 64rem; the three section edge colours (DESIGN-sanctioned); `.docs-status` spacing.

**Shipped and deleted:** `.docs-skip-link` and the visually-hidden clip (G1, `SkipLink`), the shell's route-focus effect and the h1 `tabIndex` (G4, `useRouteFocus`).

**Interim, deleted with their gap:** the `body` canvas, colour and font (G2). `.docs-nav-group-label` went with G8.

**Shipped and adopted (2026-10-06):** G3 (`Disclosure` for Display settings and the navigation groups; the Menu keeps `DocsDisclosure`, because a panel shown from a breakpoint is not a Disclosure feature), G5 (`Listbox native="always"` with `itemToLang`, R3), G6 (`Badge` in the status line and header), G7 (library `CodeBlock` with Copy), G8 (`Navigation.Label`). Still interim: `DocsDisclosure` for the Menu, G2, G9.

**Goes:** every `:focus-visible` ring (`.docs-wordmark`, `.docs-radio input`, `.docs-select`), `.docs-main:focus` and `.docs-h1:focus, .docs-display:focus` outline removal, the `forced-colors` block, `.docs-wordmark`, `.docs-badge`, `.docs-toggle[aria-expanded]` and `.docs-chevron` (with its transition), `.docs-display-panel`, `.docs-fieldset`, `.docs-radio`, `.docs-display-note` colour and size, `.docs-display` type, the `h2` hairline, `.docs-example*` boxes and toolbar, `.docs-select`, the stage `p` margins, `.docs-code-label` type, `.docs-visually-hidden` once R12 lands.

## 7. Accessibility annotations (changes only)

- **Tab stops in order:** skip link → wordmark → Menu (below 64rem) → Display settings → (panel open: Colour scheme group, Contrast group: one stop each, arrows move and check, mirrored in RTL, native) → navigation links → main content (contents links, then per example: the language select, the example's controls; page links in order). The footer has no stops.
- **Focus moves:** none from the disclosures, the radios or the select. Skip link: to `#main` (sequential start point). Route change: to the `h1`. The menu closes on navigation; if it closes otherwise, focus goes back to Menu.
- **Names:** `Navigation.Root label` "Documentation"; contents `nav` by its visible heading; two navs with different names (the dev warning checks). Each example `figure` by its `h3`. Radio groups by their legends.
- **Announcements:** none added. G4 and G7 bring the first ones.
- **WCAG SCs of note:** 1.3.1, 1.4.1, 1.4.10, 2.4.1, 2.4.3, 2.4.7, 2.4.11, 3.1.2 (R3 stays interim until G5), 4.1.2.
