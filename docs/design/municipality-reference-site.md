# Design spec: the reference municipality site in `apps/docs`

- **Status:** Accepted (maintainer decisions in §10, 2026-10-06)
- **Designer:** ux-designer agent · **Date:** 2026-10-06
- **Plan:** [0053](../plans/0053-docs-as-municipality-site.md)
- **Type:** inventory and build order (page types, templates, blocks, patterns). Each missing piece gets its own plan and, when visual, its own spec. This file links the others and does not repeat them: the docs shell is [docs-site.md](docs-site.md), its gaps **G1–G9** are [docs-site-components.md §5](docs-site-components.md#5-gaps-ranked-by-value-for-the-docs-and-for-adopters).
- **Rule (maintainer, final):** the library comes first. A missing component, block or pattern is built in `@kvirn-ui/*`, reviewed in Storybook, then used on a reference page, then documented in the docs app. The roadmap is the order.

## 1. Brief

- **Users:**
  1. **Evaluators** (municipality frontend teams, accessibility specialists, procurement): "When I judge KvirnUI, I want to see the pages a municipality actually runs, working, so I can tell whether it covers our site."
  2. **Integrators** (in-house teams and suppliers): "When I build our site, I want to copy a whole page type and see exactly which parts it uses, so I don't rebuild patterns."
  3. **The fictional resident** each page is designed for. The pages are judged as if real, so each one is designed for the hardest resident case: once a year, on a phone, under stress, in a second language, with a screen reader or a tremor.
- **Hardest-case user:** a Finnish accessibility consultant evaluating for a bilingual Ostrobothnian municipality, with NVDA, 400% zoom (320 CSS px), English and Swedish as second languages. They open a form page, make an error on purpose, and judge the library by what happens.
- **The municipality: Kvirnby kommun** (fictional; the name carries the library's name, so it can't be mistaken for a real place). A mid-sized Swedish municipality. **Locales (decided, Q1):** `sv` first and `en`, both complete; nothing else in v1. Finnish and Sámi pages (a Swedish municipality in the Finnish and Sámi administrative areas, Lag 2009:724, `TODO(legal-verify)`) are a later addition. Tone: plain Swedish (_klarspråk_), "du" and "vi", calm, no blame.
- **Constraints:** no third-party requests, cookies or analytics (rule 7), so no maps, embeds, real eID redirects or consent to ask for. No compliance claims (rule 8). Every form is client-side only and says so. Reference content strings live in the docs app's messages; every string a block renders lives in `@kvirn-ui/i18n` in six locales (rule 4).
- **Success criteria:**
  - Every reference page imports `theme.css` and `@kvirn-ui/*` only: **no `docs.css` on reference routes** (the proof that adopters can do the same).
  - Every page type in §2 works at 320px and 400% zoom, in four themes and forced colours, with 0 axe violations.
  - Each reference page links to "How this page is built", which lists every part with its docs page.
  - ≥ 80% of evaluators correctly say Kvirnby is not a real municipality, and ≥ 80% find the parts a page uses within 2 minutes (usability plan, §8, `pending`).
- **Evidence:** none from users. **Assumption:** evaluators trust a working page more than a component list. → Research question: do evaluators open reference pages or component pages first, and which do they copy from?

## 3. Templates and layout primitives

| Template           | Regions in DOM order (= reading and focus order)                                                                                                                      | 320px                                                   | 40rem     | 64rem and wider                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | --------- | ----------------------------------------------------------------------- |
| **T1 Site shell**  | skip link → `banner` (reference notice row, brand, utility links, language links, search, main nav) → site alert → `main` → `contentinfo`                             | header wraps to rows; main nav behind "Meny" (G3)       | same      | one brand row and one nav row; nav always shown                         |
| **T2 Landing**     | `main`: intro band (Section) with `h1` and lead → link-grid bands → teaser band → contact band                                                                        | one column                                              | 2 columns | 3 columns; container max `80rem`                                        |
| **T3 Article**     | breadcrumb `nav` → section `nav` → `main` (`h1`, lead, contents, prose, meta, related)                                                                                | section nav collapsed behind "I det här avsnittet" (G3) | same      | sidebar column + content column; text at `45rem`                        |
| **T4 Transaction** | skip link → `banner` (notice row, brand, service name, language, "Kontakta oss") → `main`: back link → error summary → `h1` question → Stepper → fields → one primary | one column, `40rem` max at every width; no main nav     | same      | same: a form never gets a sidebar                                       |
| **T5 List**        | breadcrumb → `main`: `h1` → (search field) → count as text → list → pagination                                                                                        | one column                                              | same      | one column `45rem` (lists scan top to bottom; no card grid for results) |
| **T6 Status**      | `main`: `h1`, one or two paragraphs, links                                                                                                                            | one column `40rem`                                      | same      | same                                                                    |

Nothing is sticky. A reference page's `<html lang>` is the page's locale, so the reference site needs its own root layout (a route group), separate from the docs' `lang="en"` (3.1.1).

**Layout components (maintainer, 2026-10-06: React components, not bare theme classes).** None exists today; the docs shell does this in `docs.css`. Four, in `@kvirn-ui/react`, like Section and Card: each renders a part class, `theme.css` supplies the CSS, and without the theme they are plain elements (rule 5). Flat for a single element, a namespace for parts (`docs/architecture.md` naming rule; flat part exports for server components).

| Component                                | Why it earns its place                                                                  | Parts                           | Props (typed choices, no free CSS)                                                                                                                                                                    | Class rendered (theme supplies)                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `Container` (flat)                       | every template; replaces the docs' three max-width wrappers                             | –                               | `size`: `'page'` (default: centred, max `80rem`, inline padding `space-4`/`6`/`10` by breakpoint) · `'reading'` (`45rem`) · `'form'` (`40rem`); the two measures are start-aligned and add no padding | `kv-container`, `kv-container--reading`, `kv-container--form`                                    |
| `Stack` (flat)                           | the rhythm between blocks outside prose (T2 bands, T4 form parts, lists)                | –                               | `gap`: `2` · `4` · `6` (default) · `8` (the `space` steps DESIGN.md names)                                                                                                                            | `kv-stack`, `kv-stack--gap-2/4/6/8`                                                              |
| `Columns` (flat)                         | link grids, teasers, footer groups; "Grid" is avoided because it reads as the ARIA grid | –                               | `minColumnWidth`: `'sm'` (`14rem`) · `'md'` (default, `18rem`) · `'lg'` (`24rem`); `gap`: `4` · `6` (default) · `8`                                                                                   | `kv-columns`, `kv-columns--min-sm/md/lg`, `kv-columns--gap-4/6/8`                                |
| `SidebarLayout` (Root, Sidebar, Content) | T3 and the docs shell: a fixed side column from 64rem, stacked below                    | `.Root`, `.Sidebar`, `.Content` | Root `sidebarWidth`: `'sm'` (`16rem`) · `'md'` (default, `20rem`). The side follows DOM order: whichever part comes first is at inline start                                                          | `kv-sidebar-layout`, `--sidebar-sm/md`, `kv-sidebar-layout-sidebar`, `kv-sidebar-layout-content` |

- **Rejected:** `Cluster` (the header and footer blocks lay out their own rows and `ButtonGroup` covers buttons; revisit at a third use), `Grid` (name), responsive prop objects and `style`-like props (`padding="13px"`): a site changes values in CSS, not props.
- **Element and landmarks:** each renders a `<div>` and implies no role, landmark, name or `tabindex`. `render` decides the element (`<Columns render={<ul />}>` with `<li>` children for a list of links, so its count is announced; `<SidebarLayout.Sidebar render={<nav aria-label=… />}>`). A landmark is always the consumer's choice and must be named. `.Content` is not `<main>` by default (a page can have one `main` only).
- **Order:** DOM order is the visual, reading and focus order at every width. No `reverse`, `order` or dense-packing prop exists (1.3.2, 2.4.3).
- **Reflow:** column tracks are `minmax(min(<width>, 100%), 1fr)` and the sidebar stacks below `64rem`, so nothing scrolls sideways at 320px or 400% zoom (1.4.10). No fixed heights (1.4.12).
- **State and behaviour:** none, so no `data-*`, no hook beyond what Section has, no client code (usable in a server component). Collapsing a sidebar is Disclosure's job (G3), not the layout's.
- **Prose:** the four classes join the not-prose boundary list (the roadmap's guard test), so prose margins never fight the gap.
- **Page base:** `:where(body)` canvas, text and font is **G2**, in the working tree.

### Briefs for the missing pieces

Each is sized to be one plan. G1, G3, G4, G6, G7, G9 are briefed in docs-site-components.md §5 and only amended here.

- **Layout components (new, M1 primitives).** `Container`, `Stack`, `Columns` and `SidebarLayout` as specified in §3: components in `@kvirn-ui/react` with `render`, typed choice props, the part classes in `theme.css` (logical properties, `space` steps, no reordering: `order`, dense packing and `row-reverse` are banned), a DESIGN.md "Layout" subsection, stories at 320px, 40rem, 64rem and 80rem including `render={<ul />}` and a named `nav` sidebar, and an `.a11y.md` each that says they add no semantics. Tests prove what's testable: the element `render` gives, no role or `tabindex` added, DOM order kept, no horizontal scroll at 320px (1.4.10). Done when the docs shell's own layout glue moves to them and `docs.css` shrinks to the docs-only list.
- **G3 amended: Accordion.** After Disclosure, `Accordion` is a list of Disclosures with headings (APG Accordion): each trigger is a `<button>` inside an `h2`/`h3` the consumer chooses, panels `hidden` (find-in-page with `until-found` is a plan question), every panel independent (no "only one open"), no arrow-key navigation unless the plan adopts APG's optional keys. A "Show all" button is a later option, not v1.
- **G9 amended: Site header and footer.** Header rows: the notice row slot (§6), brand (`Link` brand look, an optional local SVG logo with the municipality name as text), utility links ("Kontakta oss" first, so help sits in the same place on every page, 3.2.6; "Mina sidor"), B6 language links, the search slot (B16), and the main `Navigation` horizontal with up to 7 topics, behind a G3 "Meny" disclosure below 64rem. A transaction variant drops the nav and search and adds the service name. Footer: a `Columns` of named `nav`s with `h2` headings (Contact, About the site with statement, feedback, privacy, cookies), the organisation name and address. Strings: `siteHeader.menu`, `siteHeader.navigationLabel`, `siteFooter.label`.
- **B6 Language links (recipe).** A horizontal `Navigation.Root label` ("Språk", "Language") whose links show each language in itself ("Svenska", "English" in v1; "Suomi" and "Davvisámegiella" later) with `lang` and `hrefLang`; the current language carries `aria-current="true"`. No flags, no select, no automatic redirect. Docs page and story; no new component unless review asks for one.
- **B7 Site alert (rule).** A DESIGN.md rule: one site-wide Alert at most, directly after the `banner` and before `main`, `Alert.Warning` or `Alert.Info`, never announced on load, optional `Alert.Close` whose dismissal lasts the session. No new part.
- **Breadcrumb (M3).** `Breadcrumb.Root` (`<nav>` named `breadcrumb.label`, "Du är här"), `.List` (`<ol>`), `.Item`, `.Link`; the current page is the last item, plain text with `aria-current="page"`, so it is never a link to the page you are on. Separators are CSS, hidden from AT, and mirror in RTL. It wraps at 320px and never collapses into "…", because a hidden level is a hidden way out. Not inside `main`.
- **Pagination (M3).** `Pagination.Root` (`<nav>` named `pagination.label`), Previous and Next as links with words (`pagination.previous`, `pagination.next`) and arrow icons, page-number links with `aria-current="page"`, an ellipsis that is text. URLs, never buttons, so Back and sharing work. Below 40rem: Previous, "Sida 2 av 9" (`pagination.status`) and Next only. Targets 44px.
- **SummaryList (new primitive).** A native `<dl>` with `SummaryList.Root`, `.Row` (a `div`), `.Key` (`dt`), `.Value` (`dd`) and `.Actions` (`dd`) whose Change link reads "Ändra" plus the key, visually hidden (`summaryList.change`, needs G1). Rows stack below 40rem. Used by check answers, contact cards, case cards, events and the statement. Theme class `kv-summary-list` with `border-subtle` row dividers. Prior art: GOV.UK Summary list.
- **Back link (`kv-link--back`).** A `Link` choice: `arrow-back` icon first (mirrors in RTL), text "Tillbaka" (`backLink.label`) or the step's name, placed before `main`'s `h1` and before the error summary. It is a link to the previous step's URL, not `history.back()`, so answers are kept by the form state.
- **Stepper → step indicator (M4, narrowed).** A line of text under the question `h1`, its own element and the next reading stop: "Steg 2 av 5" plus the section name (`stepper.status`, `stepper.statusWithName`), `body` in `text`, never dots or a progress bar alone, never a link list. No `aria-describedby`, no live region (Plan 0083, `stepper.md`). A full task list ("Ansökan: 3 av 5 delar klara") is a later pattern.
- **ErrorSummary (M4 block, Form wizard).** Built on `Alert.Danger` (DESIGN.md "Error summary"): title `errorSummary.title` ("Det finns ett problem") as an `h2`, a list of links to each invalid control's id, worded like the inline errors. On submit with errors it renders before the `h1` and the Stepper, receives focus (`tabindex="-1"`, the token ring under `:focus-visible`, maintainer decision 1), and is not announced. A link moves focus to the control and scrolls its label into view; a group links to its first option. The page `<title>` gets `errorSummary.titlePrefix` ("Fel: "). Updates on each submit, never while typing.
- **G7 amended: reference number.** On P8 the number is in the `numeric` role (needs a `kv-numeric` text class, or a `Kbd`-free span: plan decides) with `CopyButton` after it. The number is also in the Alert.Success title, so it is read even without copying.
- **Login entry (M4 block).** A page of one Card per e-ID method, each with one link in its heading, equal in look (no primary and no `kv-link--service`, which is one per view: the choices are equal), names from the adopter (BankID, Freja eID, Suomi.fi-tunnistus, ID-porten), and "Andra sätt att ansöka" below. No CAPTCHA (3.3.8). On the reference site the methods are generic ("E-legitimation, exempel") and lead to a fake sign-in (Q7).
- **Timeout warning (M1–M2 dependencies).** Needs AlertDialog (native top layer, no Portal or FocusScope; Plan 0067). The block: an `AlertDialog` 2 minutes before expiry, title and body from i18n, "Fortsätt" (primary, initial focus) and "Logga ut"; the remaining time in words, updated once a minute, never read every second; on expiry a T6 page that keeps answers and offers sign-in again. The reference flow has no server session, so it is triggered by a demo control in the notice row (Q14).
- **Search block (M4).** A `<search>` landmark with `Field.Label` "Sök på webbplatsen" (visible on the search page, VisuallyHidden in the header), TextInput `type="search"`, a Button "Sök" (never icon-only). Results page: the count as text in the `h1`'s lead ("12 träffar på ”förskola”", ICU plurals), announced politely once on a client-side result change only; each result a title link, the breadcrumb path in `body-small`, and an excerpt with `<mark>` (prose already styles it); no results: spelling advice, popular pages, contact. Results are a list, not a Table.
- **Statement block (M4).** Structure and headings only, per variant (SE after Digg's template, FI in fi and sv, NO linking to uustatus.no, EU/EAA): how accessible the site is, known problems with reasons (a list the adopter fills), how to report (links B28), enforcement body, how it was tested, dates. **Never pre-fills a conformance status** (regulations skill). Headings and fixed wording in `@kvirn-ui/i18n`; facts are props or children.
- **Feedback block (M4).** One page: which page (prefilled with the referring URL, editable), what went wrong (Textarea, CharacterCount), how to reach you (optional email, `autocomplete="email"`), then B21 and a confirmation. Never asks for a personal identity number. The adopter supplies the submit; the reference site's says nothing was sent.
- **Consent banner (M4).** Before `main`, in flow, not a dialog and not a trap; "Godkänn" and "Avvisa" equal in look (two secondary buttons, no primary), a settings link, nothing pre-ticked, an ePrivacy note. Storybook and its docs page only: Kvirnby sets no cookies (Q9).

- **Labelling, so nobody mistakes Kvirnby for a real service:**
  1. A notice row, first inside `banner` on every reference page, in the page's language (`reference.notice`, §7), with "Så är sidan byggd" and "KvirnUI-dokumentation" links. A Section band in `canvas`, not an Alert (it isn't a status), never dismissible.
  2. `<title>`: "{page} – Kvirnby (påhittad kommun) – KvirnUI".
  3. `robots: noindex` on reference routes, so search engines don't list a fake municipality.
  4. Contact data that can't reach anyone: `@kvirnby.example` (RFC 2606), phone numbers from a range reserved for fiction or none (`TODO(legal-verify)` with PTS), no real organisation or personal identity numbers.
  5. Forms submit nowhere; every confirmation says "Inget skickades: det här är en referenswebbplats".
  6. No real coat of arms or e-ID marks (Q7).
