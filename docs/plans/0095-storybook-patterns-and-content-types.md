- **Status:** Draft (decisions D1–D3 wait for the maintainer)
- **Owner:** lead
- **Created:** 2026-10-09 · **Target:** M4 pilot, ahead of the docs shell
- **Related:** [0053](0053-docs-as-municipality-site.md), [municipality-reference-site.md](../design/municipality-reference-site.md) (inventory, §5 slices, §10 decisions), [0090](0090-docs-header-and-landing.md), `storybook-docs` and `design` skills

## Goal

The docs site is the documentation and also a complete municipality site. Its shell (header, footer, templates) is built and reviewed in Storybook first (0053 working rule), so Storybook gets three sections that read like the docs `/components` index: **Components** grouped by purpose, **Patterns** grouped by purpose, and **Content types** (whole pages in the site chrome).

## Non-goals

- New library components or tokens. Pattern CSS classes in `theme.css` are in scope (D6). A pattern is a composition of shipped components; a missing part is a gap listed below and gets its own plan (0053 rule).
- Moving the docs app to the patterns. That is the step after the maintainer reviews them here.
- Third-party requests (maps, embeds, analytics, consent calls; rule 7). Claims of compliance (rule 8).

- **24 of 25:** accordion, contact card, image, link list, nav tiles, page header, preamble, rich text, teaser, landing page, main nav, login / My pages, share, last-updated, read aloud (23), skip link (22).
- **Mid:** filter (23), news list (23), related links (22), table (21), TOC (21), opening hours (20), address (19), hero (19), search box (19), map (18), document list (18), pagination (16), card grid (16), event list (16), mega menu (15), alert (13), fact box (12).
- **Rare:** carousel 9, tabs 7, quote 7, feedback widget 5, key figures 0, sub-page list 0.
- **A start page is** rich text, link list, news list, CTA, hero, nav tiles, teaser, search, contact, events. **A landing page is** header, preamble, breadcrumbs, link list, teasers, nav tiles, meta. **A content page is** header, rich text, preamble, breadcrumbs, CTA, contact card, meta, teaser, image, TOC.

## Design

### Information architecture

Top level, as in `opti-react`: Foundation · Components · Patterns · Content types.

**Components** use the docs groups (`componentGroups` in `apps/docs/components/site-sections.ts`): Actions · Content · Layout · Navigation · Forms · Choice and overlays · Data and behaviour. Title becomes `Components/<Group>/<Name>`; `Components/Form/*` becomes `Components/Forms/*`. Story files stay in `src/components/<name>/`.

**Patterns** (survey coverage in brackets). Each is a story file with its states, at 320px and wide, and a Docs page listing the parts it uses.

| Group                    | Patterns                                                                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Site chrome              | Site header [24] with mega menu [15], transaction header, Site footer [25], Language links [25], Site alert [15], Cookie consent [25, story only], Page tools (read aloud 23, share 24, print 21) |
| Navigation and promotion | Hero [19], Top tasks, Nav tiles [24], Link list [24], Service link / CTA [25], Related links [22], Breadcrumb and section nav [21, 11]                                                            |
| Content and media        | Preamble [24], Fact box [12], FAQ (Accordion) [24], Table [21], Contents [21], Figure [24], Document list [18], Video (native `<video>` only) [15]                                                |
| News, events and notices | News list [23], Event list [16], Notice [13], Subscribe [25]                                                                                                                                      |
| Search and forms         | Search box [19], Search results [18], Filter [23], Pagination [16], Form with error summary [21], Login entry [24], Page feedback [5]                                                             |
| Places and contacts      | Contact card [24], Opening hours [20], Address and visit [19] (a text address and a directions link, no map), Unit finder [17]                                                                    |

Left out on purpose: carousel (9; 2.2.2 cost, no job it does better than a list), key figures (0 observed).

**Content types** under `Content types/`. First slice is the maintainer's four: **Start page** (T2), **Subpage** (the survey's landing page: topic with child links), **Content page** (T3), **Documentation page** (a docs article: sidebar, TOC, prose, API, prev/next; not in the survey). Later, by survey coverage: Search results, Privacy, News article and list, Contact, Accessibility statement, Form page, Event and list, Unit page, Cookies, 404, Easy-to-read.

### Code home

`packages/patterns/src/<group>/<name>/<name>.tsx` (composition, typed props named after their parts, content passed in), `packages/patterns/src/content-types/<name>/`, and the Kvirnby fixtures in `packages/patterns/src/fixtures/` (`sv` and `en`, switched by the Locale toolbar; images are inline SVG data URIs), exported from `@kvirn-ui/patterns/fixtures` so Storybook and the docs app use the same world. Stories: `apps/storybook/src/patterns/<group>/<name>.stories.tsx` and `apps/storybook/src/content-types/<name>.stories.tsx`. A pattern takes its content as props; any fixed string it renders itself (menu label, skip-link text) comes from `@kvirn-ui/i18n` in six locales (rule 4).

### Accessibility contract (shell level; each pattern's spec completes its own)

Content-type stories are `layout: 'fullscreen'`, have one `banner`, one `main`, one `contentinfo`, a SkipLink first, one `h1`, named repeated landmarks, `lang` on the page, nothing sticky (2.4.11), no reordering (1.3.2). Every story already runs in four themes with axe; patterns add no exceptions.

### Gaps against the library (each its own plan, library first)

Hero and Site header/footer as library blocks (G9, 0053), Breadcrumb, Accordion, Pagination, SummaryList, Badge, CopyButton status in the roadmap; check each against the tree at its task. A pattern that needs one not yet shipped renders a thin local composition and names the gap in its Docs page.

## Decisions

Taken as defaults; overturn here.

- **D1 Patterns and Content types are top-level siblings of Components** (maintainer, 2026-10-09), as the reference Storybook has it. Components mirrors the docs index.
- **D2 The docs app consumes the patterns** (maintainer, 2026-10-09), so they cannot live in `apps/storybook` (an app does not import an app). **Home: a new package `packages/patterns` (`@kvirn-ui/patterns`), `private: true` until reviewed** (maintainer, 2026-10-09). `@kvirn-ui/react` stays headless with no blocks; the package depends on it and `@kvirn-ui/theme` classes, ships zero CSS (rule 5) and no new third-party dependency. Updated in the same change: the repo map in `AGENTS.md`, `docs/architecture.md` packages list, the pnpm workspace. Stories stay in `apps/storybook/src/patterns/` and `content-types/` (packages ship no Storybook files); the compositions live in the package.
- **D3 Mega menu: add it** (maintainer, 2026-10-09; spec Q6 overturned, 15 of 25 surveyed sites have one). Built as the APG Disclosure Navigation pattern from Disclosure and Navigation, never `role="menu"` (the roadmap's "NavigationMenu: not planned" stays true for a component). The keyboard contract goes in its spec and the `keyboard` skill. Site header lists it as a variant.
- **T1 placements.** Not in a docs group, so placed by hand: EmptyState and Tag in Content; Mask, Label, HelpText, ErrorMessage, Rich text editor and Overview in Forms. Story IDs follow Storybook's sanitising, so `ScrollArea` is `scrollarea`. 47 comments in fixtures and stories still say `Components/Form/<Name>`: stale names only, left for the next touch of each file.
- **D6 Pattern CSS lives in `@kvirn-ui/theme`** (maintainer, 2026-10-09): new `kv-*` classes in their own file imported by `theme.css`, semantic tokens only, under `theme:check` and the raw-colour lint (`theme-css` skill). `@kvirn-ui/patterns` stays zero-CSS and renders plain elements without the theme.
- **D7 DESIGN.md text, no new token** (maintainer, 2026-10-09): disclosure trigger in a nav row, the mega panel (square, full-width, level 3), the brand link, the site alert as a named region. Same change as the CSS. Hero uses `display`; the docs hero's colour wash stays docs-only.
- **D8 Spec questions, lead's defaults** ([spec §14](../design/storybook-patterns.md); overturn here): mega panel overlays from 64rem and closes on focus-out, Escape and outside press (Q1); site alert stays a named region before `main` (Q2); the Documentation page shows the KvirnUI docs header (Q3); the §3 IA changes are accepted: page meta in Page tools, Lättläst and Teckenspråk in Language links, header search ships with the header, Contact card moves to T3 (Q4); Teasers stand in for News list and Event list on the Start page until T5 (Q5); Share is copy link only, rule 7 (Q6); the Print button shows now and works with the browser's print, `print.css` stays 1.0 (Q7); the fixture phone number is from a range reserved for fiction with `TODO(legal-verify)` (Q8); no hover-open in v1 (Q9).
- **T2a implementation.** Site header (brand `current`, a Transaction header with `serviceName` and no search or navigation), mega menu, language links, Site footer and PageFrame (`locale: 'sv'|'en'`, wraps KvirnProvider and sets `lang`) are in `packages/patterns/src/{site-chrome,page-frame}`; fixtures `kvirnby` (sv, en) and `kvirnbyDocs` (en only); links are `#` fragments. `useMessages` comes from `@kvirn-ui/react/internal`, as rich-text does. The Meny panel keeps `hidden` and CSS shows it from 64rem, so tests use a box check (`expectDrawn`). Escape is handled in the composition and calls `preventDefault` only when it acted. `data-trail` marks the current-section trigger. Lättläst and Teckenspråk stay Swedish-labelled on the English page (`lang="sv"`). CSS is `packages/theme/patterns.css` imported by `theme.css`; DESIGN.md has a "Site chrome patterns" subsection. Added i18n keys: `siteHeader`, `languageLinks`, `siteSearch`, `siteFooter` (fi, nb, nn drafts and se English placeholders flagged in the file headers). **Gate tooling widened, maintainer to confirm:** the keyboard-docs check also walks `apps/storybook/src/patterns`, and the raw-colour lint includes `patterns.css` (both only add coverage). **Pre-existing, not this plan:** two tooling tests fail on `read-aloud` (dev-warnings table lacks `read-aloud-no-voice`; the keyboard-docs row "Arrows, typeahead" names no test).
- **D9 Composition rule** (maintainer, 2026-10-10; overturns the data-prop shape of T2a): a pattern is a compound component, `X.Root` plus named parts (`SiteHeader.Topbar`, `.Brand`, `.Search`, `.Menu`), that wraps shipped components into a feature. Components and text are passed as children: `<SiteHeader.Brand href="/">Kvirnby kommun</SiteHeader.Brand>`, never `{ label, href }` objects or arrays in props (no `items`, `topics`, `links`). A part is one native element or one library component and takes `as`, `className` and the rest props like a library part. Props are for behaviour and state (`current`, `defaultOpen`, `name`), never content. DOM order is children order: no `position` or `order` props. The pattern names landmarks and renders its own fixed strings from i18n (overridable by `messages`) and owns behaviour (Meny state, Escape, focus after close). Stories write literal JSX with literal Swedish text; there is no fixture object. Shared story chrome is a small JSX component in story support. The package `fixtures` export holds assets only (images, marks).
- **T3a implementation.** Hero, Top tasks, Nav tiles, Teaser and Card grid are parts in `packages/patterns/src/navigation-and-promotion/`. `TopTasks.List` exists because a `ul` cannot hold the heading. Hero uses the existing `display` size; its image is a grid column from 64rem and decorative (`alt=""`). Teaser's image bleeds by the card padding inside `Card.Body`. The Top tasks heading is content, so no i18n key. DESIGN.md has a "Promotion patterns" subsection (maintainer-review note, no token).
- **R1 and R2 implementation (composition rule).** Header family: `SiteHeader.{Root,Notice,Topbar,Brand,Logo,Service,Utility,UtilityLink,Search,Menu}`, `LanguageLinks.{Root,Link}`, `MainMenu.{Root,Link,Overview,Topic,TopicButton,TopicPanel}` (directory `main-menu/`; the mega menu is a variant, a `Topic` instead of a `Link`). Roots are `X.Root`, not callable (library convention). `data-trail` is set after hydration by a layout effect (visual only). Footer: `SiteFooter.{Root,Groups,Contact,About,Group,Heading,Links,Link,Address,Organisation}`; `Contact` and `About` own their i18n headings. Alert: `SiteAlert.{Root(tone),Title,Body,Link,Close}`, the presence of `Close` replaces a `dismissible` prop. Consent: `CookieConsent.{Root,Heading,Text,Actions,Accept,Reject,Accepted,Rejected,Link}`, no result text unless `.Accepted` and `.Rejected` are written. Page tools: `PageTools.{Root,Updated(dateTime),CopyLink,Print,Top}`. `PageFrame.{Root,Main,Body,Sidebar}`: `Body` is an extra part because `Sidebar` and `Main` need a shared grid parent. `kvirnby.ts`, `locale.ts` and the data types are deleted; `fixtures` is images only. Changeset for the theme added.
- **D10 English, no text in patterns, few tests** (maintainer, 2026-10-10; amends D4 and D9). (1) All example text in stories and Docs is English; the fictional municipality is "Kvirnby municipality". Swedish appears only where a story demonstrates `lang` switching. (2) A pattern holds no text of its own: visible text is a child, a landmark or control name is a `label` (or `aria-label`) prop forwarded to the shipped part, and the only i18n strings are those the shipped parts already own (alert close, copy and read-aloud feedback). The namespaces `siteHeader`, `languageLinks`, `siteSearch`, `siteFooter`, `pageTools`, `consent`, `sectionNavigation`, `serviceLink`, `contactCard` and `relatedLinks` are removed; `@kvirn-ui/i18n` does not change for this plan. (3) Patterns compose components that are already tested: a test exists only for behaviour the pattern itself adds (Meny and topic state, Escape, focus after close, outside press, the alert and consent focus moves). Axe in the stories runs in four themes; `.a11y.md` rows for composed behaviour name the shipped component's test.

Names are `label` props (`MainMenu.Root`, `LanguageLinks.Root`, `SiteHeader.Utility`, `SectionNav.Root`, `BreadcrumbTrail.Root`). ## Risks & open questions

- Page stories may hit axe rules a component story never does (landmark uniqueness, heading order). They are fixed in the composition, never by a disabled rule.
- Retitling changes every story ID: bookmarks and the `path=` links break once; no redirect exists in Storybook.
- The patterns list is long. Slices ship alone; T2 and T4 are the proof, the rest is a backlog ranked by coverage.
