## Goal

An adopter opens "Show code" on any story and sees code they can paste: `CheckboxGroup.Root`, `CheckboxGroup.Legend`, `Field.Root`, the hooks, with real props. Today many stories show `<Contact locale="sv" onValueChange={() => {}} />` instead: a story-only wrapper that says nothing about the component.

## Non-goals

- No change to a component, its tests or its contract. Story names, ids and `play` functions stay (e2e specs and the `*.stories` test project select stories by id), so only `render`, `parameters` and fixtures change.
- No new stories, and no removal of a story unless it repeats another (then decide in this plan first).
- The Foundation MDX pages and Colors/Typography stories (they document tokens, and have no Show code for a component).
- The `*.a11y.md` contracts.

## Background

### The rule

**A story's "Show code" is the code an adopter writes.** It shows:

1. the real public API: `X.Root`, `X.Trigger`, `X.Label`, `Field.Root`, `useX()`, with real props and real handlers (`onValueChange={setValue}`, not `() => {}`);
2. no story-only wrappers: no local component such as `Contact`, `Duration`, `RentField`, `MunicipalityListbox`, no `*Example`, `*States` or `*Page` component, no `locale` prop on a wrapper;
3. no story-only markup in the part an adopter copies: `kv-story-*` layout wrappers, `style={popupStyle}` and test counters (`WithClickCount`) belong in a decorator or in a `play`-only helper, not in `render`;
4. no hand-written code string (`parameters.docs.source.code`). It drifts.

How a story gets there, in order of preference:

- **Inline `args` / JSX in `render`.** Storybook shows it as written. `meta.args` and `meta.argTypes` carry the options. Localised text comes from a text table (`choiceTextsFor(locale)`) read in a small `render` body, and the locale comes from the `withFormLocale` decorator and `globals`, never from a prop on a wrapper.
- **A fixture function with `showSource`**, only when the example is too long for the stories file (a table, a form with ten fields). The function must itself be the example: the real compound parts visible, the localisation plumbing at the top, and no call to another local component that holds the real markup (`CasesView`, `BirthDate`, `ResultNotification` all hide the API). Name the function after the example.
- **State matrices (RTL, ForcedColors) and the layout-only pages** (`AllExamples`) may render a fixture, since they exist for axe and e2e. They still use `showSource` on a function that shows the real parts, or they render the same inline JSX as the story they mirror.

- **Package docs and docs site:** `packages/react/src/**/*.md` snippets use only real components and props. They match today's API, but nothing keeps them in step (check once, low priority). Nothing in `docs/architecture.md` is wrong: `Disclosure` is a pattern illustration.
- **Gap in the skill:** `storybook-docs` allows a fixture with `showSource` but does not say that the shown function must contain the compound parts. Update the skill in the same PR.

### Process per component

1. Read the component's `.tsx` and the existing story file. Keep story names, ids and `play` functions.
2. Move `args` into `meta.args` and `meta.argTypes`; compose the parts in `meta.render` or in each story's `render`.
3. If a story needs a large fixture, write one exported function that is the example, and set `parameters: showSource('<name>/<name>.fixture.tsx', 'FunctionName')`.
4. Delete the wrapper component when nothing uses it. Fixtures only the e2e or tests use stay in the fixture file, not the stories file.
5. Open the story in Storybook, read "Show code", and check that an adopter could paste it.

## Decisions

- **Inline first, fixture second.** Inline `args` and JSX keep Show code honest with no extra mechanism. `showSource` stays for the few examples that are too long, as the skill says today. Needs the maintainer's approval because it tightens a rule in the owning skill.
- **Locale is a decorator and a text lookup, not a prop on a wrapper.** `withFormLocale` and `globals` already exist. Stories read their strings with `choiceTextsFor(locale)` in the `render` body. The text lookup is plumbing at the top, the parts are what a reader sees.
- **State matrices keep a function, with `showSource`.** An RTL or ForcedColors story exists for axe and e2e, so it may share one function, as long as the function's body is the real parts.
- **Stateful and long stories use `showSource` fixtures, with `locale` as a prop of the fixture** (as `text-input` does): the fixture function is the example, and the text lookup sits at the top. Inline stories read the locale from `globals` and the `withFormLocale` decorator. (Implementation decision.)
- **Listbox, Combobox and Autocomplete all use `showSource` fixtures.** Storybook's source printer can't show function props or function children: `Combobox.List` and `Listbox.List` with a render function child, `itemToString` and inline handlers print as `{function noRefCheck() {}}`. The skill now says so. (Implementation decision.)
- **The logging `onValueChange` is removed from `meta.args` on the stories that are shown inline** (it printed as `() => {}`), so the Actions panel no longer logs their changes. Stories shown by a fixture may keep `logChange`, as DateInput's `Default` does. (Implementation decision.)
- **Announcer has no `meta.component`.** `Announcer` isn't an exported component, the `useAnnouncer` hook is documented through the guide. (Implementation decision.)
- **Radio group names are `duration-${id}`** (`useId`), so radios on one Docs page don't act as one group. (Implementation decision.)
- **Popover's popup style comes from a decorator `<style>`**, not an inline `style` in the shown code. (Implementation decision.)
- **DateInput and Form:** `ControlledDate`, `PlainFormDate`, `KeyboardDate` and `PermitForm` write `Fieldset.Root`, `DateInput.Root` and `Fieldset.HelpText` themselves, with `useDateInput().order` for the help text's example, instead of calling `<BirthDate />`. `BirthDate` stays as the fixture of `Default` and the locale and error variants, since its function body is the real parts. `DateStates` moved to the fixture file and is shown by RTL and ForcedColors. Plan 0040's auto-advance and `NoAutoAdvance` are unchanged. The Form variants (Finnish, Compact, RTL, ForcedColors, Keyboard) share `PermitForm`'s `showSource`. Field, Label and ErrorMessage show `FieldStates` from `form/form.fixture.tsx`. (Implementation decision.)
- **A guard against regression (proposed, needs approval as it is a new check):** a test in `tooling/` (or an addition to `docs-source.ts`) that fails when a story's `render` returns a JSX tag that is neither imported from `@kvirn-ui/react` nor an intrinsic element, unless the story sets `showSource`. A scan like that found these 248 stories. **Not built:** it still needs the maintainer's approval.

## Risks & open questions

- Some stories pass `locale` to a wrapper for the e2e or `play` (`expect(canvas.getByText(...))`). Check each `play` against the new markup before and after: same ids, same text.
- Inlining makes the stories files long (Listbox has 37 stories). Split a story file's fixtures into the `*.fixture.tsx` with `showSource`, not back into wrappers.
- `meta.component` of `Announcer` and `Icon` drives the autodocs controls and API table; changing it changes the Docs page. Check the page afterwards.
- Question for the maintainer: is a localised text lookup in a story's `render` acceptable in Show code (`text.contactLegend`), or should Default use literal Swedish strings, as the skill's skeleton does for Default?
