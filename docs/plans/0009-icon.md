# Plan 0009: Icon

- **Status:** In progress
- **Owner:** Maintainer / component-engineer
- **Created:** 2026-10-01 · **Target:** M1
- **Related:** ADR-0024 (Icon API, Proposed), ADR-0005 (`Register`), ADR-0007 (layering), ADR-0015 (render), ADR-0016 (Button), ADR-0013 (theme delivery), DESIGN.md Iconography. New: ADR-0025 (icon libraries as devDependencies)

## Goal

Adopters register their icons once in `KvirnProvider` and write `<Icon name="arrow-forward" size="sm" />` everywhere, with names checked by TypeScript (ADR-0024). An icon can be their own SVG, an imported `.svg` file, or an icon from Lucide, Heroicons or Phosphor, and they can mix them. Size, stroke width, colour, fill and stroke work the same way whatever the source. Icons inside a Button line up and take the button's colour without extra CSS. An icon-only button gets a square target and a warning in development if it has no accessible name.

## Non-goals

- A runtime dependency on any icon library (hard rule 6). The built-in set is original drawings (ADR-0024, decision 9).
- Icon fonts (Font Awesome webfont, Material Symbols). They aren't SVG, and Material Symbols loads from Google's servers (hard rule 7).
- Iconify's online mode. `@iconify/react` fetches icons from `api.iconify.design` by default, which is a third-party call. Its offline bundles work like any other component and aren't tested.
- `startIcon` and `endIcon` props on Button. Icons are children, so DOM order gives start and end, and RTL works without extra code.
- The visible tooltip DESIGN.md requires for icon-only buttons. It comes with Tooltip (M2).

## Background

### How the libraries build their `<svg>`

Source read from the published packages on 2026-10-01: lucide-react 1.49.0, @heroicons/react 2.2.0, @phosphor-icons/react 2.1.10, @tabler/icons-react 3.48.0 and react-icons 5.7.0. Weekly npm downloads: lucide-react 130M, react-icons 10M, @mui/icons-material 8.8M, @phosphor-icons/react 5.9M, @heroicons/react 4.8M, @tabler/icons-react 3.8M and @fortawesome/react-fontawesome 2.5M.

All five forward `ref`, spread unknown props onto the root `<svg>`, and default to `currentColor`. They differ in prop names and in which props win:

| Library      | Model                 | `width`/`height` from Icon                                     | `strokeWidth`                                       | `color`                            | `fill` / `stroke`                                 | Default accessibility                                    |
| ------------ | --------------------- | -------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------- | ------------------------------------------------- | -------------------------------------------------------- |
| Lucide       | stroke, 24 grid, 2    | ✓ wins over its own `size`                                     | ✓ its own prop, same name                           | ✓ its prop, sets `stroke`          | ✓                                                 | `aria-hidden` unless an `aria-*`, `role` or `title` prop |
| Heroicons    | stroke 1.5 / fill     | ✓ (no size prop)                                               | ✓ overrides 1.5                                     | ✓ `color` attribute                | ✓                                                 | always `aria-hidden="true"`, plus `data-slot="icon"`     |
| Phosphor     | fill, 256 grid        | ✓ wins over its `size`                                         | n/a: weight is its `weight` prop (`thin` to `bold`) | ✓ its prop, sets `fill`            | `fill` ✓, `stroke` n/a                            | none                                                     |
| Tabler       | stroke, 24 grid, 2    | ✓                                                              | ✓                                                   | ✓ its prop                         | ✗ **its `stroke` prop is the width.** Use `color` | none                                                     |
| react-icons  | mixed (per set)       | ✗ its `size` (default `1em`) is applied last: size the element | mostly n/a                                          | ✓                                  | ✓                                                 | none                                                     |
| Own SVG/SVGR | whatever the file has | ✓                                                              | ✓ if the shapes don't set their own                 | ✓ if the shapes use `currentColor` | ✓ if the shapes don't set their own               | none                                                     |

Conclusions:

1. **Attributes on the root `<svg>` are the common ground.** `width`, `height`, `stroke-width`, `fill`, `stroke` and `color` reach every library's root, and the shapes inherit them. The `color` attribute sets `currentColor`, which every library uses, so it's the one colour channel that works everywhere.
2. **Presentation attributes, not inline `style`.** They work under a strict CSP. `style=""` in server-rendered HTML is blocked without `'unsafe-inline'`, and React doesn't repair it on hydration. Public-sector sites run strict CSPs (ADR-0006 already designs for it). They also sit below all CSS, so a consumer's CSS can still override them.
3. **Checked in a browser** (Playwright, Chromium and Firefox): `var(--token)` works in `color`, `fill` and `stroke-width` attributes, and `width="1.25em"` sizes against the font size. So `color="var(--kv-color-danger)"` works. WebKit couldn't launch on the dev machine (missing system libraries). The e2e WebKit project must cover this before `alpha`.
4. Phosphor is the third tested library. It's the most-downloaded general-purpose set after Lucide (react-icons and MUI are an aggregator and a framework set), and it's fill-based, so the tests cover both icon models.

### Prior art

- Radix `AccessibleIcon`: wraps a child icon, hides it and adds a visually hidden label.
- React Spectrum `Icon`: clones the child SVG, `aria-hidden` unless it gets `aria-label`, then `role="img"`.
- Chakra `Icon`: `as={LibraryIcon}`, or children for a custom SVG.
- Headless UI / Catalyst: Heroicons' `data-slot="icon"` lets Button style the icons it contains.
- react-icons: `width="1em" height="1em"` attributes, so icons scale with text.
- Designsystemet (NO), Aksel: decorative by default, `title` for meaningful icons.

### WCAG

1.1.1 (text alternative or hidden), 1.3.1, 1.4.1 (status not by icon colour alone), 1.4.4 and 1.4.10 (`em` sizes scale with text and reflow), 1.4.11 (a meaningful icon needs 3:1), 2.5.3 (an icon-only button's name matches its tooltip), 2.5.8 (icon-only target), 4.1.2 (an icon-only button's name).

### API sketch

The registry is the main API (ADR-0024). `render` and children stay for one-off icons.

```tsx
// app/icons.ts: a 'use client' module, next to the provider setup (kvirn-provider.md)
'use client'
import { ArrowRight, ChevronDown, Plus, TriangleAlert, X } from 'lucide-react'
import { TrashIcon } from '@heroicons/react/24/outline'
import MunicipalityLogo from './logo.svg?react'
import { defineIcons } from '@kvirn-ui/react'

export const icons = defineIcons({
  'arrow-forward': { component: ArrowRight, mirrorInRtl: true },
  'chevron-down': ChevronDown,
  add: Plus,
  close: X,
  delete: TrashIcon, // libraries mix
  warning: TriangleAlert,
  logo: MunicipalityLogo,
})

declare module '@kvirn-ui/react' {
  interface Register {
    icons: typeof icons
  }
}

// app/providers.tsx
<KvirnProvider icons={icons} iconDefaults={{ strokeWidth: 1.5 }}>…</KvirnProvider>

// Anywhere, server components included: name is a plain string
<Icon name="arrow-forward" />
<Icon name="delete" size="lg" color="var(--kv-color-danger)" />
<Icon name="warning" label={messages.warning} />        // meaningful: label from your translations (ADR-0007)
<Icon name="logo" label={messages.logo} size={48} />
<Icon name="arow-forward" />                             // type error, and a dev warning at runtime

// With Button
<Button><Icon name="add" />Lägg till</Button>
<Button className="kv-button--icon-only" aria-label={messages.close}>
  <Icon name="close" />
</Button>

// One-offs, without registering
<Icon render={<SomeRareIcon />} />
<Icon viewBox="0 0 24 24" fill="none" stroke="currentColor">
  <path d="M5 12h14M12 5v14" />
</Icon>

// Hook: props, plus the registered component for a name
const icon = useIcon({ name: 'close', size: 'md' })
const CloseIcon = icon.component
<CloseIcon {...icon.iconProps} />
```

Registry:

- `defineIcons(entries)` returns its argument, typed and frozen, like `defineMessages` in `@kvirn-ui/i18n`. An entry is an icon component, or `{ component, mirrorInRtl }`.
- An icon component is any component that forwards its ref and spreads SVG props onto one `<svg>`: Lucide, Heroicons, Phosphor, Tabler, SVGR output, or your own.
- `Register['icons']` types `name` (`IconName`). Without a registration, `IconName` is `string`, like Link falls back to `<a>` (ADR-0005).
- A nested `KvirnProvider` merges its `icons` over its parent's by name, and `iconDefaults` field by field.
- Precedence, lowest first: the library's own defaults, `iconDefaults`, the entry's `mirrorInRtl`, then the instance's props.
- `name`, `render` and children are exclusive. The props type is a union, so passing two is a type error.
- An unknown name renders an empty `<svg aria-hidden="true">` at the right size, so the layout doesn't jump, and warns once in development.
- Register the icons the app uses. Every registered icon is in the bundle that holds the provider, whether a page uses it or not. Rare icons use `render`.

Props (also `UseIconOptions`):

| Prop          | Type                                      | Renders                                       | Default                                        |
| ------------- | ----------------------------------------- | --------------------------------------------- | ---------------------------------------------- |
| `name`        | `IconName`                                | the registered component                      | –                                              |
| `size`        | `IconSize` (below)                        | `width`, `height`, and `data-size` for a step | `iconDefaults.size`, else `'md'`               |
| `strokeWidth` | `number \| string`                        | `stroke-width`                                | `iconDefaults.strokeWidth`, else the library's |
| `color`       | `string`                                  | `color`, which sets `currentColor`            | inherited text colour                          |
| `fill`        | `string`                                  | `fill`                                        | the library's                                  |
| `stroke`      | `string`                                  | `stroke`                                      | the library's                                  |
| `label`       | `string`                                  | `role="img"` and `aria-label`                 | none: decorative                               |
| `mirrorInRtl` | `boolean`                                 | `data-mirror-in-rtl`                          | the entry's, else `false`                      |
| `render`      | `RenderProp<IconElementProps, IconState>` | the element                                   | `<svg>`                                        |

- `IconSize` is ``'sm' | 'md' | 'lg' | number | `${number}em` | `${number}rem` | `${number}px` ``: a step, pixels as a number, or a typed length.
- The steps are `sm` 1em, `md` 1.25em and `lg` 1.5em: 16, 20 and 24px next to 16px text (DESIGN.md), and they grow with the text (1.4.4). `md` matches the Button's 1.25 line height, so an icon doesn't make a button taller.
- Every value goes on the root `<svg>` as an attribute (Background, conclusion 2). `className: 'kv-icon'` joins the consumer's and the library's own class names.
- Set size and colour on `Icon`, not on the library component: Icon's attributes win over Lucide's and Phosphor's `size` (but not react-icons', table above).
- Exports: `Icon`, `useIcon`, `defineIcons`. Types: `IconProps`, `IconState`, `IconElementProps`, `IconSize`, `IconName`, `IconComponent`, `IconRegistry`, `IconRegistryEntry`, `IconDefaults`, `UseIconOptions`, `UseIconResult`, `IconPartProps`. `KvirnProviderProps` gains `icons` and `iconDefaults`.
- No core machine: Icon has no state.

### Accessibility contract (draft)

| Case                 | Root `<svg>`                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| No `label` (default) | `aria-hidden="true"`, no role                                                                     |
| `label`              | `role="img"`, `aria-label={label}`, no `aria-hidden`, even on Heroicons, which sets it by default |

- Keyboard: none. Icon is never focusable and adds no `tabindex`.
- Focus: none.
- Announcements: none. A label is read as an image name.
- Icon-only Button: the name goes on the Button (`aria-label` or `aria-labelledby` from your translations) and the icon stays decorative. In development, Button warns once if it has no name: no `aria-label`, `aria-labelledby` or `title`, and no content outside `aria-hidden` (4.1.2). New row in `button.a11y.md`.
- Forced colours: `currentColor` follows the system colours. The theme turns an explicit `fill`, `stroke` or `color` on `.kv-icon` into `currentColor` in forced-colours mode, so a hard-coded colour can't disappear.
- RTL: `mirrorInRtl` flips arrows and chevrons, never check marks, logos or text-like icons. The theme does it with `:dir(rtl)`. Without the theme, the consumer flips `[data-mirror-in-rtl]` themselves.
- Consumer responsibilities: a label for a meaningful icon, text next to a status icon (1.4.1), 3:1 contrast for a meaningful icon (1.4.11), and icon-only buttons only for universal actions (close, search, menu).
- WCAG SCs: 1.1.1, 1.3.1, 1.4.1, 1.4.4, 1.4.10, 1.4.11, 2.5.3, 2.5.8, 4.1.2.

### i18n strings

None. Icon renders no text. Labels come from the consumer's translations. Button's dev warning is developer-facing English, like the existing warnings.

### Theming surface

`kv-icon` class, `data-size="sm" | "md" | "lg"`, `data-mirror-in-rtl`. The theme (spec by ux-designer) adds:

- `.kv-icon`: `flex-shrink: 0`, alignment with text outside flex containers. **It never sets size, stroke, fill or colour**: CSS beats attributes, so an explicit prop would lose.
- `.kv-button--icon-only`: a square target, at least `--kv-button-min-block-size` wide (2.5.8). A class, not `:has(> .kv-icon:only-child)`: `:only-child` ignores text nodes, so it would match a button with an icon and a label.
- `[data-mirror-in-rtl]:dir(rtl)`: `scale: -1 1`.
- Forced colours, as above.

## Risks & open questions

1. **Third library.** Decided: Phosphor (ADR-0025).
2. **Default stroke width.** Decided with the registry: `iconDefaults.strokeWidth` on `KvirnProvider`, unset out of the box, and the docs show 1.5 (DESIGN.md). The theme can't set it, because CSS would beat the prop.
3. **A built-in semantic set.** Decided: 24 icons, the base layer of the registry (ADR-0024, decisions 9 and 10; design spec §4.1).
4. **Component types.** Settled: `IconComponentProps` declares optional fields without `| undefined`, so Phosphor's strict types fit. Type tests for all three libraries.
5. **`aria-hidden` removal on Heroicons.** Settled without a `mergeProps` change: `iconProps` keeps the `aria-hidden` key as `undefined` when labelled, and both `mergeProps` and Heroicons' `Object.assign` pass it through. Tested for all three libraries.
6. **WebKit and `var()` in presentation attributes** isn't verified yet. If it fails, `color` with a token falls back to a class in the docs.
7. **Element props vs Icon props.** `<Icon size="lg" render={<Trash2 size={30} />}>`: Icon's `width` wins over Lucide's `size`, but an element's own `width` would win over Icon's (ADR-0015). The docs say to size on Icon.

8. **From the design spec (§9), for the maintainer:** keep the 1px stroke at `sm` (16px), or allow a per-size stroke later? Hold slot 25 for `sort` or `help`? The info status colour waits for the Notification spec. Navigation items have no `gap` for an icon. The capital-height alignment assumes Inter.
9. **`eye-off` has no pupil.** The spec's 2-unit clearance around the slash covers the whole pupil (r 3), so it's left out. Design review: keep it, or relax the gap for the pupil.
10. **Bundle:** the 24 built-ins are about 1.5 KB of path data (the module is about 2 KB gzipped), in every bundle that uses Icon.
