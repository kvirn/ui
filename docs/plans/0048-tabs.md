## Goal

A keyboard user passes the tabs with one Tab press, moves between them with the arrow keys and reaches the selected panel with the next Tab. A screen-reader user hears "tab, 2 of 3, selected".

## Non-goals

- Closable, reorderable or scrolling tab lists (a scrolling list breaks 1.4.10).
- Lazy or unmounted panels, URL or hash sync.
- Tabs that navigate to other pages: that is `Navigation` with `kv-navigation--horizontal`, and `tabs.md` says so.
- A shared roving registry with Toolbar (see Decisions).

## Background

WAI-ARIA APG Tabs. No Tabs code, i18n or story exists; the roadmap row (`docs/roadmap.md:49`) says `planned`, and `architecture.md:19` says `getRovingTarget` is for Toolbar first and "Tabs and Menu will reuse". The shared core primitive is `getRovingTarget({key, currentIndex, count, orientation, direction, loop})` in `packages/core/src/roving-focus/get-roving-target.ts`: it owns Home/End and the orientation's two arrows, flips Left and Right in `rtl` for horizontal only, returns `null` for other keys, and ignores disabled items, Enter, Space and modifiers. Toolbar's item registry (`use-toolbar.ts`) is module-private, and its Tab stop is the last focused item, where Tabs needs the selected tab.

## Design

### API sketch

```tsx
<Tabs.Root defaultValue="uppgifter" onValueChange={(value, { reason, event }) => …}>
  <Tabs.List aria-label="Ärendet">
    <Tabs.Tab value="uppgifter">Uppgifter</Tabs.Tab>
    <Tabs.Tab value="historik" disabled>Historik</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="uppgifter">…</Tabs.Panel>
  <Tabs.Panel value="historik">…</Tabs.Panel>
</Tabs.Root>
```

- Parts: Root `<div class="kv-tabs" data-orientation>`, List `<div role="tablist" class="kv-tabs-list">` (`aria-orientation="vertical"` only when vertical), Tab `<button type="button" role="tab" class="kv-tabs-tab">`, Panel `<div role="tabpanel" class="kv-tabs-panel">`. Flat exports `TabsRoot`, `TabsList`, `TabsTab`, `TabsPanel`; `Tabs` is a frozen namespace object like `Navigation`.
- `useTabs({ value, defaultValue, onValueChange, activationMode = 'automatic', orientation = 'horizontal' })` returns `{ value, rootProps, listProps, getTabProps(value, { disabled, onClick }), getPanelProps(value) }`. The hook gates `onClick` for disabled tabs, as `useButton` does. One of `value` or `defaultValue` is required by the types: there is no "first tab" fallback, because registration happens after the server render.
- Types: `UseTabsOptions`, `UseTabsResult`, `Tabs*Props` and the part prop types, `TabsActivationMode`, `TabsChangeReason = 'press' | 'arrow-key' | 'home-end-key'`, `TabsChangeDetails { reason, event }`, render states `TabsState`, `TabsTabState { isSelected, isDisabled }` and `TabsPanelState { isSelected }`.
- `orientation` and `activationMode` are props (they change the keys), unlike Navigation's class.

### Behaviour

- **Tab:** `aria-selected`, `aria-controls`, `aria-disabled="true"` (never native `disabled`), `data-selected`, `data-disabled`. **Panel:** `aria-labelledby`, `hidden` when not selected, `tabindex="0"`, `data-selected`. A `tabIndex` the consumer passes wins (`-1` for a panel that starts with a focusable element). No `data-focus-visible`; the theme uses `:focus-visible`.
- **Ids:** `useId()` on the Root plus the escaped value (each character outside `[A-Za-z0-9-]` becomes `_<hex code point>_`, `_` included, so ids are unique and an IDREF has no spaces). Private `tabs-ids.ts` with its own unit test. Not an index: a panel needs its tab's id on the first server render, before anything registers, and an index breaks when tabs reorder.
- **Panels are always rendered**, with `hidden`, so every `aria-controls` and `aria-labelledby` resolves and axe `aria-valid-attr-value` passes. Not `inert`, not unmounted.
- **Registry:** a ref `Map<value, element>` filled by cached per-value ref callbacks, sorted with `compareDocumentPosition` at key time. No state, no observer, no core change.
- **Tab stop:** the focused tab while focus is inside the list, else the selected tab (a `focusedValue` state set on tab focus and cleared when focus leaves the list), so Tab from an unselected focused tab leaves the list. The server render is already right: the selected tab `0`, the rest `-1`.
- **Keys** on the list's `onKeyDown` through `getRovingTarget` (`loop: true`, disabled tabs included, direction from `getComputedStyle(list).direction`). Ignored: `defaultPrevented`, Control, Alt, Meta, Shift, and a target that is not a registered tab.
- **Automatic:** an arrow, Home or End focuses and selects, but never selects a disabled tab (focus only). **Manual:** focus only; Enter and Space select through the native click (`press`). A click selects; a disabled tab ignores it.

### Accessibility contract (draft, `tabs.a11y.md`)

Roving tabindex, one Tab stop. Selection follows focus (except onto a disabled tab). Arrows wrap. No shortcuts. Deviations from APG, both in the Decisions: the panel's default `tabindex="0"`, and focusable disabled tabs. Consumer rules: name the list when there is more than one, keep labels short, use manual activation only for slow panels.

| Key                    | Context           | Action                                                              | Test (`tabs.e2e.ts ›`)                                         |
| ---------------------- | ----------------- | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| Tab                    | before the list   | Moves to the selected tab                                           | `Tab enters at the selected tab`                               |
| Tab                    | on a tab          | Leaves the list for the selected panel, also from an unselected tab | `Tab leaves the tab list for the panel`                        |

- Roles and ARIA: `tablist`, `tab`, `tabpanel`; `aria-selected`, `aria-controls`, `aria-labelledby`, `aria-orientation` only when vertical, `aria-disabled`.
- Announcements: none beyond the roles ("tab, 2 of 3, selected"). Selection changes are not live.
- WCAG SCs: 1.3.1, 1.4.1, 1.4.10, 1.4.11, 2.1.1, 2.4.3, 2.4.7, 2.5.8, 4.1.2.

## Decisions

- **Tabs builds its own small registry.** Toolbar took three review rounds, and touching it breaks rule 10. Extract a shared registry when Menu lands (the third user, the shape known). Toolbar's registry also carries a `MutationObserver` on native `disabled` and focus bookkeeping; Tabs needs neither, because disabled tabs are `aria-disabled`.
- **Panels get `tabindex="0"` by default** (needs the maintainer's approval: an APG deviation; approved with this plan). APG says Tab goes to the tabpanel unless the first element with meaningful content inside it is focusable, and a panel without focusable content should set `tabindex="0"`. A headless panel cannot know its first content without scanning the DOM. Default `0` costs one redundant Tab stop; no default would strand keyboard users on a scrolling text panel (2.1.1). The consumer passes `tabIndex={-1}` when the panel starts with a focusable element. The APG sentences go in `key-tables.md` and `apg-patterns.md`.
- **A disabled tab stays focusable** (keyboard rule 5) and automatic activation never selects it, so focus and selection can differ (APG's keyboard practice keeps disabled controls focusable; only "automatic activation never selects it" is our choice; approved with this plan). The contract says so.
- **`orientation` and `activationMode` are props,** because they change the keys. `activationMode` defaults to `automatic` (APG: when panels show instantly).
- **Ids from `useId()` and the escaped value, panels always rendered with `hidden`.** An index would break on reorder and on the first server render.
- **Typeahead is not implemented** (APG Tabs has none).

## Risks & open questions

- Focus and selection can differ on a disabled tab in automatic mode (stated in the contract).
- One redundant Tab stop on panels whose first content is focusable.
- Hidden panels still mount; `isSelected` in the render state lets a consumer render lazy children.
- A tab that unmounts while focused leaves no `tabindex="0"` until focus moves (closable tabs are a non-goal).
- Q-T1 in the spec: how a wrapped tab list marks the selected row.

## Testing strategy

Rule 13: no CSS values. Key rules are proved in e2e only, once.

- `tabs.test.tsx` (browser, axe in automatic, manual, vertical, disabled and long-label states): roles and names in sv and en; one `aria-selected`; ids resolve for `"Bygga och bo"` and for a value with `:` and `'`; inactive panels `hidden` but in the DOM; `aria-orientation` only when vertical; roving `tabindex` including the focused tab; controlled, uncontrolled and the reasons; a controlled owner that refuses; `getTabProps` and `getPanelProps` on own elements; `render` and refs; `renderToString` has the ids, `hidden` and tabindex and no `window`; the four warnings; a nested `Tabs` keeps its own arrows.
