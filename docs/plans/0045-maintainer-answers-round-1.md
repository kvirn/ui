### Work package 2 notes (done, unverified until the gates run)

- **Direction (decision taken while implementing).** `dir="auto"` was never in the code: the editor's blocks and the Textarea carried no `dir`, and only the docs, the contract and a Storybook `dir` control said otherwise. Every other input inherits the page's direction, and `KvirnProvider` renders no element, so its `dir` reaches the page through `useLocale().localeProps`. I followed that convention instead of adding `dir={useLocale().dir}` to the two elements: the RTL stories and tests stay valid and a page's own `dir` is never overridden by the `ltr` default of "no provider". `dir` is removed from `TextareaProps` (`Omit`), the Storybook control is gone, and the docs say the direction is the page's. If the maintainer wants the attribute written from the provider, it is one line in `useTextarea` and in `RichTextEditorContent`, plus a `dir` on the story decorator (`withFormLocale`).
- **Keyboard (verified against `kvirn-keymap.ts`).** Tab nests a list item when it can, moves to the next cell in a table when it can, and otherwise returns without acting, so the browser moves focus. That matches the maintainer's truth. The code also arms a one-shot exit on the first Escape (see below).
- **Removed:** `RichTextEditor.KeyboardHint`, `RichTextEditorKeyboardHint` and its props type, the Root's `keyboardHint` prop, the `registerKeyboardHint` context entry, the `aria-describedby` wiring of the hint, the three `richText.keyboardHint*` messages (type and six locales), the `kv-rich-text-keyboard-hint` class mention in `theme.css`, the unit tests of the instruction, the three e2e tests of "Escape then ...", the e2e test of the instruction's text, and every doc line that told users to press Escape, then Tab (contract, package guide, `keyboard` skill rule 7 and its editor table, Storybook stories and fixtures).
- **Kept, and open:** `KvirnKeymap` still consumes the first Escape in the text (so a Dialog around the editor stays open and the text is kept), and that first Escape still arms a one-shot exit that the next Tab or Shift+Tab takes, even in a list item. The Dialog behaviour is documented as a row in the contract. The arming is now unreachable by any documented path and has unit tests in `kvirn-keymap.test.tsx` (`Escape, then Tab or Shift+Tab`). It exists for the removed instruction; the Dialog consumption is a by-product of it. Not removed because it is behaviour code: the maintainer decides whether to drop the arming and keep only the consumed first Escape.
- WCAG 2.1.2: with no instruction, the unmodified Tab and Shift+Tab must always get out. They do: nesting, outdenting and cell moves are finite, and the first and last list item and cell leave. Recorded in the contract.

### Work package 3 notes (Alert close button; done, unverified until the gates run)

- **API as built.** `Alert.Close` (also `AlertClose`): a native `<button type="button" class="kv-alert-close">` with `<Icon name="close" />` (decorative). Props: every `<button>` attribute except `type` and `aria-disabled`, `onClick` (repo naming; Button and Toggle use `onClick`, not `onPress`), `disabled` (native, gates `onClick` through `useButton`, also for a `render` element's `onClick` via `takeRenderElementProps`), `messages` (`{ close }`), `children` (visible text replaces the icon and the `aria-label`), `render` (must stay a `<button>`: dev warning `alert-close-not-a-button:<tag>`), `ref`. `useAlert` gets `closeProps` (`className`, `type`, resolved `aria-label`), so the hook user can build their own; no separate hook, because the part reuses `useButton` and `useAlert` already holds the message resolution. Exported types: `AlertCloseProps`, `AlertCloseState`, `AlertClosePartProps`.
- **Name resolution.** `alert.close` is one new key in all six locales: sv "Stäng meddelandet", fi "Sulje ilmoitus", nb "Lukk meldingen", nn "Lukk meldinga", en "Close message", se "Close message". Order: `messages` on `Alert.Close`, then `messages` on the root, then the provider, then built-in `en`. A longer name than "Stäng" on purpose: it tells several alerts' buttons apart in a button list.
- **Decision for the maintainer: `se`.** `se` keeps the English placeholder, as for most `se` strings; it is marked in the `se.ts` header comment and needs translator review. I did not guess North Sami.
- **Decision for the maintainer: names.** The orchestrator's draft was "Stäng"/"Sulje"/"Lukk". I chose the longer, noun-bearing names above (see Name resolution). Say if you prefer the short ones; it is one string per locale.
- **Decision: placement.** DOM order is the consumer's, and the docs say "last in the root" (the last Tab stop after the Actions). The theme places the button in the last grid column of the first row wherever it is in the DOM, so Tab order differs from the visual position only in that the button is read after the actions. Alternative (first in DOM, right after the Title) was rejected: it puts a button between the heading and the text for screen reader users.
- **Decision: guidance not enforcement.** The design spec said errors and warnings must not be dismissible. The decision is now "optional", with guidance in the contract, `alert.md` and the design spec (§7.5 rewritten, D12 superseded). Nothing in code stops `Alert.Danger` from having a close button. No dev warning. Say if you want one.
- **Focus (2.4.3).** The Alert owns no state and cannot move focus (it does not know the page). The contract, `alert.md` and the `Keyboard` story document and show the consumer moving focus to the heading in the same `onClick`; an e2e test and a component test prove the pattern.
- **Keyboard contract changed.** The Alert is no longer "no focusable parts": focus lines (native) plus rows for Tab/Shift+Tab/Enter/Space on the button. A `Keyboard` story exists (the dismissible example). Enter/Space are the native button's, not ours.
- **Theme.** `kv-alert-close` in the Alert section of `theme.css` only: control-size tokens (44px / 32px compact, never under 24px), centred on the title's first line with a negative block margin, `:focus-visible` ring, hover `surface-raised`, `ButtonText`/`Highlight`/`GrayText` in forced colours, hidden in print, logical properties, no raw colours. The alert's grid gets a last column only when it has a close button (`:has`). The one existing rule `:not(.kv-alert-icon)` became `:not(.kv-alert-icon, .kv-alert-close)`. The close button sits on the four `-subtle` backgrounds with `text` and `focus-ring`, pairs `theme:check` already measures; hover uses `surface-raised`, which is not measured on the subtle backgrounds as an adjacent colour (it is only a hover hint).
- **Docs touched:** `alert.a11y.md`, `alert.md` (new API section and Dismissing), `docs/design/alert.md` (the keyboard section, §7.5, D12 and the open question), `DESIGN.md` (Alerts bullet and the class list), `packages/theme/README.md` (class list).
- **Tests written, not run:** `alert.test.tsx` (new `Alert.Close` describe, a `useAlert` `closeProps` test, a type test, and the "status words end with a colon" test narrowed to the four `…Prefix` keys), `naming.test.tsx` (`Close` in the Alert alias set), `alert.e2e.ts` (Tab, Shift+Tab, Enter, Space, focus indicator, forced colours, 24px target; `keyboard` and `with-close-button` added to the axe and reflow lists). Stories: `Keyboard`, `WithCloseButton`, `AllExamples`, `RTL` and `ForcedColors` now include the dismissible example, and `LongFinnishText` has a close button.

### Work package 4 notes (Typography h1–h6; done, unverified until the gates run)

- **Scale chosen (all serif, the heading family, 1rem, never stepping down below 40rem).** `heading-4`: 600, line height 1.4, 0em. `heading-5`: 500, line height 1.5, 0em. `heading-6`: 500, line height 1.5, 0.03em tracking. Feature settings `normal`. They are the only values that fit the constraints: Plex Serif is loaded at 500 and 600 only and upright only, 700 is unused, an all-caps or shrinking treatment is excluded, and the prose margins (`space-6` above, `space-2` below) were kept as they were. The differences between the three are small by design; the docs say so and keep the advice to stop at `h3`.
- **Decision: positive tracking for `heading-6`.** It was the one axis left (weight 500 and 600 are taken, italics are synthesised, case is excluded). 0.03em is 0.48px per letter at 16px, readable, and under 1.4.12 the 0.12em override replaces it.
- **Decision: Heading component follows.** `HeadingSize` gains `heading-4|5|6`, and levels 4 to 6 default to their own size (they had no class, and looked like prose's old shared style). The bare `kv-heading` base now equals `heading-4`, so a hand-written `kv-heading` class is still a sensible heading. `HeadingState.size` and `UseHeadingResult.size` lose `| undefined`. This is a public type change, so the changeset names `@kvirn-ui/react` as well as the theme. Test updated: `heading.test.tsx` (class of `level={4}`, `useHeading({ level: 5 })`).
- **Prose sizes.** The old shared rule used `--kv-prose-font-size`, so `h4` to `h6` were 14px in `kv-prose--small`, against DESIGN.md's 16px floor. They now keep their roles in every size, like `h1` to `h3`. Consequence, documented in DESIGN.md, `prose.md` and `prose.a11y.md`: in `--large`, `--xl` and `--2xl` they are smaller than the body text, so resident content stops at `h3` (as `h3` already is in `--xl` and `--2xl`).
- **Story.** Type roles table gets the three rows (the play counts rows from the role list). New story `Foundation/Typography › Heading levels`: a prose `<article>` with `h1` to `h6` in turn, in the toolbar locale, inside the page's own `h1`. The sample has its own `h1`, so the page has two `h1`s and no skipped level; `heading-order` is a best-practice rule outside the gate's tags, and no heading is empty. Heading stories: `Sizes` and `Outline` show all six levels, and `size` is now a control.
- **Contrast.** No new pairs: text colour is `--kv-color-heading` as before.
- **No test reads `theme.css`** (rule 13), so no token-list test needed updating.

### Notes on packages 5 and 7 (orchestrator)

- **DateInput.** A typed digit past the box's length (2, 2, 4) is refused in `beforeinput`. It is not the native `maxlength`, which would cut a paste silently (3.3.8), so a paste stays whole and the consumer validates it. The `forms` skill, `date-input.md` and `date-input.a11y.md` say so.
- **Links.** Underline on hover only. The maintainer chose "hover only everywhere, adjust the colours". The light and dark themes meet 3:1 against body text (dark `--kv-primary-400` is `#7784f2`; `theme:check` now measures the pair). The two contrast themes cannot (3:1 against text and 7:1 on the canvas conflict), so they keep the resting underline through `--kv-link-decoration-line`; the maintainer to confirm or waive.
- **accessibility-reviewer round 1 (CHANGES REQUIRED), fixed:** links in grey or red text, in forced colours and in the contrast themes keep the resting underline (1.4.1); `Alert.Close` with `null`/`false` children keeps its name (4.1.2); the editor's Escape-arms-exit is removed (the first Escape is still consumed, Tab never reads it) and its tests replaced; the DateInput contract and e2e describe the digit limit; duplicate Alert component tests cut (rule 13); "3.2.5, Level AAA" named in the Link docs. A second review pass has not been run.
