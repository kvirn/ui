# Plan 0007: Card

- **Status:** Done (alpha. Manual AT pending before beta)
- **Owner:** Maintainer / component-engineer
- **Created:** 2026-10-01 · **Target:** M1
- **Related:** design spec [card.md](../design/card.md)

## Goal

Adopters put any content on a surface with one component: a text block on a surface background in a sidebar, or an image, a heading, text and action buttons. The default theme gives it DESIGN.md's card look, and they change surface, radius and padding with plain attributes.

## Non-goals

- A Title part or automatic labelling.
- A clickable card or stretched link.
- Status panels (danger, success and warning). They need an icon and a heading, so they belong in a future Notification component.
- Shadows. A card is elevation level 2: surface and hairline, no shadow.

## Background

- No APG pattern. Native `<div>` by default, and the consumer picks `<article>`, `<section>` or `<li>` with `render`.
- WCAG: 1.3.1 (the consumer's semantics survive), 1.4.3 and 1.4.11 (text and buttons on every card surface), 1.4.10 (320px reflow), 1.4.12, 2.4.11 and 2.4.13 (focus rings never clipped).
- Prior art: GOV.UK has no card, Designsystemet (NO) `Card` (parts, padding, media), Inclusive Components "Cards" (what not to do with links).

## Design

The visual spec is [docs/design/card.md](../design/card.md) (ux-designer, Draft). It sets `data-surface`, `data-radius`, `data-padding` and `data-dividers`, the padding model, rounded full-bleed media without clipping, the footer button group, and how prose behaves around cards.

Decisions on the spec's open questions (2026-10-01):

1. The dark primary-button hover on `surface-raised` (2.98:1) is fixed by keeping a `primary` edge on hover.
2. Prose can be turned back on inside a card with `data-kv-prose`. Accepted as specified.
3. No card-list attribute in the theme yet. Stories use their own list CSS and `data-kv-not-prose`.
4. `data-surface` uses the token names: `surface-raised` (default), `surface`, `canvas`.
5. Per-part padding allows all four steps (`none`, `sm`, `md`, `lg`): the maintainer asked for varied padding. The docs say why `none` is the usual choice.

### API sketch

```tsx
// Compound
<Card.Root>Plain text block. The root pads itself when it has no parts.</Card.Root>

<Card.Root render={<article />}>
  <Card.Header data-padding="none">
    <img src="/bibliotek.jpg" alt="" />
  </Card.Header>
  <Card.Body>
    <h3>Biblioteket på Storgatan</h3>
    <p>Öppet alla dagar 10–19.</p>
  </Card.Body>
  <Card.Footer data-kv-button-group="">
    <Button data-variant="primary">Boka tid</Button>
    <Link href="/karta">Visa karta</Link>
  </Card.Footer>
</Card.Root>

// Variants are attributes; names and values from the design spec
<Card.Root data-surface="surface" data-radius="md" data-padding="sm" data-dividers="">…</Card.Root>

// Hook, for your own elements
const card = useCard()
<section {...card.rootProps} aria-labelledby={headingId}>
  <div {...card.bodyProps}>…</div>
</section>
```

Exports: `Card` (`Root`, `Header`, `Body`, `Footer`), `CardRoot`, `CardHeader`, `CardBody`, `CardFooter`, `useCard`. Types: `CardRootProps`, `CardHeaderProps`, `CardBodyProps`, `CardFooterProps`, `CardState`, `UseCardResult`, `CardPartProps`.

### Accessibility contract (draft)

| Part   | Element (default) | ARIA                                        | `data-kv`     |
| ------ | ----------------- | ------------------------------------------- | ------------- |
| Root   | `<div>`           | none. The consumer adds it with the element | `card`        |
| Header | `<div>`           | none. Never `<header>` (banner landmark)    | `card-header` |
| Body   | `<div>`           | none                                        | `card-body`   |
| Footer | `<div>`           | none. Never `<footer>` (contentinfo)        | `card-footer` |

- Keyboard: none of its own. Tab order is the children's DOM order. No `tabindex` is added.
- Focus: Card never moves focus and never clips a child's focus ring.
- Announcements: none.
- Consumer responsibilities: the heading level, alt text (empty for a decorative image), `<ul>`/`<li>` for a list of cards, and `aria-labelledby` when rendered as `<section>`.

### i18n strings

None. Card renders no text of its own.

### Theming surface

`data-kv="card" | "card-header" | "card-body" | "card-footer"`, plus the consumer attributes from the design spec (surface, radius, padding). Default: `surface-raised`, 1px `border-subtle`, `lg` radius, 24px padding (DESIGN.md `card`).

## Risks & open questions

- Generic attribute names such as `data-padding` could clash with an adopter's own CSS. The theme scopes them to `[data-kv^='card']`.
- Prose inside a card body, and a card inside prose, must both look right. Prose already skips `[data-kv]` elements, but not necessarily their descendants. Implemented as "nearest of card and `data-kv-prose` wins", for two levels of nested cards.
- **Open: `role="list"` on a list of cards.** The design spec's Example C is `ul[role=list]`, so Safari keeps the list semantics when no markers show. The repository's jsx-a11y `no-redundant-roles` rule rejects `role="list"` on a `<ul>`, and gates aren't weakened, so the stories use a plain `<ul>` (decision 3). The maintainer decides whether the lint configuration should allow it (a separate decision). Until then, check the list in VoiceOver + Safari in the manual AT run.
- The primary hover edge decision was amended during implementation: `primary-hover` on `surface-raised` is documented, not required (2.98:1 in dark). What is enforced is in `contrast-requirements.ts`.
