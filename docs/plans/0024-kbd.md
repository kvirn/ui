# Plan 0024: Kbd

- **Status:** Done (alpha. Manual AT pending before beta. ADR-0053 still to be accepted)
- **Owner:** Maintainer / Claude
- **Created:** 2026-10-03 · **Target:** M1
- **Related:** ADR-0053 (Proposed), ADR-0052, ADR-0039

## Goal

Adopters write a key in running text as `<Kbd>Tab</Kbd>` and get the key as the theme draws it (a keycap), in prose and outside it. Today only a raw `<kbd>` inside `kv-prose` is styled.

## Non-goals

- Key translation or a key-name catalogue. Key names are what's printed on the keyboard, and the consumer picks them.
- Platform detection (`Ctrl` or `Cmd`).
- Shortcut handling. Kbd documents a key and never binds one.
- Replacing the Storybook Keyboard section's own `kbd` styling.

## Design

Look: [docs/design/kbd.md](../design/kbd.md) (revision of the default look, 2026-10-03): a flat key with no depth, one shared rule for `kv-kbd` and prose `kbd`, and the combination group fixed.

```tsx
<p>
  Du kan flytta mellan fälten i formuläret med <Kbd lang="en">Tab</Kbd>.
</p>
<Kbd>
  <Kbd>Ctrl</Kbd>+<Kbd>C</Kbd>
</Kbd>
```

- `Kbd`: one `<kbd class="kv-kbd">`. `render` changes the element. `useKbd()` gives `element` and `rootProps`. No role, ARIA, text or state.
- Nested keys: the outer one stays plain, like prose's `kbd`.

### Accessibility contract (draft)

No keys and no focusable part. Contract: `kbd.a11y.md`. Consumer responsibilities: `lang` on key names in other-language text (3.1.2), the key is never the only instruction (1.3.3), and shortcuts can be turned off or remapped (2.1.4).

### i18n strings

None.

### Theming surface

`theme.css` section 9b: one rule for `kv-kbd` and prose's `kbd` (design: `docs/design/kbd.md`). No new tokens.
