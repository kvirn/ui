# The test-runner guard

What `.claude/hooks/guard-test-runner.mjs` and `test-preflight.mjs` allow, block and wait for.

(`.claude/hooks/guard-test-runner.mjs`, reached from `guard-subagent-checks.sh` by the hook input's `agent_type`; without `agent_type` the test-runner is blocked like any other subagent). It allows `vp test run|related <paths>`, `vp check <paths>`, `vp run e2e <spec>`, `vp run i18n:check` and `vp run theme:check`. It blocks a path-less run, a glob, a path that doesn't exist, a whole package or app, a stories file without `--project`, `--changed`, `-u`, retries, worker counts, `--watch`, `--fix`, `--shard`, `VITEST_MAX_WORKERS`, `E2E_BROWSERS` and `CI`, background runs, more than one test command per Bash call, `vp fmt`, builds, and `vitest`, `playwright` or `tsc` called directly. `test-preflight.mjs` decides when a run may start: it is BUSY while a heavy process (vitest, `vp test|check|lint`, e2e, playwright, tsc) runs anywhere on the machine, or while worktree files changed within the quiet window (20s, or 90s while another Claude session works in the same worktree; tune with `KVIRN_TEST_QUIET_SECONDS`). These are heuristics that read process names and file times: a runner under another name, or an editor's Vitest extension in watch mode, can fool them (the BUSY message names the pid), and the session check reads `/proc/<pid>/cwd`, so it does not see other sessions on macOS.
