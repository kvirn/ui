# Dev warnings

In development, KvirnUI logs a warning when markup or props break something a user depends on: a missing name, a part in the wrong place, an element that cannot do the job. The table lists every one, grouped by what went wrong.

- **Development only.** A warning is `console.warn("[KvirnUI] …")`. It is logged once per code, and never in production: the literal `process.env.NODE_ENV` is replaced by your bundler.
- **For you, not for users.** The text is English, is not in the message catalogs, and is never shown on the page or announced.
- **After mount.** A check reads the DOM or a registration count in an effect, never during render, so it sees what the browser sees.
- **A warning never replaces a rule.** Where the rule must hold, the code is a type error or a throw instead (see "Throws" below).
- **The code is the key.** A part in `<angle brackets>` varies: `listbox-<part>-outside-root` is `listbox-trigger-outside-root`, `listbox-list-outside-root` and so on. Two different values warn separately.

## How to read the table

| Column        | Says                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| Code          | The key the warning is logged under. It is also what makes it fire once               |
| From          | The component, part or hook that logs it. A name links to its Docs page               |
| What is wrong | What the markup or props do, and the WCAG criterion that is affected, if there is one |
| Fix           | What to do instead                                                                    |

## Render gave the wrong element

A part that needs a specific element checks, after it has mounted, what `render` produced. The fix is always the same: render the element the warning names and forward its ref. See [Your own element](?path=/docs/foundation-your-own-element--docs).

| Code                                   | From                                                   | What is wrong                                                                                                                           | Fix                                                                                          |
| -------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `button-not-a-button:<element>`        | [Button](?path=/docs/components-button--docs)          | `render` produced something other than a `<button>`, or didn't forward the ref. Role, keys and `disabled` come from the native element. | Render a `<button>` and forward its ref. For navigation use Link.                            |
| `toggle-not-a-button:<element>`        | [Toggle](?path=/docs/components-toggle--docs)          | Same as Button: `render` did not produce a `<button>`.                                                                                  | Render a `<button>` and forward its ref.                                                     |
| `tabs-tab-not-a-button:<element>`      | [Tabs](?path=/docs/components-tabs--docs)              | `Tabs.Tab` with a `render` that is not a `<button>`. Its keys and its disabled state come from the native element (4.1.2).              | Render a `<button>` and forward its ref.                                                     |
| `disclosure-not-a-button:<element>`    | [Disclosure](?path=/docs/components-disclosure--docs)  | `Disclosure.Trigger` with a `render` that is not a `<button>`. Its keys and its disabled state come from the native element (4.1.2).    | Render a `<button>` and forward its ref.                                                     |
| `alert-close-not-a-button:<element>`   | [Alert](?path=/docs/components-alert--docs)            | `Alert.Close` with a `render` that is not a `<button>` (4.1.2).                                                                         | Render a `<button>` and forward its ref.                                                     |
| `link-not-an-anchor:<element>`         | [Link](?path=/docs/components-link--docs)              | The registered link component or `render` did not produce an `<a href>`.                                                                | Make the registered component render an `<a>` and forward its ref, or fix the `render` prop. |
| `fieldset-not-a-fieldset:<element>`    | [Fieldset](?path=/docs/components-form-fieldset--docs) | `Fieldset.Root` with a `render` that is not a `<fieldset>`. The group name comes from the native `<legend>`.                            | Render a `<fieldset>` and forward its ref.                                                   |
| `toolbar-item-not-focusable:<tag>`     | [Toolbar](?path=/docs/components-toolbar--docs)        | `Toolbar.Item` rendered an element that is not focusable by itself, so keyboard users cannot operate it (2.1.1).                        | Render a button, a link, an input, or an element with an interactive role.                   |
| `toolbar-item-natively-disabled:<tag>` | [Toolbar](?path=/docs/components-toolbar--docs)        | `Toolbar.Item` rendered a natively disabled element. It cannot take focus, so the arrows skip it (2.1.1, 2.4.3).                        | Pass `disabled` to the `Toolbar.Item` instead: it stays focusable with `aria-disabled`.      |

## Throws instead of warns

Where a rule must hold, a development warning is not enough, so the code fails loudly, also in production:

- `masks.oneTimeCode({ pattern })` and the `pattern` of `OneTimeCode.Root` throw a `RangeError` for an invalid pattern.
- A `RichTextEditor` part outside `RichTextEditor.Root` throws, because it cannot work without the editor.

## Accessibility

- **Warnings point at real failures.** Each one names the WCAG 2.2 criterion it protects where there is one: names and roles (4.1.2), labels and instructions (3.3.2), error identification (3.3.1), info and relationships (1.3.1), keyboard (2.1.1) and status messages (4.1.3).
- **A clean console is not conformance.** Warnings catch what code can see. Check the page with a keyboard and a screen reader as well.

## Keeping the table true

A unit test reads this page and the source of every package. It fails when a `warnOnce` code has no row here, or a row has no `warnOnce` call. Add a warning, and add its row in the same change.
