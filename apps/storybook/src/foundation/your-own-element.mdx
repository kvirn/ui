# Your own element

Every part renders exactly one element. Some parts let you choose which one with `as`. For every other part you build the element yourself with the part's hook. `className` and `style` add to the part's own, and `mergeProps` joins your props with a hook's props. This page says once how they behave. The Docs page of each component says which of the two it offers.

There is no `render` prop and no `asChild`.

## `as`

`as` comes in two forms, and a part has one of them or neither.

| Form          | You write                                        | What happens                                                                                                  |
| ------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| **Tag**       | `as="aside"`                                     | A string from the part's short list of allowed tags. The element's own attributes are plain props on the part |
| **Component** | `as={AcmeButton}` and `tone="quiet"` on the part | Your component gets the part's props and every other prop you wrote on the part, as plain props               |

```tsx
import { Link, Section, Tooltip } from '@kvirn-ui/react'

// Tag: a landmark instead of a div, named by its heading.
<Section as="aside" aria-labelledby="kontakt">
  <h2 id="kontakt">Kontakta oss</h2>
</Section>

// Component: your design system's button on the trigger. Its props are props of the Trigger.
<Tooltip.Trigger as={AcmeButton} tone="quiet" aria-label="Skriv ut">…</Tooltip.Trigger>

// `as="a"` on a Link bypasses the router you registered, for one link.
<Link.Root href="/blankett.pdf" download as="a">Blankett (PDF)</Link.Root>
```

A tag outside the part's list is a type error. From JavaScript it logs `as-not-allowed:<part>:<tag>` once in development and the part renders its default element. The allowed tags are on each component's Docs page, because a tag changes the outline or the semantics (1.3.1, 4.1.2).

Only one `as` per part. To put two parts on one element, such as a Tooltip over a Toolbar item that opens a Popover, write a small component that applies one of them and pass it as the other's `as`.

### What a target component must do

A component you pass to `as` must:

- **Accept `ref`** and put it on its DOM node. Focus management, the position of a popup and the development checks read the element through it.
- **Spread the rest of its props on that DOM node.** The part's handlers, `aria-*`, `id`, `className` and `data-*` arrive as props, and dropping one drops a behaviour.
- **Render what the part needs.** `Menu.Trigger`, `Popover.Close`, `Dialog.Close` and `AlertDialog.Close` need a button. A `Link.Root` target needs an `<a href>`. A `Toolbar.Item` target must be focusable by itself and not natively disabled. The checks log a development warning, see [Dev warnings](?path=/docs/foundation-dev-warnings--docs).

### Server Components

`as` works from a Server Component when its value can cross to the client:

| `as`                                       | From a Server Component |
| ------------------------------------------ | ----------------------- |
| A tag string (`as="p"`)                    | Works                   |
| A Client Component (it has `'use client'`) | Works                   |
| A Server Component                         | Throws when it renders  |
| An inline function or arrow component      | Throws when it renders  |

## Hooks, for everything else

A part with no `as` (a Button, a Toggle, a Tab, a form control, a Listbox, a Table) is not a place to swap the element, because its role, its keys and its disabled state come from the native element it renders. If you need your own element, or your design system's component, use the hook and spread what it returns.

```tsx
import { mergeProps, useButton } from '@kvirn-ui/react'

function SaveButton() {
  const button = useButton()
  return <AcmeButton {...mergeProps({ tone: 'quiet' }, button.buttonProps)}>Spara</AcmeButton>
}
```

The hook's result also holds the state (`isDisabled`, `isFocusVisible`). The part puts the same facts in its `data-*` attributes (`data-disabled`, `data-open`, `data-selected`), so styling by state needs no function, only a selector.

A hook that disables something must stay in charge of its activation: a disabled Button must not call your `onClick`. Keep `buttonProps.onClick` on your element: it is the gated one.

## `mergeProps`

When you spread a hook's props on your own element, `mergeProps` joins them with yours. It is public, and the parts use the same function when they merge your props on a part with `as`.

```tsx
import { mergeProps, useButton } from '@kvirn-ui/react'

// Two objects, merged: the result is one object for one element.
mergeProps(
  { className: 'acme-save', onClick: logClick, style: { color: 'red' } },
  { className: 'kv-button', onClick: save, style: { color: 'blue', margin: 0 } },
)
// { className: 'acme-save kv-button',
//   onClick: calls logClick, then save,
//   style: { color: 'blue', margin: 0 } }

// With a hook: your props first, the hook's last.
function SaveButton() {
  const button = useButton()
  return <button {...mergeProps({ className: 'acme-save' }, button.buttonProps)}>Spara</button>
}
```

It merges from left to right, for one element:

| Prop                 | Result                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------- |
| Handlers (`onClick`) | **Chained**: every handler is called, in argument order, with the same arguments            |
| `className`          | **Joined** with a space, never replaced                                                     |
| `style`              | **Merged** by property: the later object wins for a property both set                       |
| `ref`                | **Merged** into one callback ref: every ref gets the element, and each is cleared on detach |
| `id`                 | The later one wins, and two different ids give a development warning (see below)            |
| Anything else        | The later defined value wins. `undefined` never overrides                                   |

The order decides who wins. Put your props first and the hook's last when the hook must win, and put yours last when yours should. `mergeProps(a, b, c)` accepts any number of objects.

### Two ids

An `id` on the part is what a label's `htmlFor` or an `aria-describedby` points at. When two different ids are merged, the later one wins and the first is gone, so the label or description points at nothing. In development that logs `merge-props-id:<first>:<second>`. Pass one id, or let the part set it. Inside a Field, set the control's id with `controlId` on `Field.Root`.

### What merging cannot do

- **It cannot block an activation.** Merging your own `onClick` over `buttonProps`, or replacing `buttonProps.onClick`, is not supported: the hook gates it when it is disabled.
- **It does not repair markup.** Merging props onto the wrong element still gives the wrong element.

## `className`

A part renders its own stable class, such as `kv-button`, and the default theme styles it. Your `className` joins it and never replaces it, with `as` or without. So `className="kv-button--primary"` adds the theme's variant, and `className="acme-save"` adds yours, and the theme keeps styling the part.

State is in `data-*` attributes (`data-disabled`, `data-open`), never in classes, so your CSS can select on it.

## Accessibility

- **Semantics come from the element.** A part chooses the element that gives the role, the keys and the disabled state. That is why a part either offers a short list of safe tags or none at all.
- **Names move with you.** A landmark you create with `as` (a `<nav>`, `<aside>` or `<section>`) needs its own name (2.4.1, 2.4.6). A dialog you create needs one too (4.1.2).
- **Keep the focus ring.** Do not set `outline: none` on your element. The part's class and `data-focus-visible` draw the ring (2.4.7).
- **Keep the ref.** Focus management, the position of a popup and the checks above read the element through the ref, so a component you pass to `as` must forward it.
