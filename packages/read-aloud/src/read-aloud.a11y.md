# Accessibility contract: ReadAloud

- **APG pattern:** none for the group. Buttons follow [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/), the naming practice for media buttons such as Play and Pause. `ReadAloud.Bar`'s transport follows [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/): one Tab stop with roving `tabindex`, arrows between the items.
- **Deviations:** none from the APG. Previous, Next and Stop stay focusable while unavailable (`aria-disabled`) while idle, so their names can be found and the keyboard path doesn't jump.
- **Native elements used:** `<button type="button">`, `<select>` with a `<label>`, a plain `<span>` for the status, a plain `<p>` for the privacy note. `Bar` is a plain `<div>`, no role of its own, around a `Toolbar.Root` (`role="toolbar"`); `Settings` is a `Popover` (`role="dialog"`); `Hide` is a `<button>`; `WhenStarted` renders no element of its own, a `Fragment`.
- **Tests:** planned as `read-aloud.test.tsx` next to this file (a fake engine, nothing speaks over the network). **Not written yet** — every "Test" cell below names the test that row will get, not one that exists or has run; none of this component's behaviour is proved by a re-runnable test today (see the AT matrix's Automated rows).
- **Status:** Planning

ReadAloud reads a region of the page aloud for people who benefit from hearing it, using Kvirn's own voice service. It is not a screen reader substitute and never starts by itself.

Other texts: Speed and Voice labels (`readAloud.rate`, `readAloud.voice`), the speed options (`readAloud.rateOption`, `1.5×`), the Note text (`readAloud.note`) and its `howItWorks` link, read in the normal reading order like any other static text — not announced.

The phrases are the approximation of a virtual screen reader (software that imitates one for tests), not NVDA or JAWS wording.

The "no voice" row above and `Root`'s own "renders nothing once `hasVoice` is `false`" (Roles table) are two different moments, not a contradiction: `hasVoice` is resolved synchronously at mount from the engine's own voice map (D14), so a language with no voice at all (`fi`, `nn`) never renders a player, not even briefly — there is nothing to announce because there is no group to read. The `polite` "no voice" announcement fires later, during an already-mounted, already-reading session, when a chunk's own resolved voice turns out missing once the real voice list has loaded (`error: 'no-voice'`) — the player is already on screen, so the state is announced in place instead of the player vanishing under the resident.

## Keyboard

- **Focus strategy:** native in the panel; **roving `tabindex`** inside `ReadAloud.Bar`'s toolbar
- **Selection follows focus:** n/a
- **Arrows wrap:** yes, inside the Bar's toolbar (APG Toolbar default)
- **Shortcuts:** none

## Focus management

- Initial focus: not moved. Focus never leaves the control that was used, including after stop and at the end of the content.
- Trap: no. Restore to: not applicable.
- Never obscured by: the panel composition is in the page flow and never sticky. `ReadAloud.Bar` is the one exception: static by default, a theme rule may make it sticky only while `data-status` is not `idle`; it un-sticks at `(max-height: 30rem)` instead of covering a focused element, and the consumer sets `scroll-padding-block-start` to its height. The selection trigger is placed below the selection, beside it when there is no room, and never over the selected text (2.4.11 Focus Not Obscured (Minimum), level AA).
- Hide: on press, focus moves to the one remaining Play button in the same place, so it is never lost to the page.
- SelectionTrigger: never takes focus. Any key, Tab included, dismisses it before focus moves, so it never covers a focused element (2.4.11 Focus Not Obscured (Minimum) (AA)). It is not in the Tab order, and it is not hidden from assistive technology. The identical action, and the whole keyboard path, is Play.
- Selection: a selection made in the content is captured, so Tab to Play doesn't lose it. Reading it collapses the selection.

## Announcements

| Event                                                                                            | Message key (i18n)                  | Politeness |
| ------------------------------------------------------------------------------------------------ | ----------------------------------- | ---------- |
| A wait past 1 second (once per press)                                                            | `readAloud.preparing`               | polite     |
| No voice for the content's language                                                              | `readAloud.errorNoVoice`            | polite     |
| The voice service is busy                                                                        | `readAloud.errorServiceBusy`        | polite     |
| The voice service is unavailable                                                                 | `readAloud.errorServiceUnavailable` | polite     |
| The browser couldn't play the audio                                                              | `readAloud.errorPlayback`           | polite     |
| Nothing resolved to read (B3, Plan 0154): a misconfigured `scope`, no `<main>`, or empty content | `readAloud.errorNoContent`          | polite     |

Nothing else is announced: not play, pause, next, stop, the end, or a skipped part (`readAloud.partSkipped`, shown in Status but never announced) — a resident who is listening does not need every gap or skip narrated, and a live region would talk over the speech itself and over a screen reader. Opening or closing Settings, hiding the Bar, and the Bar becoming sticky announce nothing either: none of them is news.

## Consumer responsibilities

- Set `lang` on the content, not just the page: the voice follows the content's own declared language, never the UI's `locale` (3.1.2). Offer the player to everyone: don't auto-start and don't hide it from assistive technology.
- Give the engine a `url` (directly, or once via `<KvirnProvider readAloud>`) and a `name`: `Note` and `Settings` both need it to tell residents who the text is sent to.
- Wrap the app in `KvirnProvider`: errors are announced through it.
- Mark what must not be read with `data-kv-read-aloud-skip`.
- **`ReadAloud.Bar` only:** without `contentRef`, it reads `scope` (a CSS selector) if given, else the page's `<main>`. `<!-- KV:READ-ALOUD:START -->` / `<!-- KV:READ-ALOUD:STOP -->` HTML comment pairs inside that root narrow it further; they are for server-rendered and CMS markup, since React/JSX cannot emit a comment, and an HTML minifier that strips comments removes them with it.
- **The disclosure's destination page is yours.** `ReadAloud.Settings`'s `howItWorksHref` and `ReadAloud.Note`'s own both link to a page you write, explaining that listening sends the text to your chosen service. The library names no URL and does none of this for you: with no `howItWorksHref`, there is no link and no dev warning — only the recipient sentence, which already names who receives the text, but a site that sends text to a third-party voice service should still link its own explanation, most usefully from the Bar's `Settings`, since a Bar composes no standalone `Note`.

## Visual / modes

Headless: no CSS. Classes `kv-read-aloud`, `kv-read-aloud-progress`, `kv-read-aloud-progress-fill`, `kv-read-aloud-button`, `kv-read-aloud-play`, `kv-read-aloud-button-label`, `kv-read-aloud-transport`, `kv-read-aloud-previous`, `kv-read-aloud-next`, `kv-read-aloud-stop`, `kv-read-aloud-select`, `kv-read-aloud-label`, `kv-read-aloud-status`, `kv-read-aloud-note`, `kv-read-aloud-selection-trigger`, `kv-read-aloud-bar`, `kv-read-aloud-toolbar`, `kv-read-aloud-count`, `kv-read-aloud-settings`, `kv-read-aloud-settings-popup`, `kv-read-aloud-hide`, the choice classes `kv-read-aloud--icons` and `kv-read-aloud--words`, both on Root (hybrid, with the word on Play/Pause only, is the default with no class), and the highlight `::highlight(kv-read-aloud)` are for the theme. The highlight is not the only cue: Status shows the sentence position, and a `data-busy`/`data-error` icon on Status, in text colour, backs up the spinner and the error text (1.4.1 Use of Color, level A). The meter is the same: decorative length, never the only position cue, since Status already carries the words. Every icon-only control in the Bar still carries its name from i18n in the button's own text (visually hidden by the choice class, not `aria-hidden`), so its accessible name never depends on the class.

- Focus indicator: the Button's (`data-focus-visible`); the selects use the browser's focus ring.
- Target size: buttons and selects are native controls at least 24 × 24 CSS px (2.5.8 Target Size (Minimum), level AA), set by the theme.
- Forced colours: `::highlight` maps to `Highlight`/`HighlightText`; Status is the position cue either way.
- Reduced motion: the sentence scrolls into view only when it is out of view and `prefers-reduced-motion` is not set; the `preparing` spinner animation is suppressed (the theme's job).

## WCAG SCs covered

- 2.2.2 Pause, Stop, Hide (A) and 1.4.2 Audio Control (A) do not apply: speech and the highlight start only when the user presses Play. Pause and Stop are offered anyway, reachable during `preparing` too, and the highlight is cleared on stop and unmount.
- 2.1.1 Keyboard (A): every control works from the keyboard.
- 2.4.11 Focus Not Obscured (Minimum) (AA): the SelectionTrigger never takes focus and any key dismisses it before focus moves.
- 3.1.1 Language of Page (A) and 3.1.2 Language of Parts (AA): each chunk is spoken with a voice for its own `lang`, never another language's and never the UI's `locale`. Unmarked text takes the closest `[lang]` above it, then the provider's `locale`, then `en`; an inner `lang` attribute wins. A chunk with no voice either stops the reading (the content's own language) with a message naming it, or is skipped and read past (an inline, differently-languaged chunk, D10).
- 4.1.2 Name, Role, Value (A): the controls have names and roles, and axe finds no violation.
- 4.1.3 Status Messages (AA): `preparing` (once per press), the five errors, and nothing per sentence or per skip.
- 3.3.1 Error Identification (A): each error says what happened and, where there is one, what to do next (`errorServiceBusy`, `errorNoVoice`, `errorNoContent`).
- 2.5.8 Target Size (Minimum) (AA), 1.4.11 Non-text Contrast (AA): the default theme's job, including the Bar's icon-only controls.
- 2.4.3 Focus Order (A): `ReadAloud.Bar`'s toolbar keeps the bar at 2–3 Tab stops (toolbar, Settings' popup once open, Hide while idle) ahead of the page's own navigation, which a worded five-button bar would not be.
- 3.3.1 Error Identification (A), applied to `scope`: a selector or a missing `<main>` that leaves nothing to read is shown and announced to the resident (`readAloud.errorNoContent`), not just a development-only warning (B3, Plan 0154) — the dev `console.warn` still fires too, for whoever wired `scope`.

- Tab through the panel: each control is named. Previous, Next and Stop are read as unavailable while idle.
- Press Enter or Space on Listen: speech starts and focus stays on the button.
- Press Escape while it reads: reading stops and focus stays where it was.
- In the Bar, Tab once to reach the toolbar, then use the arrow keys: focus moves between Previous, Play, Next, Stop and Settings, wrapping at the ends.
- Select text with Shift and the arrow keys, then Tab to Listen: only the selection is read.
- With no voice for the content's language, no player ever appears, not even for a moment.

## Known issues

- **Real speech is manual only.** Tests use a fake engine; the docs site and Storybook never call the live voice service in CI. The iOS unlock, real voices and the Kvirn service's actual latency need a check with your own users and assistive technology.
- **Highlight** needs the CSS Custom Highlight API. Without it, Status's position text is the only position cue, which is by design, not a gap.
- **fi, nb and nn strings:** have a native speaker review them before you launch.
- **voice.kvirn.com is not deployed yet.** Until it is, every environment but a local dev edge sees the "service unavailable" state.
