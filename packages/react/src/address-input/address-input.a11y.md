# Accessibility contract: AddressInput (AddressInput.Root, .Line1, .Line2, .PostalCode, .City, .Country)

- **APG pattern:** none for the address as a whole; `Line1` with a `geocoder` is the APG Combobox (editable, list autocomplete), as AddressSearch. There is no APG pattern for an address. An address is four labelled text inputs inside a `<fieldset>` with a `<legend>`, which is what the GOV.UK addresses pattern and the Nordic public-sector design systems do, and what autofill, dictation and every screen reader handle well.
- **Deviations:** one, approved by the maintainer on 2026-10-22. In `AddressInput.Line1` with a `geocoder`, Enter with no suggestion active searches and never submits the form, as in AddressSearch. One accessibility trade-off, approved the same day: Line1 keeps `autocomplete="address-line1"` and its `name` while it is a combobox, so autofill and 1.3.5 Identify Input Purpose (AA) stay, and a browser may show its own autofill list beside ours. Decisions: a plain `Fieldset` (not `group`), so each Field marks itself and Line 2 shows "(optional)"; one Field per line, so help texts and errors are per line; no auto-advance (3.2.2 On Input, A); the lookup is opt-in (a `geocoder` on the Root) and only a helper, so Line1 stays free text; `AddressInput.Country` is optional and first; without it the lookup offers only the Root's country, since the form can't record another. The boxes hold no text; the lookup's strings are `addressInput.*`, plus the `addressSearch.*` ones it reuses.
- **Native elements used:** `<fieldset>` and `<legend>` (the consumer's `Fieldset.Root` and `Fieldset.Legend`), `<div>` (`AddressInput.Root`, and each Field), `<label for>` (the Field's label), `<input type="text">` (each box), `<select>` (`Country`), `<input role="combobox">` and `<button type="button">` (`Line1` with a geocoder).
- **Tests:** `address-input.test.tsx` next to this file; the parts' own behaviour is `text-input.test.tsx`, `field.test.tsx`, `fieldset.test.tsx` and the mask tests. `address-input.stories.tsx` in `apps/storybook/src/components/address-input/`.

An address is one question ("Your address") answered with up to four boxes: street, line 2, postal code and city. `AddressInput.Root` is the layout and goes inside a plain `Fieldset.Root`, whose legend names the group. Each part is a `TextInput` inside the consumer's own `Field.Root` with a `Field.Label`, so a line has its own label, help text and error. With a `geocoder` on the Root, `Line1` is the ARIA 1.2 combobox of AddressSearch (in `@kvirn-ui/map`) instead, in the same Field, with a privacy notice above it, a Search button on request, the popup, help text and a note after a pick. `Country`, a native select in the consumer's own Field, is optional and first.

Rules, each proved by a test:

- **Autocomplete tokens (1.3.5 Identify Input Purpose, AA).** An autocomplete token tells the browser what a box is for, so it can fill it in. Line1 `address-line1`, Line2 `address-line2`, PostalCode `postal-code`, City `address-level2`. A Root `autoComplete` of `off` turns every part off, any other value (`section-postal`, `shipping`) goes before each token, and a part's own `autoComplete` wins (`address-input.test.tsx › each part gets its token, a Root prefix or off, and a part’s own wins`).
- **Text lines are not corrected.** Line1, Line2 and City have `spellcheck="false"` and `autocorrect="off"`: street names are not words (same test).
- **The postal code follows the Root's country.** SE `123 45`, FI `00100` and NO `1234` through the existing `postal-code` mask, with `inputmode="numeric"` and `dir="ltr"`. Any other country: no mask, `inputmode="text"`, `autocapitalize="characters"`, `dir="ltr"`, so a foreign code is never refused. The default country is the provider's, then the locale's (`address-input.test.tsx › follows the Root’s country: SE groups the digits, DE keeps letters with no mask`, `› without a country on the Root, the provider’s country is used`).
- **Nothing is rewritten and focus never moves on its own.** A full postal code keeps focus in the box, and changing `country` leaves a typed value as it is; the mask applies to the next edit (`address-input.test.tsx › a full postal code never moves focus, and changing country never rewrites the value`).
- **Paste is never blocked.** No box cancels a paste, and a pasted postal code takes the country's mask (`address-input.test.tsx › paste is never cancelled in any box, and a pasted postal code takes the country’s mask`).
- **Development warnings** (shown in the browser console while you build): a Root outside any group; a Root in a `group` Fieldset; a part outside a Root (`address-input.test.tsx › warns outside a fieldset, in a group fieldset, and for a part outside a Root`); a `Country` with no accessible name, not the first control of its Root, or outside a Root (`› a Country without a name, not first and outside a Root warns`).
- **The lookup is opt-in and Line1 stays free text.** Without a `geocoder` on the Root Line1 is a plain `textbox`, exactly as before (`address-input.test.tsx › without a geocoder Line1 is today’s plain textbox, with no combobox and no lookup text`). With one, Line1 is a combobox that keeps its label, `name` and `autocomplete="address-line1"` (`› with a geocoder Line1 is the ARIA 1.2 combobox named by the Field label, keeping its token and name, described by the notice, the help text and the consumer’s help`) and is submitted with the form as the street (`› is submitted with the form as the street, with the other boxes`).
- **The privacy notice is read before typing.** It sits above Line1, so a popup never covers it, and is first in Line1's description, then the lookup help (`› the privacy notice is above Line1 and first in its description, then the help text`). This differs from AddressSearch, which keeps its notice below. With `privacyNotice={false}` there is no notice and the description starts with the lookup help: the consumer must say where the text goes in the Field's help text, so it is still in the description (`› privacyNotice false renders no notice, and the consumer’s help text still describes Line1`). A maintainer-approved accessibility trade-off.
- **Nothing is sent before the visitor types in Line1, and neither autofill nor our own fill searches.** Typing in Line 2, the postal code or the city never searches (`› typing in Line 2, the postal code or the city never searches`). An `input` event without a typing `inputType` (browser autofill, the form fill) sets the text, opens no list, searches nothing and announces nothing (`› browser autofill of all the boxes, Line 1 included, searches nothing, opens no list and announces nothing`).
- **A pick fills, and says so.** It writes the result's `address.line1` (never its label) into Line1 and fills the postal code and the city, as typing does (a controlled `value`, the DOM value, a form library's `input` listener: `› the fill reaches a controlled value, the DOM value of an uncontrolled box and a form’s input listener as typing does`; `› a pick writes address.line1 into Line 1, never the result’s label, and typing on searches again for house-level matches`), never Line 2 (`› a pick fills Line 1, the postal code and the city, never Line 2, keeps focus in the lookup and shows the note`). Focus stays in Line1 with the caret at the end, so a missing house number is typed straight after, and typing on searches again. A pick replaces what was typed in those three boxes (`› a pick replaces what the visitor typed in the three boxes`). A box the result has no value for keeps a value the visitor typed and is emptied if an earlier pick left its value (`› a result without a postal code keeps a typed one, and empties one an earlier pick left`; `› a result without a city adds the missing town to the note and empties the earlier pick’s city`). A street without a house number is filled the same way and the note asks for the number (`› a street without a house number is filled and the note asks for the number`). A place with no postal address fills nothing, is shown and announced, the typed text is restored and the list stays open (`› a place with no postal address fills nothing, says so in the list, announces it and keeps the list open`). `onLookupResult` gets the whole result (`› onLookupResult gets the whole result of each pick`).
- **Narrowing and the house-number lookup only help.** Line1's searches send `postalCode` and `city` once those boxes hold a value, and nothing when they are empty; filling them starts no search (`› the postal code and city are sent with a search once their boxes have values`; `› empty postal code and city boxes send neither, and filling them starts no search`). After a `street` pick, a house number typed after the street calls the geocoder's `structured` lookup; an exact answer fills the postal code and the city and keeps Line1 as typed, a keystroke cancels a pending lookup, and no answer, a street-level answer, an error or a geocoder without `structured` changes nothing and announces no error (`› typing a house number after a street pick looks it up with the parts and fills the postal code and city`; `› an address not found leaves every box as it was and announces no error`; `› a failing lookup changes nothing and announces no error`; `› a street-level answer fills nothing`; `› a geocoder without a structured lookup does nothing after a number is typed`; `› a keystroke aborts a pending lookup and only the last text is looked up`).
- **The fill note is plain text.** "Filled in from the address search. Check the address." follows a pick, with the sentences for a missing house number, postal code or town and a changed country. It names no address, so an edit never makes it stale, it is in Line1's description and never a live region. After a pick an edit says nothing on request, and as you type only the new search's count is said (`› the fill note is in Line 1’s description after the help text`; `› the note is plain text, not a live region, and an edit after the pick neither re-searches nor announces`).
- **Which country the lookup searches.** Without a `Country` part the lookup asks for, and keeps, only addresses in the Root's country (`country`, else the provider's), and the help text names it (`› without a Country part only the Root’s country is offered, the count says what is left and the geocoder is asked for it`; `› without a Country part the Root’s country prop sets the country searched and named`). With one, every country is listed, the selected one first, and the geocoder is asked for the selected one (`› with a Country part every country is listed and the geocoder is asked for the selected one, which follows the select`). A pick in another country sets the select first, with a `change` event as a visitor's, so the postal code's mask follows, then writes the boxes (`› a pick in another country switches the select first, the mask follows, the boxes are written, and the note and announcement say so`). `Country` is a native select with the Root's country first, named in the page's language, and `value`/`defaultValue`/`onChange` as any select (`› is a native select named by its Field label, autocomplete country, the Root’s country first and named in the page’s language`; `› names the countries in the provider’s language and takes the Root’s autocomplete prefix`; `› the Root’s country is the starting value, and the select follows value and defaultValue`).
- **Strings.** The lookup's text is `addressInput.*` and the `addressSearch.*` keys it reuses (`submit`, `privacy`, `privacyUnnamed`, `tooShort`, `searching`, `resultCount`, `pickedFilled`), each overridable per instance and per provider (`› every string comes from the catalog: the Swedish one translates the help, scope, notice and Search`; `› a per-instance message replaces the catalog text, for Line 1’s own keys and the reused ones`). The boxes and `Country` hold no text and Line1's label is the consumer's; country names come from `Intl.DisplayNames`. The mask's polite "character not allowed" messages are TextInput's (from TextInput).
- **No axe violations** in every state of the test file and in every story state, in every theme (`address-input.test.tsx › has no violations idle, with results open, rejected, filled with the note, and with a Country part`; `› has no violations on a status line: too short, error and offline`).

## Keyboard

- **Focus strategy:** native. The boxes and `Country` are native controls, and DOM focus stays on Line1 while its active suggestion is `aria-activedescendant`
- **Selection follows focus:** n/a
- **Arrows wrap:** no (the list stops at its ends)
- **Shortcuts:** none

The boxes are native: AddressInput handles no key in them, never calls `preventDefault` on one and never moves focus when a box is full. `Country` is a native select: the platform's keys. With a geocoder Line1 is the combobox of AddressSearch with one approved deviation: Enter with no suggestion active searches and never submits the form. The parts are in the order you write them in your code: Country, Line1 (then Search on request), Line2, PostalCode, City.

## Focus management

- Initial focus: none set by AddressInput.
- A search, a result, an error, an offline answer, a pick or a Country change never moves focus (3.2.2): it stays in Line1 (or the select). A pick writes the boxes without focusing them.
- Trap: no.
- Restore to: n/a.
- Not hidden by your page: if your site has a sticky header, keep `scroll-padding` so a focused box and the error under it stay visible (2.4.11 Focus Not Obscured (Minimum), AA).

## Consumer responsibilities

- A plain `Fieldset.Root` with a `Fieldset.Legend` that names the address; not `group`.
- One `Field.Root` per box with a `Field.Label`, `required` on the ones that are, and a `Field.HelpText` with an example for the postal code in the country's form (3.3.2 Labels or Instructions, A).
- Per-part errors in `Field.ErrorMessage` with `invalid` on that Field, a whole-address error in `Fieldset.ErrorMessage`, and an `ErrorSummary` link per invalid part (the Field's `controlId`; the whole-address error links to Line1).
- `country` on the Root when the address is not in the provider's country. A country control is `AddressInput.Country`, first in the Root, in its own Field with a `Field.Label` ("Country") and a `name`; add it when the service takes addresses outside the Root's country.
- A lookup only with a `geocoder` the service has chosen, named in its own privacy notice (GDPR: what is typed and the visitor's IP address reach it). The notice above Line1 says where the text goes. With `privacyNotice={false}` you say where the text goes in Line1's `Field.HelpText`, and with `attribution: null` on `kvirnGeocoder` you credit the data on the page.
- `autoComplete="off"` for someone else's address, and `section-*` when a page has two.
- An address the user gave earlier in the same process is carried forward: filled into the boxes (`defaultValue`) or shown as a summary with a change link (3.3.7 Redundant Entry, A). Prefer the summary to read-only boxes, which look editable.
- Validation: the lookup never marks a box invalid, and a pick is not a check. Validate the boxes as you do without it.

## Visual / modes

- Focus indicator: the TextInput's, the select's and the combobox's own, a visible outline with an offset.
- Target size: each box, the select and the lookup are as tall as a TextInput. Search and Clear are at least 24px (2.5.8 Target Size (Minimum), AA), also in compact density.
- Layout: the boxes stack. When the address has room (about 22rem wide), the postal code and the city share a row. The Country field is as wide as its content. At 320px and at 400% zoom the boxes stack, the lookup's help text, notice and note wrap and Search wraps below the input (1.4.10 Reflow, AA; 1.4.12 Text Spacing, AA).
- The fill note has a leading check icon in the text colour, decorative; the words carry the meaning (1.4.1 Use of Color).
- Forced colours mode (the user's own system colours): each box uses the TextInput's system colours. An invalid box keeps its heavy edge, and the error text still names the problem. The status and note icons take the text colour; Search uses the system's button colours; the active suggestion uses the system's highlight colours.
- Reduced motion: the only motion is the lookup's spinner, and only under no-preference.
- Right-to-left languages: the postal code and city row mirrors; Clear then Search sit at the inline end. The postal code box is always read left to right (`dir="ltr"`). The check icon is not mirrored.

## WCAG SCs covered

- 1.3.1 Info and Relationships (A), 4.1.2 Name, Role, Value (A): a fieldset with a legend, a visible label for each box, the select and the lookup; the lookup is a combobox with a listbox.
- 1.3.5 Identify Input Purpose (AA): the four autocomplete tokens, and `country` on the select.
- 1.4.1 Use of Color (A): the note and the status lines are words with an icon.
- 1.4.10 Reflow (AA), 1.4.12 Text Spacing (AA): the row wraps; nothing is fixed in height.
- 2.1.1 Keyboard (A), 2.4.3 Focus Order (A): one Tab stop per control, in the order of the page's code, Country first; the lookup is operable by keys alone.
- 2.4.6 Headings and Labels (AA), 2.5.3 Label in Name (A), 2.5.8 Target Size (Minimum) (AA).
- 3.2.2 On Input (A): no auto-advance, and a pick or a country change never moves focus.
- 3.3.1 Error Identification (A), 3.3.2 Labels or Instructions (A), 3.3.3 Error Suggestion (AA): an error for each box with what to do, labels and an example; the lookup's help text and the "or type it in the boxes" way out.
- 3.3.7 Redundant Entry (A): the consumer's (Consumer responsibilities). Every box and Country take `defaultValue`/`value`, so an address given earlier in the process can be carried forward.
- 4.1.3 Status Messages (AA): the lookup's searching, count, no result, error, offline and pick messages through the Announcer.

### What to check

- Tab through the address. Focus moves from the country (if there is one) to the street, line 2, postal code and city. A screen reader reads the group name (for example "Your address") and then each box's label.
- Let the browser's autofill fill in the address. Every box gets the right part of it. No list opens and nothing is announced.
- Type a full postal code. The code takes the country's shape and focus stays in the box. Change the country after that: the code stays as it was typed.
- Send the form with a box wrong. The error summary has a link for that box, and the link moves focus to it.
- With a lookup: type part of a street. The number of addresses is heard. Press Enter with no suggestion chosen: the search runs and the form is not sent. Turn the network off and search: the message points to the boxes.
- Choose a suggestion. The street, postal code and city are filled in, and focus stays in the street box. One message says the address is filled in, and names anything missing (the house number, the postal code, a new country). Type the house number straight after the street.

## Known issues

- **Eastern Arabic and full-width digits** in a masked postal code are refused today (the pattern mask takes 0-9). Set `mask={false}` on `AddressInput.PostalCode` where those keyboards are expected.
- **DK and IS** have no postal-code mask (masks exist for SE, FI and NO only): the box takes what is typed, asks phone keyboards for capital letters and is ten characters wide.
