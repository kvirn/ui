# Accessibility contract: Navigation

- **APG pattern:** none needed for a list of links. A labelled `<nav>` landmark around a list of links is plain HTML, and it is not the [Disclosure Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) pattern: nothing here opens or closes. Never `role="menu"`.
- **Deviations:** none
- **Native elements used:** `<nav>` (the `navigation` landmark), `<ul>` and `<li>`. The links are [Link](../link/link.a11y.md): native `<a href>`.
- **Status:** alpha candidate. Gates green 2026-10-06, accessibility-reviewer pending, and it reads the whole contract. Manual AT is `pending`.
- **Tests:** `navigation.test.tsx` next to this file. `navigation.stories.tsx` and `navigation.fixture.tsx` in `apps/storybook/src/components/navigation/`. Design specs: `docs/design/navigation.md` (the structure and the service link) and `docs/design/navigation-link-options.md` (the look: the current page, the trail and the horizontal bar).

Navigation is a named landmark around a list of page links, with the current page marked and an optional second level. It adds no `tabindex`, no key handling, no state and no announcement: the links are the focusable parts and own the keys ([link.a11y.md](../link/link.a11y.md)). It is not a composite widget, so every link is a Tab stop and the arrow keys do nothing. It is a vertical list by default and a row that wraps with the class `kv-navigation--horizontal` on the root. Orientation is a look and not behaviour, so it is a class and not a prop, and it changes no role, key or name.

## Keyboard

- **Focus strategy:** native
- **Selection follows focus:** n/a
- **Arrows wrap:** n/a
- **Shortcuts:** none

Each link is a native `<a href>` and its own Tab stop, in DOM order, which is also the visual order: in a horizontal bar too, where right to left the order starts at the right. There is no roving tabindex and no arrow-key navigation: this is a list of links, not a menu. The links own Enter ([link.a11y.md](../link/link.a11y.md)). Navigation never moves focus. A group rendered with `hidden` is out of the Tab sequence.

| Key                                                       | Context                        | Action                                                                                     | Test                                                                                       |
| --------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| Tab                                                       | before or in the navigation    | Moves to the next link, nested links in DOM order included, then out of the nav            | `navigation.test.tsx › Tab moves through the links in DOM order, nested ones included`     |
| Tab                                                       | a group rendered with `hidden` | Skips it: its links are not Tab stops                                                      | `navigation.test.tsx › Tab skips a collapsed group`                                        |
| Tab                                                       | a group's label                | The label is no Tab stop: focus goes from the link before it to the first link of its list | `navigation.test.tsx › the label is no Tab stop: Tab goes from link to link past it`       |
| Shift+Tab                                                 | on a link                      | Moves to the previous link, then out of the navigation                                     | `navigation.test.tsx › Shift+Tab moves back through the links, then out of the navigation` |
| Enter                                                     | on a link                      | Follows the link                                                                           | `navigation.test.tsx › Enter follows the link`                                             |
| ArrowUp / ArrowDown / ArrowLeft / ArrowRight / Home / End | on a link                      | Arrow keys, Home and End are not handled: focus stays on the link                          | `navigation.test.tsx › Arrow keys, Home and End are not handled`                           |

Space, Escape and the arrow keys are not handled. Space scrolls the page, as on any link. A horizontal bar has the same keys: Left and Right do nothing there either.

## Focus management

- Initial focus: not moved. Navigation never moves focus.
- Trap: no. Tab always leaves the navigation.
- Restore to: not applicable. Where focus goes after a link is followed is the router's or the app's job (for example, to the new page's `h1`).
- Never obscured by: Navigation renders no overlay and sets no `overflow`, so a link's focus ring is never clipped (2.4.11 Focus Not Obscured (Minimum), AA; 2.4.13 Focus Appearance, AAA). In a horizontal bar the gaps keep one item's ring clear of the next item's fill.

## Announcements

| Event | Message key (i18n) | Politeness |
| ----- | ------------------ | ---------- |
| none  | none               | –          |

Navigation announces nothing. The current page is announced by the browser through `aria-current` on its link, and the level of a nested list by its native list semantics. The trail is not announced.

### Message keys

None. The name is the consumer's `label` or `aria-labelledby`, in the consumer's own translations. A new-tab notice in a link is Link's (`link.newTabNotice`).

## Consumer responsibilities

- **Name every navigation, and give each a different name** (2.4.1 Bypass Blocks, A; 2.4.6 Headings and Labels, AA): "Main menu", "In this section". Prefer `aria-labelledby` pointing at a visible heading where there is one. Don't put "navigation" or "menu" in the label when the landmark role already says it, unless the name would be empty without it.
- **Render the same items in the same order and the same place on every page.** Navigation never reorders items, so keep the list the same from page to page.
- **Mark exactly one current link per navigation** (4.1.2 Name, Role, Value, A). `current="page"` goes on the link to the page. When the page isn't in the navigation (a case page, a menu that stops above it, a header bar of sections), `current` with no value goes on the deepest item shown, which gives `aria-current="true"` (the GOV.UK Design System calls it the active item). Never on an ancestor of a listed page, and never on a link inside a `hidden` group: when the page is inside a collapsed group, the deepest item shown takes it. Navigation doesn't detect the page from the router, and a development warning fires when two links have it.
- **Collapse a group with `hidden`, never by unmounting it.** Its links stay in the DOM but leave the Tab sequence and the accessibility tree. The toggle that opens it is yours (a `Button` with `aria-expanded` and `aria-controls`): Navigation has no toggle and does not manage a disclosure.
- **A horizontal bar is one level.** A nested list stays a column under its item. Give a section's sub-links a second `Navigation` with its own name. Navigation has no flyouts and no collapsing of its own.
- **Link text** says where the link goes, in context (2.4.4 Link Purpose (In Context), A). No "click here".
- **Two levels at most on resident pages.** A staff or CMS sidebar may go deeper, with the trail showing the way (a story shows four levels). A menu that opens and closes is not a longer list: build the toggle yourself, as above.
- **A group label** is a `Navigation.Label` in the `Navigation.Item`, next to the nested list it names, with text from your own translations. Don't use a heading or a fake link for it. There is no `Navigation.Group` part.
- **Don't wrap a link in anything focusable.** Each item holds one link and an optional nested list.
- **Skip link and landmark order** belong to the page, not the component (2.4.1 Bypass Blocks, A).

## Visual / modes

Headless: Navigation ships no CSS. With `@kvirn-ui/theme/theme.css`:

- Focus indicator: the link's focus ring, at least 2 pixels thick with 3:1 contrast, outside the item (2.4.7 Focus Visible, AA; 2.4.13 Focus Appearance, AAA). Around the solid fill the offset band is what tells the ring from the fill. Test: `navigation.stories.tsx › FocusVisible` (play) for the current page.
- Target size: every item is at least 24 by 24 CSS pixels, in a list and in a bar: 44 pixels high by default and 32 in compact density (2.5.8 Target Size (Minimum), AA). Test: `navigation.stories.tsx › CompactDensity` and `› Horizontal` (play) assert the 24 pixel threshold.
- Current page: a solid fill in the primary colour with a label in the colour made for it, in bold text. The fill is a shape at 3:1 or more against the surface, and bold against regular is a second cue, so it is never shown by colour alone (1.4.1 Use of Color, A). The trail, every ancestor of it, is a quiet fill in bold text. Everything else is regular text with no fill, and a 2 pixel underline on hover and press.
- Forced colours: the fills drop (the system's background colour, with its link colour for labels). The current item gets a straight bar in the system's link colour, never a border on the rounded box: at the inline start of a list item and under the label in a horizontal bar. The trail keeps bold text. The bold cue has no automated check: it is checked by eye in the `ForcedColors` story.
- Group label: small type in the muted text colour, at every density, aligned with the links' text, with space above it from the second item on. The muted text colour on the surface is already measured for contrast (1.4.3 Contrast (Minimum), AA). Forced colours: the system's text colour.
- Contrast: every colour pair is measured by the theme's contrast check (1.4.3 Contrast (Minimum), AA; 1.4.11 Non-text Contrast, AA): the label on the current fill (4.70:1, the lowest text pair, in compact density: it passes with no margin), text on the trail fill, text on the plain backgrounds for the hover underline, and the fill against the page background, a surface and a raised surface.
- reduced-motion behaviour: the link's colour, underline and background transition only under `prefers-reduced-motion: no-preference`.
- RTL: logical properties only. The nested indent and the forced-colours bar sit at the inline start (the right), and a horizontal bar starts at the right.
- Horizontal (`kv-navigation--horizontal`): the top level is a row that wraps with gaps between items. Each item is as wide as its label, up to the row, so a longer label wraps inside its item. One level: a nested list stays an indented column under its item.
- Collapsed groups: a `hidden` group is `display: none`, so it stays collapsed without `reset.css`.
- Reflow and text spacing: a vertical list by default and a row that wraps in a bar, with `overflow-wrap: anywhere`. No horizontal scrolling at 320 CSS pixels wide with the Finnish fixtures, vertical and horizontal (stories with long Finnish text, vertical and horizontal; there is no dedicated sweep).

## WCAG SCs covered

- 1.3.1 Info and Relationships (A): a `<nav>` landmark, native lists and nesting (`navigation.test.tsx › renders a named navigation landmark with a list of list items`, `› a nested list sits inside an item, so the level is announced`). The trail is visual, and the list nesting carries the hierarchy.
- 1.4.1 Use of Color (A): the current page is a fill and bold text, and the trail is bold text (default theme). In forced colours the current page is a bar and bold text, and the trail is bold text.
- 1.4.3 Contrast (Minimum) (AA), 1.4.11 Non-text Contrast (AA): the theme's contrast check on every colour pair.
- 1.4.10 Reflow (AA), 1.4.12 Text Spacing (AA): the Finnish fixtures at 320 pixels wide, vertical and horizontal, `overflow-wrap`, no fixed heights or widths.
- 2.4.1 Bypass Blocks (A), 2.4.6 Headings and Labels (AA): a named landmark and a named group (`Navigation.Label`), with a development warning for no name and for a duplicate name (`navigation.test.tsx › development warnings`).
- 2.1.1 Keyboard (A), 2.4.3 Focus Order (A): native links in DOM order, and a `hidden` group skipped (the Keyboard rows above).
- 2.4.4 Link Purpose (In Context) (A): the consumer's link text.
- 2.4.7 Focus Visible (AA): the link ring. 2.4.11 Focus Not Obscured (Minimum) (AA): nothing covers or clips it. 2.4.13 Focus Appearance (AAA, beyond the AA bar): the ring's size and contrast.
- 2.5.8 Target Size (Minimum) (AA): the 24 pixel threshold in the compact and horizontal stories.
- 4.1.2 Name, Role, Value (A): the landmark's name, and exactly one `aria-current` per navigation, with a development warning for two (`navigation.test.tsx › development warnings`).

## Known issues

- **List semantics in Safari.** The default theme draws no list marker, and Safari (VoiceOver) drops the list semantics of such a list, so the lists carry `role="list"`. Check that VoiceOver in Safari says "list, 4 items" and announces the nested level.
- **The trail is visual only.** The ancestors of the current page are drawn as a quiet bold trail, but never marked with `aria-current` and not announced. A screen reader user gets the hierarchy from the list nesting, and a Breadcrumb is the announced path. Check how well the nesting reads with your own screen reader.
- **A solid fill can be read as keyboard focus.** A Listbox's active option and a pressed Toggle are solid in the primary colour too. The ring sits 2 pixels outside the fill. Test it with your users; the fallback is the quiet fill with a connector line.
- **Two solid fills at once.** A header bar whose section carries `current` (`aria-current="true"`) next to a list whose page carries `"page"` draws two solid items. Whether `"true"` should draw the trail look is an open design question, and the approved rule stands as written. A bar has no second row for the trail branch either: give the section's sub-links a second `Navigation`.
- **The trail's speed on very large trees** is not measured. The theme finds the trail with a CSS selector that looks at the children of each item, and a very large CMS tree could make it slow.
- **Keyboard tests run in Chromium only.** The keyboard rows run in Vitest browser mode on Chromium, not in WebKit. Test in Safari with your own assistive technology.
- **The group's name is set after hydration.** `Navigation.Label` registers in a layout effect, so the nested list gets `aria-labelledby` on the client and not in the server HTML. Without JavaScript the list has no name, though the label text still comes before it in reading order.
