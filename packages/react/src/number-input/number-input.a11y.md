# Accessibility contract: NumberInput

- **APG pattern:** none needed. NumberInput is a native text `<input>`, a `textbox`. It is deliberately **not** the APG spin button: there is no stepping with the arrow keys and no spinner buttons. The name, description and state come from HTML and `aria-describedby`, as for [TextInput](../text-input/text-input.a11y.md).
- **Deviations:** none from APG, because no APG pattern is used. `type="number"` is not used by design: it changes its value on the mouse wheel and on ArrowUp and ArrowDown, drops leading zeros, rounds silently, shows spinners that are hard to hit, and reads the decimal mark by the browser's language and not the page's (the reasons GOV.UK gives).
- **Native elements used:** `<input type="text">` with `inputmode` and `spellcheck="false"`. By default it also runs a number mask (a rule for which characters the box accepts and how the number is written: `masks.number()`); `mask={false}` runs none and a custom `mask` replaces it. A mask adds no element and no role.
- **Status:** alpha candidate. Accessibility-reviewer pending. Manual AT is `pending`.
- **Tests:** `number-input.test.tsx` next to this file, and `../mask/use-mask.test.tsx` for the mask machinery. `number-input.stories.tsx` in `apps/storybook/src/components/number-input/`.

NumberInput is a quantity or an amount in a Field: a TextInput with a number mask built in, in the provider's language. It is a native input, so the browser supplies the role (`textbox`), the keyboard, selection, paste, autofill and undo. NumberInput adds the Field's wiring, the number mask and the part classes. The mask is optional: `mask={false}` makes it a plain numeric text box (same role, keys and Field wiring, nothing left out), and another `mask` replaces the number mask. For a code with leading zeros (a postcode, a case number) use a [TextInput](../text-input/text-input.a11y.md) with a mask: a number would drop the zeros.

By default (no `mask` prop) these props become the number mask, in the provider's locale: `decimals` (default 0: no decimal mark), `allowNegative` (default `false`), `grouping` (default `false`), `min` and `max`. The decimal mark is the one of the page's language (a comma in sv, fi, nb and nn, a point in en), and a typed `,` or `.` is read as that mark. `onValueChange(value, details)` gets `details.unmaskedValue` (the machine form, `-1234.5`), `details.isWithinRange` (`min` and `max`), `isComplete` and `rejected`. With `mask={false}` none of these props shapes the value (the keypad still follows `decimals` and `allowNegative`; no `unmaskedValue`, `isWithinRange`, `isComplete` or `rejected`: only `reason` and `event`), and with a custom `mask` the details are that mask's. **A range is reported, never enforced:** the value is never clamped or corrected, so the user's entry never changes without notice. Your form says what's wrong and gives the allowed range in a Field.ErrorMessage (3.3.1 Error Identification, A; 3.3.3 Error Suggestion, AA), and states the range in the help text before input (3.3.2 Labels or Instructions, A).

`useNumberInput` gives the same `inputProps` for your own `<input>`: it reads the nearest Field too, and returns `format` and `unmask` for the provider's locale.

## Keyboard

- **Focus strategy:** native
- **Selection follows focus:** n/a
- **Arrows wrap:** n/a
- **Shortcuts:** none

All native: NumberInput handles no keys itself and never calls `preventDefault` on one. It is a text box, so ArrowUp and ArrowDown move the caret and never step the value. The mask reads the value after the browser's edit and rewrites it only when it must, and never moves focus or auto-advances. In a Field, the Field.Label, the help text and the error are not focusable and have no keys.

## Focus management

- Initial focus: not moved. No `autoFocus` by default.
- Trap: no.
- Restore to: not applicable.
- Never obscured by: NumberInput renders no overlay. A sticky header needs the consumer's `scroll-padding` (2.4.11 Focus Not Obscured (Minimum), AA).

Focus entering the input announces nothing live: the name, role, "required", "invalid" and the description (help text, then error) are read by the screen reader. NumberInput adds no strings of its own: the number mask uses two of the mask's messages (`characterNotAllowed` and `maximumDecimals`: the number engine never rejects a character for length, so `maximumLength` is for pattern and RegExp masks only), a custom `mask` uses the mask's three (`characterNotAllowed`, `maximumLength` and `maximumDecimals`), in all five locales, and `mask={false}` uses none, and they can be overridden per provider and per instance (`messages`). `announceRejections={false}` turns the announcements off, for example when you show your own message. **The KvirnProvider is required for announcements.** Without one the mask still works, nothing is announced, and one development warning says so.

Dev warnings (English, for the developer, never announced): a NumberInput with no accessible name (`number-input-without-name`, `number-input-in-field-without-label`), an `id` inside a Field (`number-input-id-in-field`), `decimals` above 0 in a Field with no help text (`number-input-decimals-without-help-text`, 3.3.2), and a custom `mask` in a Field with no help text (`number-input-mask-without-description`, 3.3.2: a mask shapes the input but doesn't explain the format). A whole number with the default mask needs no format help text, and `mask={false}` applies no format, so neither warns. A `mask` that is not a mask name warns once (`mask-unknown-name:<name>`) and runs no mask, and a country mask by name with no resolvable country warns (`mask-country-unresolved:<name>:<locale>`): both come from the mask hook (see the [TextInput contract](../text-input/text-input.a11y.md)).

## Consumer responsibilities

- Put every NumberInput in a Field with a Field.Label, or give it `aria-label` or `aria-labelledby` from your translations (4.1.2 Name, Role, Value, A). Never use the placeholder as the label (3.3.2 Labels or Instructions, A).
- With `decimals` above 0, put the format and an example in a help text, a `Field.HelpText` under the control: "In kronor, for example 1 250,50" (3.3.2 Labels or Instructions, A; a development warning checks it). The mask takes the decimal mark of the page's language, but it doesn't explain it.
- Put the unit in the label ("Monthly rent in kronor") or the help text. To also show it in the box, use an `InputGroup.Addon`: it is hidden from screen readers, so the label must still say it.
- Set `autoComplete` where a token exists, and never block paste (3.3.8 Accessible Authentication (Minimum), AA, when the number is part of signing in). Don't set `pattern`: it triggers the browser's validation message, in the browser's language.
- Validate in your form, after submit, and say what's wrong and how to fix it in a Field.ErrorMessage (3.3.1 Error Identification, A; 3.3.3 Error Suggestion, AA). `min` and `max` are only reported in `details.isWithinRange`: show your own help text, and never clamp.
- Choose a width class that fits the answer: `kv-input--width-2`, `-4`, `-6`, `-10`, `-20`. A width is a hint, never a limit.
- Wrap the app in `KvirnProvider`, so a left-out character is announced (4.1.3 Status Messages, AA) and the decimal mark follows the page's language.
- Don't pass an `id` inside a Field: the Field's id wins. Use `<Field.Root controlId>`.

## Visual / modes

NumberInput renders the `kv-input` part of TextInput with `kv-input--numeric`, so the look, focus indicator, target size, boundary, forced colours and reflow are the TextInput contract's (Visual and modes). In short:

- Focus indicator: a ring with at least 3:1 contrast against the colours next to it, on keyboard focus (2.4.7 Focus Visible, AA; 2.4.13 Focus Appearance, AAA). An invalid box shows the ring on any focus, including a click, and keeps its error-coloured edge.
- Target size: at least 24px high (2.5.8 Target Size (Minimum), AA).
- Forced colours (the system's own colour scheme): the input keeps a real border, and invalid is not shown by colour alone.
- Reduced motion: colours change gradually only when the person has not asked for reduced motion.
- Right-to-left (RTL) pages: the layout uses logical properties only. The arrow keys are the browser's own (`number-input.test.tsx › ArrowLeft and ArrowRight move the caret in a right-to-left page and are not intercepted`). A negative number's minus sign: see Known issues.

## WCAG SCs covered

- 1.3.1 Info and Relationships (A): the label, help text and error are programmatically associated (`number-input.test.tsx › the label names it, the help text and the error describe it, and the state is on it`).
- 1.3.5 Identify Input Purpose (AA): only when the number is about the user and has an autocomplete token (`postal-code`, `bday-year`, `cc-number`); `autoComplete` passes through. An amount or a quantity has no token, so 1.3.5 doesn't apply to it (`number-input.test.tsx › forwards its ref and native props, and the part classes join a consumer’s`).
- 2.1.1 Keyboard (A), 2.1.2 No Keyboard Trap (A): native input, and ArrowUp and ArrowDown are never taken (`number-input.test.tsx › ArrowUp and ArrowDown never change the value`).
- 2.5.3 Label in Name (A): the visible label is the name.
- 3.2.2 On Input (A): typing never moves focus, and a complete number doesn't advance.
- 3.3.1 Error Identification (A), 3.3.2 Labels or Instructions (A) and 3.3.3 Error Suggestion (AA): through the Field, its help text and your error message. A range is reported, never enforced or clamped (`number-input.test.tsx › min and max are reported as isWithinRange, never enforced`).
- 3.3.8 Accessible Authentication (Minimum) (AA): only when the number is part of signing in (a PIN, a code); paste and autofill work (`number-input.test.tsx › paste is not blocked: 1 250,50 and 1250.50 both read`).
- 1.4.11 Non-text Contrast (AA), 2.4.7 Focus Visible (AA), 2.5.8 Target Size (Minimum) (AA): the input is TextInput's `kv-input`, so these are the TextInput contract's (Visual / modes); NumberInput adds no test of its own.
- 2.4.11 Focus Not Obscured (Minimum) (AA): NumberInput renders no overlay; a sticky header needs your `scroll-padding`.
- 4.1.2 Name, Role, Value (A): a native `textbox` with name, `aria-invalid`, `aria-required` and `disabled` (`number-input.test.tsx › renders a native text box, not a spinbutton, with no min, max or pattern attribute`).
- 4.1.3 Status Messages (AA): a left-out character is announced politely through the Announcer, and a digit past the decimals says so and not that the field is full (`number-input.test.tsx › a letter is left out and announced politely, in the provider language (%s)`, `number-input.test.tsx › a digit past the decimals is left out and announced as decimals, not as a full field (%s)`).

## Known issues

- **Negative numbers use the text keypad.** iOS's numeric and decimal keypads have no minus sign, so `allowNegative` asks for `inputmode="text"`. The mask still leaves out letters.
- **No provider, no announcement.** `KvirnProvider` is required for announcements.
- **Undo.** When the mask rewrites the value (writes a group separator, leaves out a character), undo can't go back past that step. Accepted, as for TextInput masks.
- **`min` and `max` are not announced.** They are reported to your code only. Say the range in the help text.
- **Keyboard tests run in Chromium only.** The keyboard rows are tested automatically in Chromium, not in WebKit (Safari's engine). Test in Safari with your own assistive technology.
- **Right-to-left pages: a negative number.** Number masks don't set `dir="ltr"`, so in a right-to-left page the minus sign of a negative number may show on the right of the digits. Use `dir="ltr"` on the NumberInput if your page needs it. To be checked with real readers.
- **A typed space is announced as not allowed when `grouping` is on.** The mask writes the group separator itself, so a space the user types is left out and announced (by design; whether it is noise is a question for the AT run).
