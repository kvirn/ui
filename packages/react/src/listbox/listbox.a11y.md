# Accessibility contract: Listbox (the stylable popup and the native select)

- **Scope:** both renderings of Listbox (Plan 0022). `Listbox.Root` with `Listbox.Trigger` and `Listbox.Popup` is the stylable rendering, the APG select-only combobox. The browser's own `<select>` is the other rendering, which `Listbox.Root` renders for a single choice on touch devices (`native="auto"`, the default) and always for `native="always"`. `native="never"` keeps the popup. The popup parts (`Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`) are shared with Combobox and Autocomplete, which get their own contracts.
- **APG pattern:** [Combobox: Select-Only Combobox example](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/) for the popup, with [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) for the popup's content. None for the native rendering: its role, keys and list come from the browser and the platform.
- **Deviations:** none from the APG keyboard practice. The choices (overlays-and-lists skill) are allowed by the pattern: arrows don't wrap, Page Up and Page Down move ten options, Tab chooses the active option and moves on. The trigger is a `<div role="combobox" tabindex="0">`, as in the APG example.
- **Native elements used:** `<div role="combobox" tabindex="0">` (Trigger), `<div popover="manual" role="listbox">` (Popup), `<div role="option">`, `<div role="group">`, `<input type="hidden">` (the plain-form value), and for the native rendering `<select>` with `<option>` and `<optgroup>`, named by a `<label for>` (Field.Label).
- **Status:** alpha candidate (Plan 0022, Phase 2). Accessibility-reviewer pending. Manual AT is `pending`.
- **Tests:** `listbox.test.tsx` (the internal native select) and `listbox-custom.test.tsx` (the popup, and the rendering through `Listbox.Root`) next to this file. `listbox.stories.tsx` (the popup stories, and the Native… stories for `native="always"`) and `listbox.e2e.ts` in `apps/storybook/src/components/listbox/`.

A Listbox is one choice (or several) from a list, with no typing of text. On a desktop it is a stylable popup: it can hold groups and rich options, and the look is yours. On a phone, a single choice is the browser's own `<select>` with the platform's picker, which is better than anything custom. The value is the chosen option's key (`itemToKey`), never copied into KvirnUI state: `value` and `onValueChange` are yours, or `defaultValue` and `name` for a plain `<form>`. `multiple` always renders the popup, and so does any option with rich content: the native `<select>` shows one line of plain text per option.

Rules, tested in `listbox-custom.test.tsx` (popup) and `listbox.test.tsx` (native):

- **A combobox, not a select.** The trigger is `role="combobox"` with `aria-expanded`, `aria-controls` and `aria-haspopup="listbox"`; the `List` inside the popup is the `listbox` that `aria-controls` points at; the options are `option`s (`listbox-custom.test.tsx › a closed listbox: a combobox div wired to a hidden listbox popup`). The popup and its List are always in the DOM, so `aria-controls` points at an element on every render. Options render only while it is open.
- **Named by its label and value, described by its help text and error.** The help text is a `Field.Prose` in the Field: its description is its text content, so keep it short and plain. (`listbox-custom.test.tsx › the Field’s label and the value name the trigger, and the help text describes it`, `listbox-custom.test.tsx › invalid, required and disabled come from the Field`). A dev warning fires when a trigger in a Field has no Field.Label, or has no name at all (1.3.1, 4.1.2). The native select is named by `<label for>` (`listbox.test.tsx › the Field’s label is the name, and the description and error describe it`).
- **`aria-activedescendant` always points at a rendered option,** and is absent while closed and until the user moves (`listbox-custom.test.tsx › aria-activedescendant always points at a rendered option`). Opening with a press activates nothing, so Enter never chooses something the user did not move to.
- **Focus never leaves the trigger.** Opening, choosing, a click on an option and a press in the popup keep it there (`listbox-custom.test.tsx › a press inside the popup keeps focus on the trigger`).
- **Disabled options are reachable and cannot be chosen** (`listbox-custom.test.tsx › a disabled option can be reached with the arrow keys and cannot be chosen`).
- **Multiple.** `aria-multiselectable="true"`, a choice toggles and the popup stays open, Tab closes without choosing (`listbox-custom.test.tsx › aria-multiselectable, and a choice toggles the option and keeps the popup open`).
- **No form state.** The value is controlled with `value` and `onValueChange`, or uncontrolled with `defaultValue`. A controlled value that the parent doesn't update stays as it is (`listbox-custom.test.tsx › controlled: stays as it is when the parent does not update the value`). With `name`, hidden inputs carry it (`listbox-custom.test.tsx › with a name, a hidden input carries the chosen key in a plain form`).
- **Native rendering.** `native="always"` renders a `<select>` with the Field's label, help text and error, `<optgroup>`s for groups and the same `name`; the choice survives a switch of rendering and the popup is closed after it (`listbox-custom.test.tsx › native="always" renders a native select with the Field’s label, description and error`, `listbox-custom.test.tsx › the choice survives a switch of rendering, and the popup is closed after it`). `multiple` is never native (`listbox-custom.test.tsx › multiple always renders the popup, and native="always" with it warns once`).
- **Server rendering.** The server and the first client render are the popup. `native="auto"` reads `(pointer: coarse)` **once**, right after mount, and never listens for a change: a rendering that swapped under the user would drop their focus to the page, so the rendering never changes after that first update (`listbox-custom.test.tsx › native="auto" reads the pointer once after mount: a later change never swaps the rendering`, `listbox-custom.test.tsx › the server markup has the combobox, a closed popup and a hidden input, and no options`).
- **No placeholder as the only label.** The Field's label is always visible; the placeholder is part of the name only as a hint (4.1.2, 3.3.2).
- **`render` on every part,** with class and handlers merged and refs merged. `Listbox.Option` keeps its element's role.
- **Dev warnings:** native rendering inside a `Toolbar.Root` (`listbox-native-in-toolbar`: the trigger and its `Toolbar.Item` are gone, so set `native="never"`), a part outside a Root, a trigger without a name, an option whose item is not in the list, `native="always"` with `multiple`, `virtualize` with `groups`, and `virtualize` with a `Listbox.List` whose children aren't a function.

## Focus management

- Initial focus: not moved. Opening never moves DOM focus (a keyboard user stays on the trigger), and no option is active until an arrow key, Home, End, Page Up, Page Down or a typed letter, except that opening with a key activates the chosen option so the user can see where they are.
- Trap: no. The popup is not modal and the page behind it is not `inert`. Tab always leaves the trigger: it chooses the active option (one choice) or just closes the popup, and moves on (2.1.2).
- Restore to: the trigger, which never lost focus. Escape and a press on an option keep it there. A press outside leaves focus where the press put it (a control that was pressed keeps it).
- Never obscured by: the popup is placed under the trigger and flips above it when there is no room, so it never covers the trigger (2.4.11). Its height is limited to the room that is left, and it scrolls inside. The active option is scrolled into view when a key moves it, so it is never out of sight.

## Virtualization

`virtualize` is off by default. It renders only the options that are scrolled into view, for a flat list of thousands, and applies to the stylable popup only: the native `<select>` ignores it. The rules below are enforced in one place, `createListVirtualizer` in `@kvirn-ui/core`, and the same tests cover Listbox, Combobox and Autocomplete.

- **Keep what matters mounted.** The active option and every chosen option are always rendered, even when they are scrolled out of view. `aria-activedescendant` can only point at an element that is in the page, so it never points at nothing (4.1.2; `listbox.e2e.ts › popup: virtualized: ArrowDown and ArrowUp always leave aria-activedescendant on an option in the page`).
- **Scroll before you point.** A key that moves the active option calls `scrollToIndex` for it, and the option is rendered in the same commit that sets `aria-activedescendant`, so the element exists and is in view when assistive technology looks (2.4.3, 2.4.7; `listbox.e2e.ts › popup: virtualized: Home and End reach the first and the last option, rendered and in view`). A pointer move doesn't scroll: the option is already under the pointer. On opening, the chosen option is scrolled to.
- **Navigate the data, not the DOM.** Home, End, Page Up, Page Down, the arrows and typeahead work on the whole list, not on the options that happen to be rendered (2.1.1; `listbox.e2e.ts › popup: virtualized: typing a letter reaches an option that was not rendered`).
- **Expose the full size.** Every rendered option has `aria-setsize` (the number of options) and `aria-posinset` (its place, from 1), so a screen reader says "3 of 10 000" and not "3 of 14" (1.3.1; `listbox.e2e.ts › popup: virtualized: only a window of the options is in the page, each with its place in the list`).
- **The list is the scroll element.** The `role="listbox"` element scrolls and carries `data-virtualized`. Inside it, one sizer element (`kv-listbox-virtual-sizer`) has the height of the whole list, and each rendered option is absolutely positioned in it with `data-index`. The geometry is inline (position, block size and `translateY`) and nothing else: no colour, spacing or type, so a virtualized list lays out without a theme (hard rule 5). The list must be a scroll container with a height limit (the default theme makes it one).
- **Flat lists only.** With `groups`, `virtualize` is ignored and a development warning is logged: a partly rendered `role="group"` gives a screen reader the wrong group. The list renders in full.
- **Off by default, and the docs say why.** Options that aren't rendered can't be found with find in page, aren't printed, and are out of reach of a screen reader's browse mode. Filter first (a Combobox), paginate, or virtualize a list that stays long. A virtualized list is for a popup the user operates with the keys listed above.
- **Screen-reader support varies.** `aria-setsize` and `aria-posinset` on options, and `aria-activedescendant` into a virtualized list, are read differently by NVDA, JAWS, VoiceOver and TalkBack. The manual AT run covers it before `beta` and is `pending`.

## Announcements

None from us. A single choice reads as the trigger's value (name, role, "collapsed" or "expanded", the chosen text); each active option is read by the screen reader through `aria-activedescendant`, and we never announce it ourselves. The popup is not a live region and `Listbox.Empty` isn't announced: there is no filtering in a Listbox, so the list does not change under the user (4.1.3). The native rendering is read by the browser and the screen reader. Combobox and Autocomplete announce their result counts.

## Consumer responsibilities

- A `Field.Label` with a visible question, always. A placeholder is not a label. Outside a Field, give the trigger `aria-label` or `aria-labelledby`, and the `Listbox.List` `aria-label` when its name should differ.
- Pass `items` (or `groups`) and give each item a stable `itemToKey`. A new `items` array refreshes the list: pass one when `isItemDisabled`, `itemToString` or `itemToKey` change meaning, and memoize it when you build it in render. Don't render the item's own text twice: `Listbox.Option` shows `itemToString(item)` unless you give it children.
- A rich option (an icon, a description) must still have a plain text name, and it shows only in the popup: the native rendering shows the text only. Choose `native="never"` when the rich content matters on touch devices too, and `native="always"` where one frame of the custom trigger on a phone is a problem.
- Keep the list in a meaningful order, short enough to scan, and for more than about 15 options that a user would filter, use a Combobox. For several choices from a short list, prefer a CheckboxGroup.
- Put the choice that means "no answer" in the list as a real option, if "no answer" is valid.
- Validate and set `invalid` yourself, with a Field.ErrorMessage that says what to do ("Välj en kommun"). Don't change the page, submit or move focus when the value changes (3.2.2).
- Pass `value` and `onValueChange`, or `defaultValue` and `name` for a plain `<form>`.
- For thousands of options, filter or split the list first, and use `virtualize` only for what stays long. Give `Listbox.List` a height limit and `overflow-y: auto` (the default theme does), render it with a function child, and don't use `groups`: see Virtualization.

## Visual / modes

- Focus indicator: a 2px `focus-ring` outline, 2px offset, around the trigger (and around the native select). The active option is shown by a 4px bar at its inline start and a tinted fill, never by colour alone; the chosen option by a tick (1.4.1, 2.4.7).
- Target size: the trigger and each option are at least 44px high (32px in `kv-compact`), the trigger full width or a width class (2.5.8).
- Colour: the TextInput's look: 1px `border-control` edge, `canvas` fill, 2px `danger` edge when invalid, dashed edge on `surface` when disabled. The popup is `surface-raised` with level 3 elevation (`--kv-shadow-popup`, none in the dark themes), a `border-subtle` edge and the `xl` radius; its padding is 8px. The chevron takes the text colour and is not the only cue of a select.
- forced-colors behaviour: system colours. The trigger's edge is `ButtonBorder`, invalid `CanvasText` at 2px, disabled dashed `GrayText`. The popup is `Canvas` with a `CanvasText` edge. The active option turns `Highlight` with `HighlightText` and keeps its bar, the chosen option keeps its tick (`listbox.e2e.ts › popup: forced colours keep the popup edge and the trigger edges visible (1.4.11)`). The native select returns to the native appearance (`listbox.e2e.ts › forced colours keep the select edge visible in every state (1.4.11)`).
- reduced-motion behaviour: nothing moves. The trigger's edge and fill transition only under `no-preference`; the popup does not animate its position or opacity.
- Reflow: the trigger is as wide as its column and no wider, and the popup is at least as wide as the trigger and never wider than the viewport; long option text wraps in the popup, and the chosen text wraps in the closed trigger, which grows with it (never an ellipsis) (`listbox.e2e.ts › popup: no horizontal scrolling at 320px with the popup open (1.4.10)`).
- RTL: the chevron is at the left, the text starts at the right, and the tick is at the left of the option.

## Known issues

- **`aria-activedescendant` on VoiceOver and TalkBack** has known gaps. That is why a single choice is the native `<select>` on touch devices under `native="auto"`. The manual AT run must cover `native="never"` and `multiple` on iOS and Android before `beta`.
- **The native list is the browser's.** Its colours, size and font follow the OS and can't be styled to the theme's contrast tokens. In `forced-colors` and in the high-contrast themes it follows the user's colours.
- **The chevron of the native select is two CSS gradients.** A `<select>` takes no pseudo-element, and a wrapper would change the markup. In forced colours the theme returns to the native appearance, which draws its own arrow. The popup's trigger draws its chevron with a pseudo-element.
- **The first frame on a touch device.** With `native="auto"` the server and the first client render are the popup trigger, and a coarse pointer switches to the native select right after mount, before the user can interact. The pointer is not watched afterwards (a laptop that gains a touch screen keeps its rendering until the page loads again). Use `native="always"` to avoid the first frame.
- **Virtualization is opt-in and has limits.** Without `virtualize`, every option renders while the popup is open, so a list of many thousands is slow: use `virtualize` for those. With it, options that aren't rendered can't be found with find in page or printed, groups are not virtualized, and `aria-activedescendant` into a virtualized list is unverified on VoiceOver and TalkBack (see Virtualization).
- **The popup has no tab stop.** It scrolls natively, and keyboard users scroll it by moving the active option, which is scrolled into view. axe treats the combobox popup as exempt from `scrollable-region-focusable`.
- **Keys differ by platform for the native rendering.** The Keyboard rows describe Chromium on Windows and Linux (tested); macOS and Safari open the list for the arrow keys. The AT run covers macOS.
- **WebKit not run locally.** CI runs the `webkit` and `mobile-safari` projects. `popover="manual"`, the outside press and Escape must be checked on Safari 17.
