# Accessibility contract: Combobox (Root, Control, Input, Toggle, Clear, ValueList, Value, and the popup parts)

- **Scope:** Combobox, one or several choices from a list that the user filters by typing (ADR-0037, item 4; Plan 0022). `Combobox.Root` with `Combobox.Input` and `Combobox.Popup` is the editable combobox. `Control`, `Toggle` and `Clear` are optional, `ValueList` and `Value` are for `multiple`. The popup parts (`Popup`, `List`, `Option`, `Group`, `GroupLabel`, `Empty`) are the Listbox's: their roles and styling are in [listbox.a11y.md](../listbox/listbox.a11y.md), and `Combobox.Root` provides the same context. Autocomplete (free text) has its own contract: [autocomplete.a11y.md](../autocomplete/autocomplete.a11y.md).
- **APG pattern:** [Combobox: Editable Combobox With List Autocomplete](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-autocomplete-list/) (`aria-autocomplete="list"`, manual selection), with [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) for the popup's content.
- **Deviations:** none from the APG keyboard practice. The choices ADR-0037 records are allowed by the pattern: no option is active until an arrow key, arrows don't wrap, Page Up and Page Down move ten options, Home, End, ArrowLeft and ArrowRight stay with the text field and return visual focus to it (no option stays active), Tab closes the popup without choosing, a second Escape doesn't clear the text, and there is no inline completion (`aria-autocomplete="list"`, not `"both"`). The optional Toggle and Clear buttons are not tab stops, which is allowed because the keyboard has other ways to do the same (see Keyboard). Decisions: ADR-0037 (items 4, 6, 7, 8, 9, 10, 12, 13, 14), ADR-0046 (the popup layer), ADR-0029 (Field wiring, no form state), ADR-0039 (keyboard), ADR-0040 (the Announcer) and ADR-0050 (the implementation notes for Combobox and Autocomplete).
- **Native elements used:** `<input type="text" role="combobox">` (Input), `<div popover="manual">` (Popup), `<div role="listbox">` (List), `<div role="option">`, `<div role="group">`, `<ul>` and `<li>` (ValueList, Value), `<button type="button">` (Toggle, Clear, and each remove button), `<input type="hidden">` (the plain-form value).
- **Status:** alpha candidate (Plan 0022, Phase 2). Accessibility-reviewer pending. Manual AT is `pending`.
- **Tests:** `combobox.test.tsx` next to this file. `combobox.stories.tsx` and `combobox.e2e.ts` in `apps/storybook/src/components/combobox/`.

A Combobox is for choosing from a list that is too long to scan: the user types a few letters, the list shrinks, and they choose. The value is one of the options (or several), never the text: text that matches nothing stays in the field and the value is `null`, so your validation can say "Välj ett alternativ i listan". The value is the chosen option's key (`itemToKey`), never copied into KvirnUI state: `value`, `onValueChange` and `inputValue`, `onInputValueChange` are yours, or `defaultValue` and `name` for a plain `<form>` (ADR-0029). The text is never cleared or replaced silently: only choosing an option replaces it (with the option's text, or with an empty field in `multiple`, because the choice moves to the value list), and only the Clear button empties it.

Rules, tested in `combobox.test.tsx` (and end to end in `combobox.e2e.ts`):

- **ARIA 1.2 combobox, not 1.0 or 1.1.** `role="combobox"` is on the input, with `aria-expanded`, `aria-controls` and `aria-autocomplete="list"`; the `List` inside the popup is the `listbox` that `aria-controls` points at; the options are `option`s (`combobox.test.tsx › a closed combobox: a native input wired to a hidden listbox popup`). The List is always in the DOM, so `aria-controls` points at an element on every render. With no option to show it is `hidden` and the input reports `aria-expanded="false"` (nothing to move into, as in the APG), while the popup may still show the Empty text. Options render only while it is open.
- **Named by its label, described by its hint and error.** The hint is a `Prose` in the Field (ADR-0054): its description is its text content, so keep it short and plain. (`combobox.test.tsx › the Field’s label names the input, and the hint describes it`, `combobox.test.tsx › invalid, required and disabled come from the Field`). A dev warning fires when an input in a Field has no Label, or has no name at all (1.3.1, 4.1.2).
- **`aria-activedescendant` always points at a rendered option,** and is absent while closed and until the user moves. Typing clears it, so it never points at an option the filter has taken away (`combobox.test.tsx › aria-activedescendant always points at a rendered option, and typing clears it`). Opening by typing or by a press activates nothing, so Enter never chooses something the user didn't move to.
- **Focus never leaves the input.** Typing, opening, choosing, a click on an option, a press in the popup and a press on Toggle or Clear keep it there (`combobox.test.tsx › a press inside the popup keeps focus on the input`). The remove buttons are the one exception, because they are focusable buttons the user chose to press.
- **The text is never cleared silently.** Text that matches no option stays after Tab, Escape and a blur, and the value is `null` (`combobox.test.tsx › text that matches no option stays after Tab and after Escape, and the value is null`). Editing away from the chosen option's text makes the value `null` and keeps what was typed (`combobox.test.tsx › editing away from the chosen text makes the value null, and keeps what was typed`).
- **Enter keeps its native meaning when no option is active:** the form can submit, and nothing is chosen (`combobox.test.tsx › Enter with no active option is the browser’s own: the form submits and nothing is chosen`). A key during an IME composition belongs to the composition (`combobox.test.tsx › a key during an IME composition is left to the composition`).
- **Disabled options are reachable and cannot be chosen** (`combobox.test.tsx › a disabled option can be reached with the arrow keys and cannot be chosen`).
- **Filtering** is on the label, anywhere in it, in the provider's locale: å, ä and ö are not a and o in Swedish, and accents are ignored where the locale allows (`combobox.test.tsx › å, ä and ö are not a and o in the Swedish provider`). Your own `filter` replaces it, and `filter={false}` plus `isLoading` serves results that the server has filtered.
- **Multiple.** `aria-multiselectable="true"`, a choice adds a value, empties the text and the popup stays open, and a chosen option chosen again takes the value away. Chosen values are a list of remove buttons before the input; removing one moves focus to the next remove button, else the previous one, else the input; Backspace in the empty input removes nothing (`combobox.test.tsx › aria-multiselectable, and a choice adds a value, empties the text and keeps the popup open`, `combobox.test.tsx › removing a value moves focus to the next remove button`, `combobox.test.tsx › removing the last value moves focus to the previous remove button`, `combobox.test.tsx › removing the only value moves focus to the input`, `combobox.test.tsx › Backspace in the empty input does not remove a value`).
- **No form state.** The value and the text are controlled with `value` and `inputValue`, or uncontrolled with `defaultValue` and `defaultInputValue`. A controlled value or text that the parent doesn't update stays as it is (`combobox.test.tsx › controlled: stays as it is when the parent does not update the value`, `combobox.test.tsx › controlled inputValue: shows the text it is given, and a refused change is pulled back`). With `name`, hidden inputs carry the value (`combobox.test.tsx › with a name, a hidden input carries the chosen key in a plain form, and the typed text is not sent`).
- **The popup never covers the input** (2.4.11) and is at least as wide as it (`combobox.test.tsx › the popup is under the input and never covers it`).
- **Server rendering.** The server writes the input, a closed popup, the hidden inputs and no options (`combobox.test.tsx › the server markup has the input, a closed popup and a hidden input, and no options`).
- **`render` on every part,** with class and handlers merged and refs merged (ADR-0015).
- **Dev warnings:** a part outside a Root, an input without a name, a `Combobox.Value` for an item that is not chosen, an option whose item is not in the list, and no `KvirnProvider` when something has to be announced.

## Keyboard

<!-- Format and rules: the `keyboard` skill (ADR-0039). Shown on the Storybook Docs page. -->

- **Focus strategy:** aria-activedescendant. DOM focus stays on the input, and the active option is `aria-activedescendant`
- **Selection follows focus:** no (Enter, Alt+ArrowUp or a click chooses an option, and the arrow keys only move the highlight)
- **Arrows wrap:** no
- **Shortcuts:** none

The input is one Tab stop. In `multiple` the remove buttons come before it in the Tab order. Toggle and Clear are not tab stops (`tabindex="-1"`), because everything they do has a key: ArrowDown and Alt+ArrowDown open the popup, and the text can be selected and deleted. They are still in the accessibility tree, so touch screen reader users and voice control reach them by name. Home, End, ArrowLeft, ArrowRight (with or without Shift or Control) and Space are the text field's own: the caret moves and a space is typed, and they are never cancelled. The four caret keys also return visual focus to the field, as the APG says: the active option is cleared and `aria-activedescendant` is removed, and the popup stays open. The arrows used here are vertical, so they do not flip in right-to-left text. A key that is not in this table is left to the browser (`F5`, `Control+L`), and Control and Command combinations are never taken.

## Focus management

- Initial focus: not moved. Opening never moves DOM focus (a keyboard user stays in the text field), and no option is active until ArrowDown or ArrowUp, except that opening with a key activates the chosen option so the user can see where they are.
- Trap: no. The popup is not modal and the page behind it is not `inert`. Tab always leaves the input: it closes the popup without choosing and moves on (2.1.2).
- Restore to: the input, which never lost focus. Escape, a press on an option, Toggle and Clear keep it there. After a value is removed, focus goes to the next remove button, else the previous one, else the input, so it is never lost to the page. A press outside leaves focus where the press put it (a control that was pressed keeps it).
- Never obscured by: the popup is placed under the input (or its Control) and flips above it when there is no room, so it never covers the field (2.4.11). Its height is limited to the room that is left, and it scrolls inside. The active option is scrolled into view when a key moves it, so it is never out of sight.

## Announcements

| Event                                         | Message key (i18n)     | Politeness |
| --------------------------------------------- | ---------------------- | ---------- |
| The popup is open and the list has N options  | `combobox.resultCount` | polite     |
| The popup is open and no option matches       | `combobox.noResults`   | polite     |
| The popup is open and the options are loading | `combobox.loading`     | polite     |

They go through the shared Announcer (ADR-0040), about 500 ms after the last change (`announcementDebounceMilliseconds`), so nothing is said while the user types, and a count that changes again replaces the one waiting. A count is said only for what the user caused by typing: opening the popup with ArrowDown, ArrowUp, Alt+ArrowDown or the Toggle announces nothing, because the list didn't change. "No results" and "loading" are always said. They need a `KvirnProvider`, which renders the live regions; without one nothing is announced and a dev warning says so. **The active option is never announced by us:** the screen reader reads it through `aria-activedescendant`. Choosing an option is read as the input's new value. The popup is not a live region, and `Combobox.Empty` and the loading text are shown, not announced by themselves (4.1.3). The remove buttons' names, the Toggle and Clear names come from `combobox.removeValue`, `combobox.showOptions` and `combobox.clear`, in the provider's locale and overridable per instance (`messages`).

## Consumer responsibilities

- A `Label` with a visible question, always. A placeholder is not a label. Outside a Field, give the input `aria-label` or `aria-labelledby`, and the `Combobox.List` `aria-label` when its name should differ.
- Pass `items` (or `groups`) and give each item a stable `itemToKey`. A new `items` array refreshes the list: pass one when `isItemDisabled`, `itemToString` or `itemToKey` change meaning, and memoize it when you build it in render. For server filtering pass `filter={false}`, `isLoading`, and your own debounce and fetch.
- Validate and set `invalid` yourself, with an ErrorMessage that says what to do ("Välj ett alternativ i listan"). Text that matches no option leaves the value `null`: the Combobox never clears it for you. Don't change the page, submit or move focus when the value changes (3.2.2).
- Keep the list in a meaningful order. For up to about 15 options use a Listbox or a RadioGroup instead, and for free text with suggestions use Autocomplete.
- A rich option (an icon, a description) must still have a plain text name, which is also what goes in the input when it is chosen.
- Apply `onValueChange(null, { reason: 'input' })`: it is what "the text no longer names the chosen option" reports. A controlled parent that keeps the old value gets the chosen option's text put back, which would undo what the user is typing.
- Pass `value` and `onValueChange` (and `inputValue` with `onInputValueChange` if you control the text, set to the chosen option's text while a value is chosen), or `defaultValue` and `name` for a plain `<form>`.
- Put `Combobox.Toggle` and `Combobox.Clear` inside a `Combobox.Control`, after the input, if you want them. Don't make them tab stops.

## Visual / modes

- Focus indicator: a 2px `focus-ring` outline, 2px offset, around the input (or around the Control, which draws the edge). The active option is shown by a 4px bar at its inline start and a tinted fill, never by colour alone; the chosen option by a tick (1.4.1, 2.4.7). The popup's look is the Listbox's.
- Target size: the input and each option are at least 44px high (32px in `kv-compact`). Toggle and Clear are as high as the box (44px, 32px compact) and the remove buttons are 44px square (32px compact), and none is ever under 24px, even where the drawn mark is smaller (2.5.8).
- Colour: the Input's look: 1px `border-control` edge, `canvas` fill, 2px `danger` edge when invalid, dashed edge on `surface` when disabled. The chosen values are chips on `surface` with a `border-control` edge, so they are not told apart by colour alone.
- forced-colors behaviour: system colours. The input's and the chips' edges are `ButtonBorder`, invalid `CanvasText` at 2px, disabled dashed `GrayText`. The active option turns `Highlight` with `HighlightText`, and the cross and chevron take the text colour (`combobox.e2e.ts › forced colours keep the edges, the cross and the chevron`).
- reduced-motion behaviour: nothing moves. The edge and fill transition only under `no-preference`; the popup does not animate its position or opacity (`combobox.e2e.ts › reduced motion: the input does not transition`).
- Reflow: the input is as wide as its column and no wider, the popup is at least as wide as it and never wider than the viewport, the chips wrap, and long option text wraps (`combobox.e2e.ts › no horizontal scrolling at 320px with the popup open (1.4.10)`).
- RTL: the text, the chips and the chevron follow the reading direction, and the tick is at the inline end (`combobox.e2e.ts › right to left: the chevron is at the inline end, and the chips start at the right`).

## Known issues

- **`aria-activedescendant` on VoiceOver and TalkBack** has known gaps (ADR-0037). A Combobox stays custom on touch devices (there is no native rendering), so the manual AT run must cover iOS and Android before `beta`.
- **Toggle and Clear are not tab stops.** That is allowed because their actions have keys (ArrowDown, Alt+ArrowDown, select and delete), and it keeps the Tab sequence short.
- **No virtualization yet.** Every matching option renders while the popup is open, so a list of many thousands is slow. A follow-up reserves `aria-setsize`, `aria-posinset` and "always render the active and chosen option" in the core.
- **The popup has no tab stop.** It scrolls natively, and keyboard users scroll it by moving the active option, which is scrolled into view.
- **A Combobox inside a form with an Enter shortcut.** Enter with an active option chooses it and never submits the form, as the pattern says. With no active option it submits (the browser's own). The text is not sent, only the hidden inputs are.
- **Text that has no match is not an error by itself.** The Combobox reports `null` and leaves the message to the consumer, because the right words depend on the form.
- **WebKit not run locally.** CI runs the `webkit` and `mobile-safari` projects. `popover="manual"`, the outside press and Escape must be checked on Safari 17.
- **`se` (Northern Sámi) is machine-drafted.** See `field.a11y.md`.
