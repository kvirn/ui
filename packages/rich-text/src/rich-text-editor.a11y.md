# Accessibility contract: RichTextEditor

- **APG pattern:** [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) above a multi-line text, with [toggle buttons](https://www.w3.org/WAI/ARIA/apg/patterns/button/), a select-only [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/) and non-modal [dialogs](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) for the link and image forms. The text is a `textbox` with `aria-multiline` (a `contenteditable`). There is no APG pattern for a rich text editor.
- **Deviations:** two, both approved by the maintainer on 2026-10-04 and recorded in the `keyboard` skill (rule 7 and its editor table). (1) **Shortcuts are on by default**, limited to the platform's text-editing convention. (2) **Tab acts inside the text**: it indents a list item and moves between table cells, only where it can, with a visible instruction for how to leave and Escape then Tab as the way out from anywhere. WCAG 2.1.2's own Understanding page uses a rich text editor with Tab indentation and Alt+F10 as a passing example. Escape in the text is consumed the first time (so a Dialog around the editor stays open).
- **Native elements used:** a `<div contenteditable role="textbox">` made by Tiptap (ProseMirror), `<button>` for every control, a `<div role="combobox">` for the picker (the Listbox), `<div popover role="dialog">` for the forms (the Popover), `<form>`, `<input>` (TextInput, Checkbox) and `<input type="hidden">` for the posted value.
- **Status:** alpha candidate (Plan 0036). Gates not yet passed and the manual AT matrix is `pending`: screen reader support for a `contenteditable` varies between NVDA, JAWS and VoiceOver.
- **Tests:** `rich-text-editor.test.tsx`, `rich-text-toolbar.test.tsx`, `link-image-forms.test.tsx` and `kvirn-keymap.test.tsx` under `packages/rich-text/src/`. `rich-text-editor.stories.tsx` and `rich-text-editor.e2e.ts` in `apps/storybook/src/components/rich-text-editor/`.

A RichTextEditor is the control of a [Field](../../react/src/field/field.a11y.md): the Field's label names the editable text, and its description, the keyboard instruction, the count, its hint and its error describe it. It adds a formatting toolbar, one Tab stop that a keyboard and screen reader user can operate, and posts its value with the form. Its output is **never sanitized**: sanitize it on the server.

## Keyboard

- **Focus strategy:** roving tabindex
- **Selection follows focus:** n/a
- **Arrows wrap:** yes
- **Shortcuts:** on by default, the platform's text-editing convention only (Control or Command with B, I, U, K, Z, Shift+Z, and Control+Y), plus Alt+F10 (Option+F10 on macOS) to the toolbar

The toolbar uses a roving tabindex and its arrows wrap ([Toolbar](../../react/src/toolbar/toolbar.a11y.md)). The text is native: arrows, Home, End, PageUp, PageDown, Shift with them, Enter (a new paragraph, a new list item, and on an empty item the end of the list) and Shift+Enter (a line break) are the browser's and Tiptap's, and are never bound. `Mod` is Control on Windows and Linux, and Command on macOS. **Never shortcuts:** Control+Alt chords (AltGr on Windows: `@ £ $ € { [ ] } \` on Swedish, Finnish and Norwegian layouts) and Command+Option, Control+E, Control+Shift+S, Control+Shift+B, Control+Shift+7 and 8 (Tiptap's defaults that clash with browsers and Nordic keyboards), and nothing uses Caps Lock, Insert, Scroll Lock or Control+Option on macOS. Every shortcut has a toolbar button.

**The way out (2.1.2).** Tab in the text acts only where it can (a list item that can be nested, a table cell that isn't the last), so everywhere else it moves focus as usual. Where it acts, the instruction under the box says how to leave: "Lämna textfältet med Esc och sedan Tabb. …". Escape then Tab or Shift+Tab always leaves. Screen readers: NVDA and JAWS use Escape themselves to leave focus mode, so Escape may never reach the editor: they are then in browse mode, where their own Tab moves to the next element, and the outcome is the same. The AT matrix checks it.

**How it is built.** The keys are decided in one ProseMirror plugin's `handleDOMEvents.keydown`, ahead of every Tiptap keymap: a handler there makes ProseMirror skip its own key handling, so no other Tab binding acts behind a "leave" and no event is stopped from propagating (except the first Escape). `KvirnKeymap` is part of `defaultExtensions()`.

## Focus management

- Initial focus: not moved. The first Tab enters the toolbar, then the text.
- Trap: no. Tab leaves everywhere, and Escape then Tab leaves from anywhere. Alt+F10 and Escape move between the toolbar and the text.
- After a toolbar command from the keyboard focus stays on the control, as APG's toolbar does, so several formats can be set in a row. A pointer press doesn't take focus from the text (the control prevents focus on `mousedown`), so the caret and selection stay.
- The picker and the popovers return focus to the text, at the selection, when they close with a choice, Cancel or Escape. A press outside a popover leaves focus where the user pressed.
- Focus never lands on `body`: when the focused Table group button goes with the group, focus goes to the text first.
- Restore to: the text at the selection (Link, Image, the picker), the toolbar (nothing).
- Never obscured by: the toolbar is not sticky. A popover or tooltip is placed so it doesn't cover its trigger (2.4.11). The selection stays visible while focus is in the toolbar (the browser's inactive selection).

## Consumer responsibilities

- **Put the editor in a Field** with a `Field.Label` (or give `RichTextEditor.Content` an `aria-label`). Give the Field's error text that names the fix.
- **Sanitize the output on the server.** Tiptap's schema drops unknown tags and attributes, but that is not a security boundary, and the docs never call the output safe. The stored HTML has `dir="auto"` on blocks and can carry a pasted `target` on a link: allow `dir` and strip `target`.
- **Limit image origins** with `imageSources` (this site's own and relative addresses by default). An image from another server is fetched by every reader's browser (GDPR).
- **Offer a smaller toolbar to residents** (`DefaultControls include=[…]`, `labels="icon-and-text"`): touch screens have no tooltips, and a wrapped full toolbar is about 200px tall at 320px.
- **Keep the extensions array stable** between renders (a constant or `useMemo`), and install Tiptap's peers once (one copy of ProseMirror).
- **Save drafts** in staff tools: a long text is the worst thing to lose to a session timeout (2.2.1).
- To show saved text, render it as `Prose`, not a read-only editor.
- Lazy-load the package (`React.lazy`): it is about 140 KB gzipped with ProseMirror.
- A custom toolbar with lists or tables and `keyboardHint={false}` must render a `RichTextEditor.KeyboardHint` somewhere in the Field.

## Visual / modes

- Focus indicator: a 2px ring around the whole box when the text has keyboard focus, and on the focused button only when the toolbar has it, 2px offset (2.4.7, 2.4.13). Any focus inside gives the box the 2px `border-focus` edge. A click in the text shows only the edge, as for text inputs.
- Target size: every control is at least 24 × 24 CSS px, 44px by default and 32px in `kv-compact` from 64rem (2.5.8, design spec §6.5.3). Test: `rich-text-editor.stories.tsx › Default`.
- forced-colors behaviour: the box keeps a `ButtonBorder` edge, a pressed toggle is a `Highlight` fill with `HighlightText`, flat buttons keep a `ButtonText` edge, the gap cursor is `CanvasText`, the selected image and cells are `Highlight`. Test: `rich-text-editor.stories.tsx › ForcedColors`.
- reduced-motion behaviour: fills fade over `--kv-duration-fast` and the popover over `--kv-duration-medium` only under `no-preference`. The gap cursor stops blinking under `reduce`. Nothing moves the layout: no slide for the Table group, no animated height.
- Reflow: the toolbar wraps group by group in both label modes, the popover fits the viewport, and long words in the text wrap. Only a wide table scrolls, inside its own wrapper. Test: `rich-text-editor.e2e.ts › long Finnish names at 320px do not scroll sideways`.
- Right to left: logical properties only, the toolbar arrows flip, and the column buttons are named by what the user sees. Each block has `dir="auto"`. Test: `rich-text-editor.stories.tsx › RTL`.
- Tiptap injects its own small `<style>` of ProseMirror's structural rules (`injectCSS`). The theme overrides the gap cursor.

## Known issues

- **Screen reader support for a `contenteditable` varies** across NVDA, JAWS and VoiceOver, and is the plan's biggest risk. Nothing here is claimed until the matrix is run.
- **A pasted link keeps its `target`** (Tiptap parses any declared attribute). Sanitize the output on the server.
- **The inactive selection** (while focus is on a toolbar button) is the browser's own highlight. The design asks for a `primary-subtle` one, which needs a decoration: not built.
- **The link and image popovers anchor to their toolbar button**, also when opened with Control+K, not to the caret.
- **No upload.** An image is inserted from an address with alt text. A follow-up plan adds upload with FileUpload's validation.
- **Tiptap's injected CSS** is unlayered, so the theme restyles the few rules it must with `!important`.
