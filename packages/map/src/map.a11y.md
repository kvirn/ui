# Accessibility contract: Map (Root, Skip, Viewport, Markers, Cluster, Controls, Attribution, BaseMapSwitch, Layers, List, Details, ClusterPopup)

- **APG pattern:** none. There is no APG map pattern. The keys follow the [keyboard interface practice](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/), and the markers follow the [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) arrow model.
- **Deviations:** the markers in view are **one Tab stop** and the arrow keys move between them, where a Tab stop per marker is unusable with many places. Arrows on the viewport pan and `+` / `-` zoom, while it has focus. Approved by the maintainer.
- **Native elements used:** `<div role="region">` (Viewport), `<div role="group">` (Markers, Controls), `<button>` (marker, cluster, controls, list row trigger, place in a cluster, Close), `<a>` (skip link), radio group (BaseMapSwitch), `<fieldset>` and checkboxes (Layers), a heading (`h2` by default, `headingLevel` sets it) and `<ul>` (List), `<dialog open>` (Details and ClusterPopup, non-modal) with an `<img>`, a heading, `<p>` for the body and address, `<p>` (Attribution).
- **Status:** in progress. Translations await native review. A Test cell marked `pending` has no test yet. Manual AT is `pending`.
- **Tests:** `map.test.tsx` next to this file. `map.stories.tsx` in `apps/storybook/src/components/map/`.

A Map shows places on a camera over a base map, with the same places as a list. It is one focusable region you can pan and zoom from the keyboard, with a set of markers that is a single Tab stop, buttons for every gesture, and a list that is the screen reader user's equivalent of the map.

These are the rules the map follows (the Keyboard table names the test for each key; not every rule below has a test):

- **Equivalent.** Every place in the data is in the list, and the viewport's description states the count (1.1.1, 1.3.1).
- **Names.** The viewport's name is the consumer's `label` and its role description is `map.roleDescription`.
- **Layers and clusters.** The layers card collapses behind a button (open by default, so a long list does not cover the map); collapsed it shows how many layers are hidden. Hiding a layer removes its markers, clusters and list rows, closes a popup of its place or cluster, leaves focus on the checkbox, and announces `map.placesInView` (or `map.placesAll`). A cluster holds one layer's places, changes on whole zoom steps only, and the selected place is never in one. An open cluster that no longer exists closes, and focus follows the chain below.
- **Focus.** Opening details or a cluster popup moves focus to its heading. Closing returns it to the opener (the marker, the cluster or the list row), else the list heading. Never `body` (2.4.3).
- **Keys are taken only while the viewport has focus** and never with Control, Command or Alt, so browser zoom keeps working (1.4.4, 2.1.4).
- **Pointer.** Drag pans, one finger scrolls the page on touch and two fingers pan, the wheel scrolls the page and zooms with Control or Command. A hint (`map.gestureTouch`, `map.gestureWheel`) shows until the next interaction. Every gesture has a button (2.5.1, 2.5.7). Buttons are at least 24 by 24 CSS px (2.5.8).
- **Failure.** When tiles fail, `map.tilesFailedTitle` and `map.tilesFailedBody` show in the viewport and the list still works (3.3.1).
- **WCAG SCs:** 1.1.1 Non-text Content (A), 1.3.1 Info and Relationships (A), 1.3.2 Meaningful Sequence (A), 1.4.1 Use of Color (A), 1.4.4 Resize Text (AA), 1.4.10 Reflow (AA), 1.4.11 Non-text Contrast (AA), 1.4.13 Content on Hover or Focus (AA), 2.1.1 Keyboard (A), 2.1.2 No Keyboard Trap (A), 2.1.4 Character Key Shortcuts (A), 2.4.1 Bypass Blocks (A), 2.4.3 Focus Order (A), 2.4.7 Focus Visible (AA), 2.4.11 Focus Not Obscured (Minimum) (AA), 2.5.1 Pointer Gestures (A), 2.5.3 Label in Name (A), 2.5.7 Dragging Movements (AA), 2.5.8 Target Size (Minimum) (AA), 3.2.1 On Focus (A), 3.2.2 On Input (A), 4.1.2 Name, Role, Value (A) and 4.1.3 Status Messages (AA). Raster tile labels are images of text that do not follow the text size (1.4.4 Resize Text, 1.4.5 Images of Text, both AA): the tile source is yours, and vector tiles are advised.

## Focus management

- Initial focus: none. The map never moves focus on its own: a pan, a zoom, a changed map type and a result shown on the map leave focus where the user put it (3.2.2).
- Opening details: focus moves to the details heading (`tabindex="-1"`), so a screen reader reads the place.
- Closing details: focus returns to the marker or the list row that opened them, else the list heading. Never `body`.
- Never obscured by: floating chrome never covers a keyboard-focused marker or cluster (2.4.11). `Map.Controls`, `Map.Attribution` and the consumer's `Map.Overlay` register their element, and focus pans the map the smallest distance (least movement; centred when nothing fits) that clears the marker, padded by the focus ring and a gap, of every overlay and of the viewport's edge. The popup is not an overlay: it is anchored to the marker, and its room is the map's own row (the engine element), so below 40rem it never covers the controls (`map.test.tsx › the details popup stays inside the map row when the viewport has more rows below it`). Nothing is sticky.

## Consumer responsibilities

- **Keep the list.** Render `Map.List`, or your own list built with `useMapState` and a `Map.Skip` with `href`. Without a list, people who cannot use the map have no way to reach a place (1.1.1 Non-text Content, 2.1.1 Keyboard, 2.5.7 Dragging Movements). The library cannot check this.
- **Name the map.** `label` is required. Write it in the page's language.
- **Describe place pictures.** `image.alt` is required: describe the picture, or use `alt=""` when it only decorates (1.1.1).
- **Never tell layers apart by colour alone.** Marker content is decoration and the name comes from `label` and `clusterLabel`. Give each layer an icon or a shape (1.4.1 Use of Color; set `icon` on the layer and its clusters draw it before the count; tested in `map.test.tsx › a cluster of a layer with an icon draws it before the count, hidden from the name`), and keep each shape at 3:1 contrast against the map (1.4.11 Non-text Contrast). Keep the marker and cluster buttons at least 24 by 24 CSS px (2.5.8 Target Size (Minimum)).
- **Put the chrome where the map expects it.** `Map.Layers`, `Map.BaseMapSwitch`, `Map.Controls` and `Map.Attribution` go inside `Map.Viewport`. Wrap any floating part of your own in `Map.Overlay`, so a focused marker is moved out from under it (2.4.11 Focus Not Obscured (Minimum)).
- **Give a replaced map type switch a visible label** when you pass a function to `Map.BaseMapSwitch` (3.3.2 Labels or Instructions).
- **Prefer vector tiles.** Raster tiles are images of text that do not follow the visitor's text size (1.4.4 Resize Text, 1.4.5 Images of Text).
- **Choose the tile host and say so.** The library has no default tile source. The visitor's IP address reaches the host you choose when the first tile is requested, so name that host in your privacy notice. Nothing is requested until a `Map.Root` with a provider mounts.
- **Show the attribution** that your tile or data licence asks for with `Map.Attribution`. Leaving it out is a licence problem, not an accessibility one.
- **Keep `places`, `layers` and the provider stable** between renders (a constant or `useMemo`).
- **Install the engine's CSS yourself** (`maplibre-gl/dist/maplibre-gl.css`), and under Vite pass `workerUrl`. The package ships neither.
- **Keep clustering on for a large source.** With `cluster={false}`, every place in view is a button on the page.

## Known issues

- **Review the translations before you launch.** Have a native speaker review the Swedish, Finnish, Norwegian Bokmål and Norwegian Nynorsk texts before you launch. Override any text with the `messages` prop or the provider's `map` catalog. Your own map label, layer names and place data are in your language already. <!-- kv-lang-ok: the language name Bokmål -->
- **Markers under the floating cards cannot be pressed there.** Where the Layers or Map type card covers a marker, use the list or the keyboard, which pans the marker clear (2.4.11).
- **Test with your users and their assistive technology.** A map is hard to make equal for everyone, so check the viewport, the layer checkboxes, the pan buttons and the list with the assistive technology your users have.
- **Markers of different layers can touch.** Layers cluster separately, so a cluster of one layer can sit on a marker or cluster of another. Every place stays reachable from the keyboard (arrow keys between markers) and in the list.
- **`cluster={false}` with a large source** puts every place in view on the page as a button. The map warns once in development past 2,000 markers, and does not cap them. Keep clustering on, or turn it off only for small layers.
- **The map has no address search.** `GeocoderProvider` is a type only, and no part uses it; to offer address search, build it beside the map with a geocoding service you choose. A visitor finds a place by the markers, the list and the layers.
